# CJGUI 可用性与验收

更新：2026-09-19。本文件维护完成证据与验收依据，不另定义架构或执行状态；机制见[架构契约](AI_NATIVE_UI_SEMANTICS.md)，实际结果见[当前状态](../../runtime/cjgui/ACTIVE_DIRECTION.md)及对应阶段记录。不要求每个阶段完成完整 GUI 框架。

## 规划大阶段时的完整性视角

最小共同操作验收只是框架的一条能力链。选择下一阶段时，还应对照以下主线；不要求每项同步开工或逐轮打分：

- 开发者用仓颉组合组件、布局、样式和资源，能更换界面结构与业务含义。
- 外部系统可在运行时生成、修改受限界面结构，与手写组件混用；编辑、绑定、失败恢复与自绘共用主链，不能只证明操作已有固定应用。
- 场景、绘制命令、自绘后端和更新机制逐步接通，系统桥接承载必要平台服务。
- 人的点击、键盘、焦点、滚动、文本与无障碍具备正常应用证据。
- 人与外部系统理解对应内容和关系，能可靠执行、解释失败并接续工作。
- 普通包消费、调试与错误反馈可以复现；轻量和效率有实际观测依据。

从[设计意图与资产导航](../plans/DESIGN_INTENT_INDEX.md)查已有实现、原型和退役入口。样例增加功能后，应能解释哪项能力可被其他应用复用；不能把固定编辑器完备度等同于通用框架完备度。

## 最小共同操作阶段

需要同时证明：
1. 独立样例通过正常包/库入口消费 CJGUI，启动真实窗口并清楚显示内容。
2. 人通过真实输入选择或修改内容，状态与画面对应更新。
3. 外部客户端能读取对应对象与当前选择，并在授权范围内完成实际操作。
4. 外部修改出现在应用实际内容和窗口中；人继续修改后，外部端能获取新状态。
5. 过期请求不会静默覆盖人的新修改，失败不会显示为成功。
6. 一次真实模型/Agent 通过同一路径完成操作；测试客户端不能冒充这一证据。
7. 运行入口、必要设置和已知限制能让下一位开发者复现。

列表可以作为首个中性样例；不固定最终产品或要求聊天框。
少量基础控件即可，不要求首阶段具备完整文章编辑、IME、白板或跨平台能力。
模型接入环境缺失时标记外部实测缺口，不把前五项通过写成全阶段完成。

## 运行时生成式界面验收

这是一条必须交付的框架能力，应用是否启用由开发者决定；不要求每个阶段重做。按照[生成契约](AI_NATIVE_UI_SEMANTICS.md#运行时生成与修改界面)，用一个正常应用完成：

同时检查信息与构建能力的对等：同一角色/授权下，人可用的已支持组件、字段、草稿、动作及约束应可被 AI 发现和直接使用；有尚未接通项须明确列出。增加一个自定义组件或字段，不能要求另维护一份 AI 专属业务镜像。首轮组件范围有限可以如实交付，不得把这种限制固化成 AI 永久只能使用几个模板。

1. 开发者注册受限组件、字段和动作，外部调用方从公开入口读取可用能力并提交界面结构。描述决定组件实例与排列，不能只是选择硬编码页面。
2. 无需重编译或重启，结构进入现有组件、布局与自绘路径并在真实窗口出现；保留手写区域作为混合消费。
3. 人在生成控件内编辑具体字段，外部读取同一 owner 的新内容；外部调用原业务动作修改后，生成控件显示实际结果，人能继续操作。
4. 在未提交草稿/当前焦点存在时增删或重排结构，验证同一绑定的状态保留、失效绑定与迟到事件的拒绝；结构更新不自动提交业务内容。
5. 未知组件/属性/动作、越权绑定、过期结构版本、重复身份、超限和候选提交失败均有可区分的拒绝，上一份界面与业务内容不被部分破坏。
6. 第二个不同领域的公共消费者不复制解释器、renderer 或私有接线；同时验证未接生成能力的普通 UI 应用仍可使用框架。
7. 记录描述规模、冷构建/局部更新耗时、实际 build/layout/submit 工作量、编辑与空闲成本、移除后的资源收敛。与同等手写组件树比较，不把解析器速度当端到端性能。
8. 真实模型至少一次通过相同公开入口查询能力、生成/修改结构并与人接续。模型环境缺失时，前七项可分别交付为“生成式运行时/脚本消费已验证”，第八项保留未验，不能互相冒充。

上述标准是目标，不表示现有实现已通过；当前状态只见 ACTIVE。

## 共同定义的接入成本验收

按[共同信息只定义一次](AI_NATIVE_UI_SEMANTICS.md#共同信息只定义一次)，在生成式阶段合并验证，不另开治理台账：

1. 新增一个有真实读写行为的字段，只提供一份业务定义、规则来源和绑定，手写界面、外部能力查询与生成界面均能引用。允许分别安排布局；不再维护 AI 专用字段副本、校验副本或业务适配分支。说明实际新增了哪些业务代码、布局引用与框架接线。
2. 将示例“保留天数”上限从365改为730，只改共同规则来源。在相应定义生效并刷新后，三条入口均得到新范围：旧规则下366被拒绝，新规则下366可应用、731仍被拒绝。最终业务操作独立检查同一约束；旧定义缓存或过期请求不得绕过当前规则。数字仅是验收样例，不替换既有应用约定。
3. 查询后改变业务状态，使操作从可执行变为不可执行，随后提交原请求应返回当前拒绝原因，业务无部分写入；解除条件后再次操作可恢复。不能只检查控件灰显或声明中的 readOnly。
4. 把已有整数输入清空、再输入合法新值，草稿过程可以读回且不错误覆盖生效值；改布局保留草稿；应用/取消按共同策略执行。非法最终值不能因 AI 入口、默认控件或替代呈现而被接受。
5. 用至少两种兼容的呈现方式消费同一字段，例如默认数字输入与使用现有按钮组合的预设选项，保持相同数据、错误与业务约束。此项复用已有控件，不借机扩建控件库。

验收报告简述复用到的类型/注册声明与实际减少的重复接线。自动导出的描述只能证明信息生成；必须连到真实状态读写和上述失败路径才算这项能力通过。

## 后续检验

首阶段之后，用另一种独立样例检查复用，避免第一款应用的私有结构决定框架。
逐步增加编辑、复杂文本、无障碍、布局和样式，同时按明确阶段落实生成式接入；应用层可选不等于框架建设可长期省略。
效率评估比较完成整件事的耗时、错误、检查与接手成本，并记录应用开发者的重复接入代码。
采用相同任务和模型，与设计良好的 GUI 加结构化接口比较；只超过截图操作不足以证明框架优势。

探针、静态图、截图和模型回复各有用途，都不能单独证明完整链路。
