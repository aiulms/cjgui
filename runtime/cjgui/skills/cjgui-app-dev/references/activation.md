# 将技能接入项目默认流程

技能安装、技能清单注入、项目规则加载、模型实际使用是四个不同环节。
宿主可能只注入技能名字，也可能缓存旧清单；技能内部写了触发条件，不能保证未加载它的模型先看到这些条件。
AGENTS.md 是一种常见入口，不是所有开发工具的强制标准；宿主若提供禁止自动调用的开关，也要按其实际配置核对。
技能的 `agents/openai.yaml` 使用 `allow_implicit_invocation` 作为可选宿主元数据，不能把该字段套用到其他工具。

用户已要求默认使用时，在宿主实际会读取的项目规则中放置短入口，不依赖用户每次说出技能名。
本版 macOS 创建器自动生成应用 AGENTS.md，规则指向所选框架的技能源；使用导出 SDK 时指向包内技能，
应用与 SDK 保持相对位置一起搬动仍可解析。手动运行 activate 时，默认指向该脚本实际所在的技能目录；
链接安装会解析到维护 checkout，不会自动改指应用的 SDK。需要随包入口时，用 `--skill` 明确选定包内技能。
旧 SDK/旧应用不自动升级，已有应用可以一次性接入；新项目尚未有 cjpm.toml 时，
也可对已存在的项目根目录先接入口，让首次建项任务能看到规则：

```sh
python3 "$SKILL/scripts/activate.py" --project "$APP" --dry-run
python3 "$SKILL/scripts/activate.py" --project "$APP"
# 若宿主读取的是另一份项目 Markdown 规则，用其真实相对路径：
python3 "$SKILL/scripts/activate.py" --project "$APP" --rules-file RULES.md
```

默认目标为 APP/AGENTS.md。自定义文件名是示例，必须换成宿主实际加载的入口；不额外创造一份无人读取的文件。
脚本追加带边界的 CJGUI 入口，保留已有规则；同一入口重复执行不重复插入。
不改用户全局 memory、宿主配置或其他项目。生成规则只是路由，详细工作方法仍来自一个 SKILL.md。
若希望覆盖同一宿主今后所有项目，可在该宿主实际自动加载的用户规则中配置同一任务触发条件，
用其已安装技能作为入口；这是一次宿主侧配置，不宣称项目 AGENTS 会自动成为全局规则。

触发依据是任务对象：创建/修改/构建/诊断应用或查询其公开 API；依赖清单、workspace 成员、import 是识别线索。
纯框架内核/native/治理任务不因此转成应用开发；混合任务在消费部分加载。应用自身的 src/*.cj 正常触发。
新应用没有文件也可按任务意图触发，然后先建项；已有 workspace 的发现范围与实际构建成员分别核对。

## 技能升级、链接迁移与用户修改

模板或技能路径变化后先看 `--dry-run`：它返回 existing/proposed 块、差异、旧链接是否存在，
以及 `update_available`（可刷新）或 `conflict`（存在用户修改/未知旧块）。普通执行也会给出差异提示，
不会把模板更新静默写入项目。确认要更新这一项目时显式执行：

```sh
python3 "$SKILL/scripts/activate.py" --project "$APP" --dry-run
python3 "$SKILL/scripts/activate.py" --project "$APP" --refresh
# 指向指定 SDK 的随包技能：两次调用都加 --skill "$SDK/framework/cjgui/skills/cjgui-app-dev"
```

新块保存内容校验和模板指纹；刷新仅接受内容校验仍匹配的生成块，或完全匹配已知 v3 模板的旧块。
`--refresh` 只原子替换边界内块并保留文件权限、块外原始字节，返回 `refreshed`；它不是强制覆盖开关。
块被手改、标记重复/缺失/错序或未知旧模板均保留并提示合并，不根据 mtime 推断是否被用户编辑。
仅移动应用后，旧相对链接可能失效；指定仍存在的技能源后按上述流程刷新。旧验收产物保持原件，
需要验证迁移时使用其副本，不重写旧证据。只升级技能也不等于已升级所有应用规则。

常规空格/中文路径在链接中保留原文，文件工具可直接使用；含 `#`、`?`、`%` 等保留字符的路径
使用编码链接，同时给出相对规则文件的 JSON 路径字符串。文件工具使用后者解析出的路径，不能把编码目标照抄成文件名。

## 验证是否真的自动使用

1. 按宿主要求刷新或开启会话，确认项目规则已加载；若不支持 AGENTS，将同一入口接到该宿主的项目规则设置。
2. 给普通应用任务，例如“修复输入框挤掉底栏”，不额外提醒技能名。
3. 检查是否先加载技能/读取 SKILL.md，再识别已有应用的依赖、查询同版用法。只看到文件或缓存条目不算此项通过。
4. 纯框架实现任务不应仅因路径含 CJGUI 就触发；但框架任务中的正常应用验收可以按需使用。

脚本返回 `host_loading: not_verified`，不冒充完成上述宿主/模型验收。
宿主不向模型提供任何技能清单或项目规则时，仓库文件无法自行进入上下文，需要一次宿主侧配置或任务入口提示；
不要承诺所有 agent 都能无条件自动使用，也不要靠修改缓存文件伪造加载成功。
