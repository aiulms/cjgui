2026-11-02。指导为下一阶段准备的完整实施提示词，交用户选择的外部模型执行；没有向外部聊天实际发送或确认开工。不恢复旧 Sol/DS，不等待 H/W/Linux，不新建线程、监控或默认顾问。一个执行者贯通共同核心、公开接入、普通消费者与 SDK；模型由用户启动配置决定，不继承旧线程的强制子代理编排。

## 目标与选择依据

推进[首版正常应用与共同操作目标](2026-09-26-framework-capability-roadmap.md)：应用保持运行时，可以打开新的业务文档、切换编辑、关闭其中一份、再次打开，并让人和公开客户端安全接续。其他文档的未保存内容和版本不受影响。这里是业务正文文档，不是再实现已有的 UI 结构文档/history，也不扩成完整编辑器产品。

本次已核的具体缺口：`shared_text_document_workspace.cj` 的文档表在构造后不增加对象，关闭只改变已有 entry 的状态；`cjgui_document_client.py` 和 `DOCUMENT_CLIENT.md` 明确只保证端点生存期内资源 ID 不换绑。原有固定工作区是有效支持范围，不能据此宣称已支持任意动态 provider。打开文件已有 `CjguiTextDocumentFileBinding`，但不能为打开一份文件整体重建工作区、连接或其他文档 owner。

本包优先采用**每次新打开分配新业务 resourceId、同一端点生存期不复用已公开 ID**的已有契约扩展。窗口槽位、列表位置、标题、路径可以重复，不能成为文档身份。关闭后重新打开同一文件也是新的打开实例；旧目标必须拒绝。由此保留固定绑定保证，不先升级整套传输或另造实例票据状态机。任意 provider 的同 ID 重绑原子条件仍是明确未支持项，不能用客户端预检冒充安全支持。

VO 包已经[接受](2026-11-02-macos-voiceover-normal-use-package.md#guidance-final-vo-acceptance-20261102)，不继续补跑该包。性能旧路线缺少能支持生产优化的判别证据，本包不恢复 B/C/D、80事件或16/32ms采样；只观察新增文档生命周期的实际成本和资源回收。

## 连续完成的实现

1. **动态工作区。** 给现有公共工作区增加所需的运行时登记、关闭/退休和可枚举状态，接通普通应用的打开、选择、关闭及再次打开入口。保持同一工作区和 endpoint；最后一份文档关闭后能处于合法空状态，再打开仍可编辑。原构造用法保持兼容，不把新能力仅写进样例私有数组。文档身份分配与当前索引由明确共同 owner 管理；拒绝重复/退休 ID 复用及溢出，不用列表下标或文档版本充当身份。已关闭正文、历史和文件关联不能永久堆积在原 entries 表里。

2. **人和公开客户端同源接入。** 生命周期动作由现有业务入口执行，按现有声明和权限公开，普通界面与外部操作复用实现；应用仍决定可打开路径和授权。通过回执或既有可关联变更取得准确的新资源身份，不能猜最近选择或同名项。客户端动态发现新资源后沿现有 DocumentTarget 读写；保正文版本、工作区聚合版本及 endpoint/stream 的区别。新增/关闭 A 不应重置 B 的正文、版本或令仍有效的 B 目标无端失效。未知结果不重发，不刷新 CAS 偷偷重试；外部历史权限不因新增生命周期而扩大。

3. **编辑与保存衔接。** 接通动态列表/详情和现有输入绑定，使实际键入与公开读回始终对应当前文档。退休对象的在途回调、旧范围请求、旧目标不能转投新文档。复用未保存保护：取消关闭保留原稿；保存失败、载入失败或被外部修改时保留原文档与可信基线，不先退役再补救；正常保存或明确放弃后才关闭。每份文档的文件绑定须对应真实 owner，不让打开另一文件更换所有文档的保存目标。用户数据不通过界面结构文档保存冒充。

4. **公共交付。** 更新真实 API/能力说明、公共客户端用法与必要创建/导出入口，保持 experimental。需要结果元数据时作最小共同增量，兼容既有固定工作区，不预设协议大升级。合流后沿现有锁与 exporter 交唯一继任 SDK，eb58作为回退；只有载荷变化才导出，不逐补丁打包。包外调用从 SDK 导入公共模块，不依赖本聊天、私有 CASE 或未声明的根树路径。

## 必要反例与一次正常消费

先为本次真实缺口保可区分的生产反例，再作最小修复。重点是：关闭/重开同路径且正文版本再次为0时，旧 resourceId 仍不能命中新对象；已退役 ID 不得被重新登记；B 的保留目标在 A 生命周期变化后仍可用；失败打开/保存和取消关闭没有正文、版本或选择的错误副作用；旧输入完成不能串进新对象。复用已有锁、owner执行和拒绝机制，不用夹具绕开生产边界。图工具不覆盖Cj时局部读源补影响检查，不反复空查。

相关改动汇合后，在同一最终编译源的正常文档窗口合并完成：

1. 打开/保留 A、B，留 B 的正文、版本和公开目标；运行中打开 C，确认窗口没有重启、endpoint未更换，公开能力能发现 C。
2. A真实编辑后取消一次关闭，原稿可继续；完成实际保存并关闭。B正文和自身版本保持，聚合上下文变化另记。
3. 将已关闭文件在同一窗口重新打开，新实例使用新资源 ID。旧目标的一次写入被拒且不改新文档；显式取得新目标后一次外部修改成功，人按正常入口聚焦并连续编辑，完整正文/版本相符。离线反例覆盖同版本重开，不能仅靠版本恰好不同证明身份安全。
4. 复用已有读回与保存方法核 B未串写，最后文档关闭后再打开可用。保存本轮改变的业务文件，按正常窗口关闭路径取得实际exit0及endpoint清理；不以强杀代替。

保最少必要的原始输入、完整正文/版本、独立预期、源/编译/签名运行身份及退出记录。额外资源检查只做预先声明的少量打开/关闭循环，核活动文档、正文/历史持有和在途引用收敛，并记录峰与静置样本；不能只凭RSS波动断言泄漏或称已测完整峰值。旧关闭含未保存分支、系统输入和标准退出按影响复用，不重跑全矩阵。无中断或新失败不重复正常链，不以补焦、重发、延时或 AX 写值救绿。
