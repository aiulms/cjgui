## 完整交付是什么

开发者用同一套仓颉组件，在不同文案、字体大小、窗口尺寸和主题下组织可用界面，并能加载、复用和实际绘制本地图片。测量、布局、绘制、输入与外部可读结构保持对应；换主题、调整窗口或外部修改后，人能够继续当前编辑。

例如，规则列表缩窄后长名称按声明换行或截断，详情和底部动作仍可使用；通知界面换一套字体、间距、颜色和图标，只需调整仓颉组件及共享资源。两者消费相同框架能力，业务定义不因外观变化而改写。

文字、布局、主题、资源和更新调度是这个交付的内部工作。单个控件、图片探针或测试入口通过，不是阶段完成。两个现有消费者用于验收复用，不增加备份、通知等产品业务。

## 连续完成的框架工作

### 1. 实际文字测量和基础排版

用与绘制一致的真实字体测量替换 byte 数估宽，提供字体大小、必要字重/字体选择、回退、行高和基线信息。显示文字支持受容器约束的换行或截断，中文、拉丁文和组合字符不能按字节裁切。仓颉决定组件尺寸与布局，CoreText/AppKit 等必要系统测量和排版服务留在窄适配内。

同一份字体、文本原点和有效区域驱动绘制、单行编辑、光标、选区及组合态；明确传输字节、平台选区索引与字符边界的转换。延续单行编辑主链，不为此展开完整富文本编辑器或自行实现所有字形光栅化。文字如果仍由同场景 AppKit 层绘制，明确记载，不宣称文字已经全部进入 Metal。

无桌面测试可以注入确定的测量服务验证布局算法，但必须另有真实系统字体测量证据，不能把测试估值当实际测量。测量缓存要包含文本、字体和约束等实际影响因素，并有合理生命周期。

### 2. 能适应内容与窗口的布局

补足当前 row/column 的最小/最大/期望尺寸、伸展/收缩、对齐和内容溢出处理；具体 API 由执行 AI 根据两个消费者收敛，不需要完整 CSS 或通用约束求解器。文字测量参与布局，滚动范围随内容、字体和视口变化重新约束。

验证窄、中、宽窗口和至少两种字号：长中英文标签、空容器、动态列表、按钮组不相互覆盖；超出最小可用尺寸时，有明确裁剪/滚动或窗口最小尺寸策略。不要靠统一放大窗口、缩小所有文字或把页面断点写进 native 绕过布局。

调整大小和重排保留稳定节点、焦点及当前草稿；事件仍指向产生时的对象。bounds/clip、命中、无障碍与外部窗口关系仍来自同一组件及布局结果。

### 3. 可复用主题与实际图片资源

提供可被两个消费者共用的主题/样式入口，集中表达字体、间距、颜色和必要交互状态；默认值、主题值与局部覆盖规则清楚。修改一份主题能实际改变相关组件，不要求逐控件改 native 或复制整棵树的样式定义。切换时保留正在编辑的内容与交互身份。

增加有界的本地位图资源入口与图片组件，PNG 等一种常用格式足以起步。资源声明和逻辑身份由仓颉管理，系统解码服务可复用；像素通过现有 Metal 后端的真实纹理路径绘制，支持必要的缩放/适配、裁剪和透明度。仅保存路径、输出摘要、读回一个无关纹理或另加专用 NSImageView 不构成交付。

同一资源能被多个节点复用；缺失/无效图片有可识别结果，替换、移除和窗口关闭释放对应资源。定义缓存归属、无效句柄与失败返回，避免每次刷新重新解码或上传。原生纹理/设备对象不进入公共 API。使用本地小型测试/样例资产即可，不扩建网络下载、素材市场或通用资源平台。

### 4. 有变化才提交，呈现与共同上下文一致

解决当前普通 `refresh()` 每次重建、连接处理 GET 后也递增场景/重新提交的问题。按实际内容、尺寸、样式和资源变化失效；无变化的重复查询、纯选区变化不应提交新场景。可采用清楚的版本/比较/缓存方式，不以完整增量渲染器或新响应式运行时作为前置。

相关变化成批更新，保留 FIFO 顺序和已接受输入；样式或布局更新期间不能丢失文本、转投新对象或偷偷提交业务。简单记录测量、场景提交、资源解码/上传次数，证明缓存有效及读操作无额外呈现副作用；不用固定 FPS 口号替代证据。

继续从组件定义派生外部投影。复核并补齐上轮字段绑定的待项：外部能够明确判断控件显示的是草稿还是已应用值及对应关系，不靠猜 `draftX` 名称；同一声明同时服务显示与语义。图片可表达必要的内容标签/装饰角色，不能凭有图片推断业务动作。

维持授权过滤、无窗口投影、稳定对象及当前选区语义。提交成功与用户已看见仍要区分；没有实际读数时保留 unavailable/-1，不为了外观里程碑伪造呈现证明。

### 5. 普通包消费与测试入口收口

两个现有普通窗口都实际使用新文字、布局、主题和图片能力，仍由消费者仓颉代码组织不同界面。至少一个正常 UI 使用方式不启动外部连接；原来的无窗口 core/领域消费者继续独立工作。

定位并修复根包正常测试缺 native sidecar 的链接入口，给出明确、可复现的构建前置和 `cjpm test` 结果。可在阶段需要时最小调整 `cjpm.toml`、构建脚本及相关测试组织；不能删除有效测试、屏蔽未定义符号或恢复旧 Bool 审计链来做绿。若发现独立的旧测试冲突，区分已退役文案断言与真实行为失败，记录实际范围并继续相关工作。

现有探针保留为相应边界的证据，同时让开发者通过正常包依赖消费新 API，不以每个样例拼接源码作为唯一入口。更新 runtime README 的实际用法、资源位置、主题/布局配置、可选连接、稳定性及迁移说明；API 保持 experimental。

| --- | --- |
| 排版与尺寸约束 | [布局器](../../runtime/cjgui/src/composable_ui.cj) 的 preferredHeight 按传入宽度测文字，[native drawRect](../../runtime/cjgui/native/cjgui_internal_renderer.m) 又固定内缩左右各 7pt；临界宽度会出现测量一行、实际多行而高度不足的风险。crossAxisLength 在 stretch 下直接返回 available，忽略该轴的 fixed/min/max；横向容器的 naturalHeight 又在分配子项实际宽度前测高。这些需要真实宽度边界复现，不能只增加固定标题高度 |
| 资源替换与生命周期 | CjguiComposableImageTexture 只以标准化路径为键，命中后永久复用，缓存直到窗口销毁才清空；[窗口比较](../../runtime/cjgui/src/composable_ui_window.cj)也只比较图片路径/模式。尚无同一逻辑资源的新版本、显式失效、移除/替换回收和有界容量。不同路径能首次加载，不等于本阶段要求的资源生命周期已完成 |
| 测量与更新成本 | 每次 syncProjection 仍 buildUi、完整 layout，并新建[生产 measurer](../../runtime/cjgui/src/runtime_renderer_session.cj)逐次跨 FFI 测量，最后才跳过等价提交；没有文字测量缓存。生产测量失败也会静默使用 Rune fallback，因此“仅无桌面测试使用 fallback”与源码不符。保留跳过提交的改进，补实际缓存及可观察的失败/降级边界 |
| 动态样式验收 | 两个消费者在 buildUi 中分别固定选择 beaconDark/paperLight，并仍重复不少颜色/尺寸；没有运行中切换主题/字号/字体与局部覆盖的完整使用证据。不同应用各有一种外观不能替代“同一编辑会话换主题后继续”的验收，字体选择也仍只有系统字号和两档字重 |
| 图片验证强度 | native 图片分支把 drawable 采样“与清屏色不同”当 pixel_match；已有背景或其他绘制也可能满足。控制器探针主要检查 loaded=1/cache=1，未验证已知源像素、透明度、fit/fill、替换和失败恢复。实际纹理编码代码存在，但当前断言不足以证明这些结果 |
| 外部绑定与结构变化 | displayValueRole 是组件上的显式字段，但当前输出只将它拼入 `resource…_field…_role` 目标 ID；[关系契约](../../runtime/cjgui/shared_operation_core/src/shared_operation_contract.cj)没有独立角色/值来源字段，目标也没有对应可读字段值节点，外部仍需推断命名。sameRenderedScene 只比较平铺节点，等价即返回且不更新 renderedRoot；还需覆盖层级改变而平铺几何相同的关系更新 |

### 按一个完整动态界面交付继续实施

目标是让开发者在**同一运行窗口**里改变文案、字号/字体、主题和图片，窗口正确重新排版并保持人的草稿/焦点；外部仍能明确读取同一字段的草稿和已应用值。资源更换或失败可恢复，重复读取的成本有界。沿用原五项工作及验收，下列是复核校准，不取消其他尚未完成项。

1. **文字、约束与测量接成一致路径。** 先复现临界行宽、长中文/组合字符、嵌套 row/column 与 stretch+fixed/min/max 的结果，再统一实际内容区域、分配宽度、行高和绘制。以共享的必要字体描述支持有限的系统字体选择/回退，字体和文字服务对象保持平台内部；不扩展富文本或全部 GPU 字形引擎。建立按文本、字体、宽度及排版选项区分的有界测量缓存，纯 GET 不重复执行同样的系统测量。生产测量失败应有明确错误或可查询降级结果，不能静默估算却宣称真实测量成功。

2. **主题与图片成为可更新、可释放的框架资源。** 接续现有主题和图片节点，提供清楚的默认/主题/局部覆盖行为及必要交互状态；两个消费者通过配置或少量演示控件，在运行中换主题、字号和图片，不将样例业务塞进 native。图片有明确逻辑身份/版本或失效入口，同路径内容的受控替换能够刷新；多个节点复用同一资源，替换/移除与缓存容量有界，仍在使用的帧资源不能过早释放。缺失/无效资源产生明确结果，保持最后有效场景或声明的占位行为，并能纠正后继续使用。不得用不断换文件名掩盖永不失效的缓存。

3. **更新成本和共同上下文同时正确。** 保留等价场景不提交的能力；测试真实测量次数、解码/上传次数、缓存与提交次数，合理的小型诊断即可。资源版本、主题和布局变化被正确纳入失效，纯选区不制造业务写入。外部获得可直接解析的资源、字段、显示角色及值来源/对应关系，继续从组件及领域声明派生；允许扩展现有只读值契约/传输，不另造可写业务副本或服务平台。字符串 ID 保持标识作用，不能要求靠下划线拆 ID 才知道当前草稿。层级或绑定变化即使不改变像素，也必须更新可读上下文，不必因此强制 GPU 重绘。

4. **完成两个普通消费者的动态使用周期与可靠验收。** 实际进行“输入形成草稿 → 换字号/主题、缩窄/放宽、替换图片 → 外部发现并读改 → 人继续编辑/应用”。规则与通知都消费同一 API；至少一个正常 UI 使用入口可不启动连接，纯 core/领域继续独立工作。图片验证使用已知小型像素/透明度样本和可识别的背景，对 fit/fill、裁剪及替换结果作实际绘制断言；加入能表明漏画图片也会失败的对照，不能继续用非清屏色充当纹理匹配。保留现有 AppKit 同批文本/Apply、selection、领域及根包检查；新增针对缺口的回归后按实际影响完成最终包验证。公开语义改变后，按原阶段要求做一次独立 Agent 的真实发现/调用验收，而不是只展示预知字段的脚本输出。

正常窗口的主题/字体/资源更新可由真实生产控制器路径进行程序化驱动，锁屏时先完成这些可独立工作；标清系统服务、程序化窗口和真实键鼠各自证据。物理中文 IME 的候选/组合/提交/删除/粘贴单独保持待验，不能以它为由停止本轮其余实现。

根包 sidecar 链接修复已得到执行验证，不再列为当前失败；只对后续改动运行必要回归。原 SDK 15.4 workaround 的上游状态仍未重新查询。其他已通过且未受影响的保存、授权、流身份等能力继续复用。

不另开阶段文件、任务或执行卡。同一 Terra/xhigh、同一目录，自主完成上述完整使用周期后，更新 ACTIVE_DIRECTION.md、README 的真实限制和本文件交付报告，主动回报指导任务，由指导 AI 复核接续。实现和独立验收仍未完成前，不以完成单项修复或改动状态文字结束。

## 收官执行报告（2026-09-12，待独立复核）

**结论：本轮框架实现与当前执行者的定向/真实窗口验收已完成，但阶段尚不能标记完整完成。** 尚缺一次由独立 Agent 仅凭真实 descriptor、公开客户端和自然语言目标作出的盲发现/调用验收；物理中文 IME 的候选、组合、提交、删除和粘贴仍为 `not_run`。两项都没有被脚本、AX 或程序化 Unicode 输入冒充。

### 本轮落地

- 布局将文字测量和最终绘制的横向内缩统一；stretch 遵守 fixed/min/max，横向自然高度按分配后的子宽计算。生产测量缓存以文本、字号、字重、字体族和宽度区分，容量 128；原生测量失败会保留旧场景并报告失败，不能静默回退后宣称成功。`fontFamily` 仅接受 `system`/`monospaced`，未知值归一为 `system`。
- 图片节点拥有逻辑 ID 与版本；native cache 键为 ID、版本、路径，活跃项可复用，替换/移除后回收，缓存上限 8。图片、主题或字体变化会触发正确失效；纯读和像素等价刷新不重复 native 提交。像素相同但层级/绑定变化会更新仓颉语义投影，不伪造 GPU 重交。
- 透明装饰资源的通用首帧诊断不能安全证明源像素时输出 `image_pixel_unverified`，不把它写成成功像素匹配。原生测试侧运行时生成非方形、已知 RGBA PNG，通过生产 Metal 编码后的实际 drawable 像素验证 FIT 留白、FILL 裁剪、clip、完全透明和半透明合成；同一 fixture 故意省略图片节点的负对照会失败，避免断言恒真。
- `WINDOW_FIELD_VALUE` 成为公开直接契约，包含 node、resource、field、显示角色、值来源和 typed value；不再靠解析 `RELATION` 的目标字符串得到 draft/applied。
- 通知和规则集消费者各自增加本地“外观/字体”“图标”控制：切换浅/深主题、system/monospaced 与蓝/珊瑚灯塔；这些是消费者呈现状态，领域真相未复制。珊瑚灯塔是本轮新生成并打包的本地 PNG，作为同逻辑 ID 的实际资源替换资产。
