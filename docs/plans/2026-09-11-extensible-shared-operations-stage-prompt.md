## 一次完成的交付目标

### 1. 可由应用实现的共同操作契约

- 定义必要且 experimental 的资源/对象身份、命名字段与类型、当前上下文、版本、动作描述、参数和实际结果。
- 至少支持本阶段确实消费的字符串、整数和布尔值，以及必要的对象目标集合；不要预造任意对象数据库、DSL 或通用反射系统。
- 领域状态继续由应用或现有列表模块唯一拥有。框架负责接入和共同检查；快照、语义、界面是投影，不能再存一份可独立修改的业务真相。
- 动作由应用注册或通过明确接口提供，参数描述用于发现和校验。执行必须进入真实 handler，不能只输出允许执行的摘要。
- 人的应用入口与外部调用复用同一业务动作实现；调用上下文与授权范围可以不同。授权身份由可信入口产生，不能接受外部请求自称为人类而绕过限制。
- 保持现有稳定 ID、同一业务锁中的版本校验与原子修改。未知对象、非法参数、业务拒绝、越权和过期请求均有明确且不误报成功的结果。

### 2. 连接层不再认识具体业务动作

- 将当前私有目录、descriptor、capability、完整 frame 收发及正常关闭逻辑复用于通用连接入口。
- 连接面向资源、快照、动作描述和调用请求，而不是内置 SET_MARKED/isMarked 分支。编码仍可替换，不为本阶段发明统一协议平台。
- 让授权明确覆盖资源、动作和对象范围；所需参数约束由声明或业务规则实施。检查必须在真正执行前有效，不能只校验广告出来的元数据。
- 读取和描述同样遵守授权范围；错误响应不能顺便返回未授权内容。已有授权继续复用，不新增每次操作的确认流程。
- 支持按明确目标范围获取上下文，避免只能每次全量返回所有记录；本阶段不要求完整查询语言、订阅系统或分布式同步。
- 相同公开客户端能发现并调用两种不同业务的动作，不为每个新动作再增加客户端源码分支。

### 3. 既有列表作为第一种消费保留下来

- 让现有列表接入上述契约，继续支撑 101 条记录、八行视口、选择、标记、授权批量设值与冲突处理。
- 复用已有 native 投影/输入桥，不让它承载通用领域语义。本阶段不要求新增原生控件或改绘制路线。
- 避免保留两套长期独立的执行主线。必要的兼容入口只能委托到同一业务实现。
- 现有 API 为 0.0.x；优先薄兼容，确实不值得保留时做明确版本/迁移说明，并同步所有活跃消费者和测试。

### 4. 一个真正不同的数据与动作消费者

- 增加正常包消费的无窗口配置样例，例如备份规则配置：启用状态、保留份数、排除类型等真实内存配置，不启动实际备份或调度服务。
- 样例自己声明字段、动作和业务约束，例如保留份数的合法范围；不能把业务动作和字段写回框架或伪装成 isMarked。
- 至少实现一个包含多种参数的实际修改动作，并通过同一业务入口验证应用侧修改和外部修改的接续。
- 通过真实独立进程和 Unix socket 完成发现、读取、调用、读回、业务拒绝、越权拒绝及过期请求处理。
- 至少做一次独立真实 Agent 验收：仅提供公开客户端、descriptor 和自然语言目标，不提供目标对象 ID、动作名或预写的完成脚本。让 Agent 从实际描述和内容选择动作、构造参数并读回结果。
- 使用现有已授权 Codex Agent 即可；可交给 Luna 做独立消费和验收。记录真实模型与轨迹，不能把固定脚本改名为 Agent。新增客户端测试必须与真实 Agent 记录分别标注。
- 再仅在消费者增加一个自定义动作或改变业务字段，证明不需要修改框架 dispatcher、授权动作枚举或通用客户端。这是复用验收，不另造完整产品。

### 5. 不需要打开窗口的正式构建与测试入口

- 建立 core/transport 的正常包或等价构建边界，使上面的配置消费者无需链接 renderer 的 AppKit/Metal FFI，也不初始化 NSApplication/WindowServer。
- 先检查仓颉工具链实际支持的包组织方式，再选择最小拆分。只处理当前共同操作能力及消费所需依赖，不搬迁全仓历史模块，不通过假 native stub 宣称解耦。
- 核心的类型/参数、业务 handler、版本原子性、授权、Unicode/分片 frame、独立实例和关闭重启都能从一个明确入口自动验收。
- 复用已有真实行为测试，增加针对新风险的测试；不要只累计测试数量或添加镜像实现的断言。
- 保证配置消费者和已迁移的列表消费者真实调用普通构建产物，不能复制源码到临时 package 冒充公开消费。
