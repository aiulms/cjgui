# 大阶段：动态复合组件、弹层引用与共同操作

2026-09-14 指导授权原任务 Terra/xhigh 配合 Luna/high 在原目录持续执行。本轮同时承接上一轮身份机制的边界与消费欠项，并交付真正可重复使用的动态组件；不要做完一个补丁就停工。

## 交付场景与方向

开发者写一次“带操作菜单的记录卡片”，能在两个列表或窗口里重复使用。插入、排序、滚动和删除后，菜单仍锚定正确卡片，编辑弹窗先聚焦正确字段；人修改和外部已授权调用都到同一真实对象。无需开发者提前算数字 ID，也无需为每种业务改 native。

这是仓颉高性能自绘 GUI 框架的通用组合能力，不是规则编辑器功能扩张。复用现有 scope/key、窗口候选事务、唯一布局/命中/语义投影、变量列表 stable key/有界测量、弹层/焦点/capture、公开 owner/CAS/窗口 target。设计入口是 [设计意图导航](DESIGN_INTENT_INDEX.md) 的组件复用、输入和单一状态归属；避坑原文的状态双真相、事件重入、盲目重绘风险继续落实，历史禁止实施语句不恢复。

## 上轮复核与必要承接

[身份阶段](2026-09-14-component-identity-milestone.md)已有公共 API 与两个正常消费者实现，指导已抽查 resolve/prepare/commit/rollback 接入，不重跑执行测试。以下须有证据闭合，未闭合前只接受已验证部分：

- 完成报告未提供最终导出消费日志/payload，而 ACTIVE 声称已经收口。找回已有原始证据；没有则标为未验，随本轮最终源码在含空格隔离目录一次完成正式导出和独立消费。工作区 bundle build 不能替代。验收日志被移入废纸篓，恢复必要原始日志与 source/binary 指纹到可读取证据目录；任务结束只清运行实例和临时端点，不丢弃验收证据。
- `Identity.isValid()` 当前局部 key 只校验长度，scope 段却有 ASCII/字符规则；重复诊断直接拼 local key，公开 transport 还要求安全诊断。复现含空格、换行、中文的 local key 路径，选择明确的公开规则：一致拒绝非法 key，或安全编码并约束诊断；不得让一次非法声明导致后续公共失败读取本身失效。不要把任意业务文本当诊断原文外发。
- 注册表的 1024 上限只在分配新 ID 时检查。复现已接受满额、候选先加入新 key 再加入全部旧 key，以及相反顺序；容量检查应覆盖每个候选条目，失败不修改 accepted。同时覆盖删除/重建和拒绝后的重试；正常窗口布局上限不能替代公共注册表自身约束。
- 当前30样本只是同一集合交替排序，且毫秒精度不足、正确性检查在计时内。沿用项目已有 `MonoTime.toNanoseconds()` 做本阶段相关范围的冷热、替换/增删、失败恢复计时，正确性比对放计时外；报告 live/pending 条目及字符串保留边界。不补跑无关文字/渲染矩阵，不凭0ms宣称性能极限。

## 本轮新框架能力

1. **可声明的组件引用。** 让弹层锚点、owner、初始焦点可引用作用域内稳定声明，引用在同一候选中解析为最终节点。兼容手工 ID 接口；明确缺失、错误窗口、歧义、已删除/重建目标的处理，不能静默选择第一个节点。外部仍消费真实已接受投影，不新增可写业务状态或永久全局查找表。Terra选择最小可解释 API，不要求固定命名或新增独立运行时。
2. **虚拟列表里的复合组件。** 当前 window 在 layout 前 resolve identity，而虚拟行在 layout 内 buildRow，须让真正物化的行也走同一身份与引用事务。复用唯一测量/物化流程，不为解析先建立所有屏外 UI、不做双份布局树。固定/变量列表共用部分沿用；本轮至少变量高度列表真实接通。稳定业务 key 与布局 ID/物化代际分开：屏外对象仍能授权操作，重新显露正确；离开视口后的挂起菜单、焦点或捕获按明确规则取消/恢复，旧事件不得串到新行。
3. **完整失败边界与重用。** 候选身份、引用、动态子树和缓存只随实际接受晋升；晚期布局/原生拒绝和异常保持原接受场景可用。核查同一调用者节点对象跨刷新/窗口复用时 `resolveNode` 原地写 nodeId 的别名风险；有真实复现则修复候选隔离或给出可执行、清晰拒绝的所有权边界，不能只靠注释让两窗口互相修改。复用既有事务，不另造回滚业务操作的机制。
4. **两种正常消费。** 规则列表实际重复使用带菜单/编辑入口的 scoped 组件，覆盖空→首条→增删/重排/滚动→弹层/焦点→人和公开调用接续。第二个正常消费者采用两份同类组件或嵌套组合，实例拥有不同真实目标；应至少一次在正常同进程多窗口入口完成 A/B 切换操作、关闭 A 后 B 继续工作，顺带收口旧多窗口前台欠项。若锁屏或工具确实不可用，保留明确未验并继续其余工作；两个独立进程不能替代同一 application 多窗口证据。

## 验收与交付边界

- 针对真实缺口补 RED→GREEN；同作用域重复、跨作用域同 key、前插/删除/换绑/排序、滚出后返回、弹层锚点与初始焦点、失败候选/重试、旧 AX/pointer/排队输入的路由必须可区分。原正常手工 ID 消费保持相关回归。外部诊断非法输入也有公共读取结果，不能仅看内部字符串。
- 以相同内容/布局和测量环境比较规范输出；小中大重复组件、主要冷热和 churn 条件每个至少30有效样本，实际 ns 计时+保留量，并核查最终接受投影无未解析/重复身份。只对实际新增开销下结论，不能把 CPU 耗时当 GPU/物理呈现。
- 相关核心、布局/窗口、两个消费者、原生边界/公共声明、根构建与 diff 检查；同 cjpm target 串行。最终源码导出在含空格路径实际构建使用本轮新公共 API 的独立应用，核对源清单、payload 与 binary，并保留原始成功/失败日志入口。没有第三方模型运行就仍只称公开脚本调用。
- 系统 IME 只集成不自研；本轮不扩富文本/多平台，不重做已经通过的无关基准，不增加安装/公证/发布。GPU/文字/资源已有路径继续使用。完成此组合阶段后优先据正常复杂场景热点判断调度/布局/渲染性能的下一步，不能无限衍生身份边界任务。

## 分工与持续推进

Terra负责解析时序、候选归属、公共引用和跨窗口/输入生命周期；接口明确后将两个消费者迁移、明确回归和最终独立消费交 Luna/high 完整工作包。必要旧问题与新能力依依赖穿插推进，不要求全清零后再做独立工作。Luna消息给实际父代理、final自动回父；Terra汇总后报告指导任务 `01a08f0f-e1ce-71c1-9a6e-4eee08308d61`，不让Luna日常报告直接发指导。

桌面由一名执行者操作，同轮复用自有临时窗口，只在必要换 binary/生命周期测试/失效时重启，整轮结束退出并验证端点清理，原始日志保留。保护用户实例；不切分支、不提交推送、不新 worktree。反复失败按 AGENTS 的 Terra/K3/指导升级，继续独立工作。完整阶段交付或重大结构阻塞主动回报，不等定时器；无需新执行卡或逐轮台账。
