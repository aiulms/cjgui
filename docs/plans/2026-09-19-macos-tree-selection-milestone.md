## 目标与场景

集中 macOS 主线：修完数据交换的两个具体旧问题，同时交付可复用的树形视图、多选和共享批量操作能力。鸿蒙由用户明确挂起：不继续修改 labs/ohos_gui_smoke，不查 SDK/镜像、不申请/下载、不补该实验测试。恢复需用户另行提出。

应用场景：开发者用 CJGUI 组织“分组→规则/条目”的层级界面。人展开分组、用鼠标和键盘跨行选择并批量启用；外部调用能读到同一选择，按已授权对象 ID 修改 100 条屏幕外记录；人展开/滚动后看到具体结果并继续编辑。树仅组织业务内容，不另存一份可写业务数据库，也不把项目做成文件管理器。

这是框架能力阶段，不是样例美化。新能力必须在至少两个不同消费者中成立：一个既有规则窗口、一个独立公共 UI-only 树消费者。保留 macOS 自绘/GPU、仓颉组件/布局/命中/状态、窄平台桥接；不替换为 NSOutlineView，不要求聊天框、Agent runtime 或特定编码。

外部执行 AI 主导整阶段，Terra CLI 按需聚焦只读判断。内部按依赖分步，旧问题与新能力穿插；只有确实影响安全或正确性的旧项阻塞对应验证，不把旧问题全部清零作为新能力开发前提。整阶段完成或所有独立工作完成后仅剩具体外部条件，才集中回报。

## 必要旧问题：给定方案与可区分验收

### 1. 剪贴板守卫与实例清理

**根因线索：** `verify_instance_isolation.sh` 的外层快照确已提前，但 LAST_EXPECTED 最后记着 CHAIN-VALUE-1，随后内层 restore 已把系统剪贴板变成 USER-ORIGINAL fixture，外层退出会因 expected 不匹配跳过真实原值恢复。`verify_shared_document_transfer_chain.sh` 虽增加 Cmd-C 后的 W4 校验，却仍在粘贴、等待和读回之后再次无条件 snapshot expected，旧的“把用户新复制接管为测试值”风险仍在。对照 cleanup 的通用可执行名匹配、启动失败与迟到启动的清理也需按实际路径核实。

**实施方案：** 使用唯一不可覆盖的 outer-original；每次确认属于本轮的写入/内层恢复成功后才更新 outer-last-owned 状态，避免 expected 仍指向恢复前内容。guard 自己执行写入/恢复时可返回操作后的 change-count 与快照，失败不能报告已接管。非本轮复制发生后，不能再无条件把当前值记成自己所有或覆盖它继续测试；优先把守卫分支测试放入独立 pasteboard，真实 Cmd-C/V 保留一次受保护链。删除粘贴完成后的无条件 snapshot；Cmd-C 的确认应结合预期类型/内容与写入前后版本，失配保持用户数据并停止依赖步骤。不要创建通用全局守卫服务。

**验收：** 独立验证驱动保存最外层真实全类型快照，运行正常/故意失败/模拟中途复制三个场景，在被测脚本 EXIT 已完成后检查实际剪贴板结果，不能仅检查被测脚本自己的 PASSED。包含内层 restore 后 outer restore 的序列；有非文本自定义类型。故意还原旧 expected 管理逻辑时该验收必须失败。对照实例按本轮准确 PID/路径/启动身份退出，退出前真实公开读回验证仍响应；不使用用户实例试验、不按通用名称杀进程。保留源指纹和新日志，勿复用旧日志名覆盖历史证据。

### 2. 释放验证必须使用同一判定器

**根因线索：** 当前正常分支不判 created/released 平衡，负对照分支只检查两个总数不等。正常22/16与故意泄漏22/0都可被各自分支接受，不能证明负对照检出了正常检查会漏掉的缺陷。`getenv(...) != NULL` 还会使设置为0也开启钩子，并把所有填充对象都保留，与“仅泄漏一个”注释不符。探针已关闭所有自有窗口，不能用“活窗口合法持有”笼统解释进程末尾残留。

**实施方案：** 观察器输出单调对象 ID、创建/释放、所属 session 和阶段；在最后自有窗口关闭并经过明确 autorelease/清理边界后运行同一集合判定：应释放集合减已释放集合必须为空，无重复释放。合法保留的对象必须逐 ID 说明 owner、原因和最终释放时机，不能放宽成允许任意差值6。不把 session=0 当释放。正常与负对照都调用同一判定器，故意仅保留一个指定已填充对象，必须返回非零且指认该 ID；外层 runner 仅将“预期的非零且 ID 正确”认作负对照通过。0/未设置时不注入。

若仍有对象存活，沿 accepted/candidate、overlay、session、autorelease pool 的实际引用链定位：先确定正常清理边界是否真正执行，再决定是观察窗口错还是生产泄漏。必要时 Terra 聚焦诊断，不改测试允许的残留数来转绿。FIFO/owner/pasteboard 所持 payload 与 declaration 对象分别归类，不声称观察到 item 释放就证明所有内存释放。实际分配峰值仍未测，保留独立限制；可结合本阶段反复开关/替换的有界资源观察补证，不让 RSS 精确回零成为无限试验。

这两项已多轮返工：执行前将上述具体差异和预期失败条件合并交 Terra CLI 一次只读审查，要求核对判定器能否真正失败。明确方案后本地完成实现/验证，不再只改日志措辞。若再次失败，按原累计升级并继续独立树能力；不因换阶段清零。

## 新能力的完整交付

### 3. 通用树数据与虚拟化

提供 experimental 的纯仓颉层级数据源、展开状态和行组合入口。数据源负责稳定 key/resource ID、父子/子项查询与数据版本；框架负责展开后的行投影、深度/缩进、可见行构建和交互。仅持必要索引/视图状态，不复制业务字段，不向公共 API 泄露原生句柄。空树、删除、重排、节点换父、重复 key/环/非法父引用都有确定结果，不能死循环或点击错误对象。

复用虚拟列表和现有行节点/布局/绘制；允许新独立文件承载树与选择，避免把所有功能塞回 composable_ui.cj。不立即支持远程异步懒加载、文件扫描、任意列树表、拖拽重排或完整 IDE 工作区。首轮固定行高即可；现有变高列表保持兼容，不要求本阶段再做一套变高树索引。

展开/折叠或数据版本变化时可做有界索引更新，首次 O(N) 建索引可接受但要计时；热滚动/hover/局部选中不能每帧遍历全部逻辑节点或重建所有行。缩进、裁剪、布局、命中、AX 行边界共享同一结果。节点在屏幕外仍可按 stable ID 查询/操作；视口不充当授权范围。

### 4. 多选、焦点和键盘接续

选择状态以 stable key 集合保存，锚点、焦点、展开和滚动分开。不要把现有单选 selectedKey 改成隐含全局选择或破坏旧应用。推荐复用/组合现有列表状态，新增多选层；具体 API 由执行者按当前接缝选择，公共签名保持 experimental。

默认语义要明确并测试：单击单选；Cmd 单击切换；Shift 按当前展开后的逻辑行顺序连续选择；上下移动、左右展开/折叠/移至父子、Home/End，以及焦点树内的全选。树失焦时不截获文本编辑器的 Cmd-A/C/V。全选默认当前展开投影内的可选逻辑条目，包含视口外行，不自动选择折叠子孙；分组是否可选由源声明。

折叠保留仍有效的逻辑选择，隐藏焦点退至最近可见祖先；删除只移除失效选择/锚点，重排仍跟随 stable key，不能跟随旧行号。Shift anchor 被删除时采用可解释回退，不向无关分支扩选。范围选择使用当次数据版本/投影，排队事件遇真正失效身份按现有输入契约拒绝。虚拟行卸载不应清掉合法选择。

应用开发者可只使用 UI；需要外部能力时，从同一个选择状态导出当前 keys、focus、anchor 和版本，通过同一个选择/展开处理入口更新，不另做可写语义镜像。系统可访问投影给行标题、展开/选中状态与父子关系所需信息；先映射到既有 AX 能力，缺口窄补，不声明完整屏幕朗读验收。

### 5. 两个消费者与真实批量业务

既有规则窗口增加一个实际使用上述公共树入口的分组视图。可从规则现有字段生成稳定分组（例如启用/未启用），不先建立新持久化分组系统。树叶对应原 record ID；状态变化导致移组时选择保持，当前草稿/未保存数据不被重建丢弃。多选后批量启用沿现有 BATCH_SET_ENABLED 及其授权/CAS/草稿冲突入口，框架不实现业务事务。调用方明确得到应用或拒绝结果，不能在native内逐条绕过校验。

同一运行实例完成：人通过鼠标/键盘选中多条→公开调用读到精确 keys/记录字段→外部授权批量修改100条合法记录（含视口外对象）→展开/滚动显示真实字段→人继续编辑其中一条→公开读回。无需滚动100次执行批量；100条不可超过现有 domain 限额，不为探针扩容量。补 stale、撤权/无权、含草稿冲突的拒绝，确认不部分落账；可撤销性以现有 owner 支持为准，不新建业务 undo 栈。

第二消费者是独立导出的 UI-only 层级目录/条目示例，使用不同的树数据形状、行呈现与选择处理，只依赖公开包；不用复制规则 runtime 或链接私有测试符号。证明组件可复用而不是规则窗口专用代码。示例不是文件管理器，不扫描/修改用户文件。

### 6. 性能、失败与公共消费一起验收

在确定性的100/1,000/10,000逻辑节点数据源上记录冷索引、展开/折叠、热滚动、范围选择、局部字段更新与 idle 的工作量/实际耗时；初始规模可用合成但实际源/构建/布局/提交必须走生产组件。树模型节点数、展开行数、实际构建行数、已保留子树/测量记录分开统计。行物化与视口+overscan有界，选择/索引可随逻辑数据增长但不能每行保留 UI 子树。

记录固定视口下的 source 查询次数、build/layout/submit 和原始样本，计时外检查选择/命中/字段正确性；热路径至少多次取样，不能用单样本宣布高性能。以现有等价平铺虚拟列表或本次同进程基线作可解释对照，不设未经测量的行业百分位。局部选择不得触发无关全树或另一窗口重建；另一个窗口输入/外部请求仍可推进，idle无业务变化不持续重绘。

覆盖 collapse/delete/rebind 后的焦点/选区、viewport resize、另一窗口、超界键盘与关闭后的迟到输入。明确区分单元/受控输入、正常窗口桌面自动化、外部脚本、真实模型、人工物理输入。无需接付费模型才能验公开调用，不声称脚本就是真实模型。

最终一次含空格独立导出/构建/运行新树消费者，保留源码/产物指纹与原始日志；正常规则窗口的同源批量链独立标记。公共 API 和 native/FFI 变化按实际影响检查；旧测试只有受影响才重跑。验证实例整轮复用、结束按准确身份清理，保留证据不保留无用窗口。
