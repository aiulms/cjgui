## 实际问题与交付

规则首次新增已复现：owner成功，刷新因 duplicate_node_id 失败。split 默认 handle 使用 nodeId+2，与列表内容22冲突；当前消费者改成24并回归通过，但公共 split helper 仍用数字偏移推导内部节点。这是框架组合成本，不能只靠为每个样例换一个数字长期规避。

本阶段交付开发者可复用的稳定身份/作用域机制：同一个复合组件可实例化两次、嵌套组合、动态增删而不碰撞；列表重排保持同一条目身份；鼠标/焦点/外部语义仍指向同一真实对象。保留低层手动ID消费能力，提供安全的公共组合入口，不要求所有应用一次迁移。不是新的响应式运行时、编辑器或自动生成产品。

## 复用与设计责任

复用 composable_ui.cj 的唯一布局/duplicate检查、composable_ui_window.cj 的接受场景/输入代际/焦点与捕获、变量列表 stable key、场景候选提交和已有公共owner/动作。按 DESIGN_INTENT_INDEX.md 的组件复用、稳定身份、事件重入和语义单一来源要求落实；不要恢复历史审计链。领域resourceId、语义名称、窗口会话和布局nodeId含义不同，不能为避撞把业务身份也换掉。

Terra先确定最小可解释方案并在本页简记：组件实例作用域+稳定局部key映射为布局身份，或等效受控身份分配。身份由明确的应用/窗口构建上下文负责；不能进程全局无界增长、按每次遍历顺序重新编号、碰撞后静默覆盖，或只用未检查哈希。内部生成节点不得偷偷占用调用者数字范围；耗尽/重复key/混用冲突明确失败，候选失败不损坏已接受映射。若使用注册表，条目/字符串/代际生命周期有界，删后重建与延迟事件策略清楚。

## 完整范围与验收

1. **公共安全组合。** 落地可选公共身份上下文/作用域入口，并让 split 内部 handle、一个含多个可交互子项的复合组件实际消费。支持重复实例、嵌套和同名局部key在不同作用域共存；同作用域真正重复仍报告冲突。保留旧手动节点接口及明确混用规则，不通过扩大默认数字段掩盖问题。公共API只含仓颉值/对象，不泄露native token。
2. **动态身份与状态接续。** 动态条目前插/删除/排序时，稳定key的业务绑定、焦点、选区、滚动锚点和捕获按已有契约保持；删除/换绑/关闭后的旧事件不得命中新对象。对象重建是否复用布局ID必须与scene/目标代际保护共同验证。场景构建或提交失败保留原接受状态，新候选映射仅在真实接受时提交，不另造业务状态机。
3. **可诊断的拒绝。** duplicate/非法身份等失败给开发者冲突位置或作用域/局部key等足够定位信息，避免只见按钮无响应。诊断不改变owner操作结果，不把渲染拒绝当业务回滚；已有公共进度/失败通道能解释owner已变而scene未接受。默认不持续日志、不把未授权内容泄露到外部诊断。
4. **两个实际消费者。** 规则样例从空到首条、增删后返回空、滚动到后续行，使用安全组合；另一个消费者实际摆放两份相同组件或嵌套split，不共享错误捕获/动作。人事件与真实公开调用仍到正确owner，外部读取的节点关系/目标可区分组件实例。无需样例私有native代码，正式导出副本含空格路径能消费新的公共入口。
5. **正确性与成本。** 同一规范布局场景比较新旧接口输出，覆盖手工ID与作用域混用、重复局部key、强制候选失败、结构重排、缓存复用和旧事件。小/中/大实际组合、至少主要冷热/重建条件30样本，用同进程实际计时及映射/保留量确认身份机制无随历史轮数无限增长或二次方查找。计时不冒称物理呈现；不重跑无关文字/缓存大矩阵。相关核心/消费者回归、根构建、FFI/声明/diff检查及最终导出一次完成。

## 实施结果（2026-09-14）

- 公共入口为 `CjguiComposableUiIdentityScope`、`CjguiComposableUiIdentity`、每窗口 `CjguiComposableUiIdentityRegistry`、`cjguiComposableScopedSplitView` 与 `cjguiComposableScopedActionRow`。作用域和局部 key 都有 ASCII/长度边界；旧手工 `nodeId`、旧 split helper 与其消费方式保持兼容。
- 注册表只在真实 scene 接受时提交候选映射，失败候选回滚且不改变已接受投影；手工 ID 不进入内部生成号段。重复局部 key、手工冲突和纯布局路径漏解析都会给出安全、可定位的诊断。删除后重建获得新布局 ID，仍由既有 scene/目标代际拒绝旧事件。
- 规则消费者恢复内容手工 ID `22`，由作用域 split 生成 handle；文档消费者以一个作用域 action row 生成撤销、重做、保存、关闭和菜单项。二者的业务语义、资源、owner action 与 native 边界没有改由新机制持有。
- 针对性 probes 覆盖重复/嵌套 scope、手工混用、重排、候选重复拒绝、焦点、已删除目标的旧 AX action 与公开失败投影。30 次实际候选/重建样本的保留映射为小/中/大 `8/48/256`；计时为同进程 `MonoTime`，small/medium 全部为 0ms，large 最大 1ms，只能说明低于或接近时钟分辨率，绝不代表物理呈现延迟。
- 两个独立临时 bundle 曾观察到规则窗口首条、后续行滚动、公开编辑/应用回显，以及文档切换 owner 后 action ID 稳定、resource target 改到 `7102`。该次 CUA/UDS stdout 未在退出前持久化，socket 和 descriptor 也不恢复；因此这些观察不计作可复现的最终 GUI/UDS 验收，后续需用保存原始输出的新实例重做。
