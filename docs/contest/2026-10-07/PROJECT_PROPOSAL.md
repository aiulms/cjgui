# CJGUI 自选命题项目提案

作品名称：CJGUI

报名命题：CJGUI：面向人和 AI 共同构建与操作界面的仓颉自绘 GUI 框架

类别：自选命题；应用框架。版本：2026-10-07 macOS 开发预览。

## 选题价值和目标用户

CJGUI 面向用仓颉开发桌面应用、鸿蒙应用与 Agent 工具的开发者。我们希望开发者只维护一份业务数据与字段规则，人能在窗口里编辑，外部系统能在授权范围内读取和修改，修改以后人还能继续操作。

日常工具常常分别维护界面状态和自动化接口，新增一个操作要在两边重复定义，外部修改还可能覆盖正在编辑的内容。界面生成如果直接绕过业务逻辑，也会出现显示值、校验规则和真实数据不一致的问题。CJGUI 将共同操作、组件绑定和状态归属放入框架设计，减少应用自行拼接这些链路的工作。

初赛交付目标是可以从源码构建的开发预览：普通仓颉应用可以显示自绘窗口；同一份内容能够在人与外部客户端之间接续；生成区能够与手写区域共用字段和动作。当前公共接口仍为 experimental。

## 技术方案

应用以仓颉 controller 和业务域管理数据。组件树、布局、语义、生成结构和公开查询读取应用声明；原生画面与外部读回都是这些数据的投影。外部请求进入应用实际操作，经过授权、参数检查与版本检查以后修改业务状态。

macOS 通过窄 Objective-C 桥接接入 AppKit 窗口、系统文本服务和 Metal 绘制合成。业务规则、组件、布局、场景与共享协议主要由仓颉实现。鸿蒙已采用 ArkTS 薄宿主、XComponent 和 OH_Drawing 接入同类仓颉核心。我们没有将 Qt、SDL、GPUI、Flutter 或 Slint 引入 CJGUI 的构建和运行依赖；成熟框架源码用于研究算法、失效与资源生命周期的处理思路。

窗口和外部客户端共享资源、字段、动作及版本。私有 descriptor 提供本次连接凭据和授权入口；通用 Python 客户端动态发现应用能力。文本修改使用声明的 UTF-8 字节位置和预期文档版本，拒绝非法边界或过期请求。客户端的缓存是可丢弃读视图，不成为第二份业务数据。

生成区接收受限的结构描述，不执行任意代码。应用声明可用组件、字段、动作、样式和资源，生成控件仍交给这些业务处理器。结构校验、候选接纳和画面更新有明确阶段；失败保留既有界面。带稳定 key 的控件支持结构调整时接续草稿，手写区域和生成区域可同时存在。

框架通过排版缓存、纹理复用、按视口实例化的虚拟列表和有边界的工作调度降低重复工作。初赛材料不承诺所有操作达到 16 ms，也不以 GPU 完成回调证明物理呈现延迟。

## 初赛可核验的交付

1. macOS 正常应用 runner、可复用应用模板、自绘组件和布局。
2. 文档窗口与规则编辑器等普通消费者，示范界面编辑、授权外部读写和接续编辑。
3. 受约束的运行时生成面板、公共查询与提交入口，以及手写和生成界面共用字段的示例。
4. 通用共享操作客户端、仓颉业务域和传输协议、测试及失败处理。
5. 鸿蒙设置与温控应用的源码和既有模拟器证据；真机、发布审核与所有输入法边界另行验证。
6. 项目提案、查重说明、验证报告、演示视频、CHANGELOG 和统一作品提交模板。

实际命令、环境、测试数量、代码指纹和演示范围见同目录 VALIDATION.md。代码基线采用已提交源码与清单中补齐的原有源码文件；并行开发中的未提交实现不作为本次演示版本。

## 自选命题查重

我们核对了 Cangjie-TPC 和 cj-awesome 的公开项目入口、TPC 资源目录，并重点查看了 CJQT、CJQT6、three.cj、CangjieMagic 及相关 UI 项目的介绍。CJQT/CJQT6 提供 Qt 绑定；three.cj 面向 3D 引擎及配套子系统；CangjieMagic 提供 Agent 开发框架。CJGUI 与它们共享 GUI 或 AI 等领域，但核心交付定位是仓颉自绘组件与统一业务操作、受限生成界面和人机接续编辑的组合。

另外核对了 CUI/苍翠，其已具备声明式、自渲染、状态和组件等能力，因此我们不把“仓颉自绘 GUI”本身当作唯一创新。CJGUI 的区别需要由共同业务操作和生成绑定的实际代码与演示证明。详细来源、共同点、区别和核查范围见 DUPLICATION_CHECK.md。该核查是团队的选题判断，最终认定以赛事评审为准。

## 仓颉语言的应用

组件、业务域、协议与控制器采用类、接口、泛型集合和显式类型组织，复用同一套字段与动作声明。Option 和结果结构表达缺失、拒绝与失败，版本与位置单位作为契约传递。窄 FFI 用于系统窗口、绘制和文本服务，平台对象不直接成为应用公共接口。已有单元测试使用仓颉 unittest 与 testmacro。

平台代码不是零原生代码；当前路线是在适合仓颉的层面优先使用仓颉，并保留可解释、可测试的系统桥接。

## AI 辅助开发和生态贡献

我们使用 AI 辅助实现、查阅成熟方案、定位问题、设计反例和整理文档。人负责目标、取舍和验收范围；运行结果、源码与原始记录决定结论。普通 AI 辅助开发不作为独立加分依据。

本次申请的生态贡献是 CJGUI 通用共享操作工具和可复用接入示例：外部 Agent 或脚本可以动态发现应用资源与动作，经授权和版本检查进入真实业务操作。贡献包括仓颉服务端契约、通用 Python 客户端、多个普通消费者和测试。运行及复用说明见 AI_ECOSYSTEM_CONTRIBUTION.md。演示中的调用者是脚本客户端，不宣称为真实大模型自主操作；本项目目前也不把该协议称为 MCP。

## 后续计划与维护
