目标是交付一个普通 macOS CJGUI 应用作为通用原型宿主：模型通过现有公开能力发现和编辑入口生成/修改原型，人可以正常输入和操作；同一宿主支持不同领域的原型项目。视觉与交互以 Apple macOS HIG 及明确的官方样板为基准，组件和布局组织借鉴 ArkUI。通过三例独立 HTML 对照发现问题，用现有 `cjgui-app-dev` 技能记录和筛选，必要共同修复回到框架。

请按以下要求实施：

1. **保护现场并确定实际版本。** 先检查工作区和并行写集，复用合适 checkout，不覆盖其他任务修改，不切分支、不 stage/commit/push。按 AGENTS 检查空间与输出边界；同 target 的 build/test 串行。图工具按仓库规则先用，索引不足再以源码补证。

3. **先完成一个真实闭环，再扩展复用。** 固定方案三个案例的具体 HIG 参考与共同需求，先让设置表单完成打开、生成、输入、读回、修改、失败保旧、保存重开，同时形成 HTML 对照；然后在同一宿主中完成资产列表详情和素材卡片面板。内部小步不逐项停工请示。
4. **复用已有资产。** 使用公共 macOS host/runner、catalog/region、typed editor、UI document workspace、form/multi-object binding、generated collection、虚拟列表/卡片、主题角色与诊断。先核已有实现和正常调用方，缺生成接入就补接入，确有共同缺陷才修责任模块。不复制解释器、布局器、输入或提交状态机。
5. **补通用原型项目能力。** 原型字段、规则、数据、有限动作和资源来自项目声明；现有 `cjgui.ui-document` 继续负责 UI。支持正常新增字段、布局/主题编辑及换领域项目，不能每次改仓颉代码或重编/重启。项目载入和换属失败保旧，兼容修改保留有效草稿与交互状态；不兼容变化及旧事件明确处理。不能按三个案例名称硬编码整页。
6. **落成可复用的 HIG 主题和配方。** 同一主题角色供手写/生成消费，核正常、焦点、选中、悬停、禁用、错误与亮暗外观。复用当前布局，按方案补有界窗口适配。准确尺寸来自所选样板或明确的项目决定，不编造 Apple 官方 token；未做的高级效果注明差异。ArkUI/SwiftUI 等只作参考，不引入其运行时或依赖。
