## 交付目标

开发者用仓颉组件组合两个不同界面，自行安排布局、样式、字段与动作；框架从这些定义形成可绘制场景、输入目标和语义关系，状态改变后更新真实窗口。一个界面延续规则集编辑，另一个使用已有通知阈值领域并采用不同布局。调整页面结构不再要求修改 Objective-C 中的专用表单布局。

本阶段将组件、布局、场景、自绘输出、输入与共同操作接成一条实际可消费的框架主链。交付规模以两个真实消费者和共用实现验收，不按类型、helper、探针或内部工作包数量结束。
这不是重写整个成熟 GUI 引擎，也不扩展备份或通知产品业务；通知样例仅编辑配置，不发送通知。

## 连续完成以下工作

### 1. 仓颉组件与布局形成真实界面

提供当前两类消费者需要的组合能力：横向/纵向容器、文字、按钮、布尔编辑、单行文本/整数编辑，以及可滚动的列表或内容区。字段与业务校验由应用定义；组件名、具体类名、文件拆分由执行 AI 决定。
布局需要实际计算尺寸、位置、间距、内边距、固定/可扩展尺寸和裁剪，能响应窗口尺寸变化；样式至少支持文字/背景/边框颜色和必要尺寸。不要只保存 layoutMode/styleToken 字符串并输出摘要。
超过八个控件或字段仍可正常组合、滚动与操作；内部分块可以有界，不能把旧 native 的八个槽提升为公共数据上限。无需完整 CSS、通用约束求解器、动画或完整控件库。

### 2. 场景与自绘后端接通

仓颉侧生成具有稳定节点标识、几何、裁剪、绘制顺序和必要样式信息的场景/绘制列表，平台后端消费这些通用数据。应用字段名、页面标题、按钮排列和业务命令不再成为 native 专用分支。
在现有 Metal 基础上真正绘制由上述场景产生的矩形、背景/边框与裁剪内容，包含后续状态变化和 resize 的再次提交；清屏与首帧日志不能替代这项交付。
文字测量、字形/排版与输入法可以使用系统服务。选择清晰、可维护的文字绘制适配方式，记录文字是否进入 GPU 合成或仍采用同场景的平台绘制，不宣称完整字形引擎。无需自行编写完整光栅化或引入重型 GUI 依赖。
无桌面环境仍可完成布局、绘制命令生成、编译、参数/资源边界验证；最终真实 GPU 显示与读回在环境可用时验证。不能为锁屏另外发明一套虚假运行成功路径。

### 3. 同一布局驱动输入、焦点与无障碍

命中、滚动、焦点移动、文本编辑和控件动作消费相同的布局/节点标识。窗口事件带上实际对应的对象及足够的投影版本信息；列表重排、外部删除或选择变化后不能把排队输入重定向到另一对象。
保留 FIFO 顺序和已接受输入；明确焦点、应用、取消与关闭边界。完成本阶段需要的中文、粘贴、删除、组合字符选区和基础输入法组合处理。
原生层提供必要窗口、键鼠/文本、剪贴板与无障碍服务；避免为了某个自动化工具覆盖整页透明原生控件。无障碍节点的标签、值、屏幕坐标和动作也应对应同一实际布局。
区分模型读取/调用、辅助功能操作、真实鼠标键盘与直接领域测试，各自标明证据。CUA 能枚举但不能点击时，判断是框架暴露错误还是工具适配限制；不要反复猜 API 或把数据写入当窗口输入。

### 4. 组件结构同时提供共同操作语义

组件组合应复用已有资源/动作绑定，表达字段与标签、行与对象、分组与子项、当前选择和可用动作的关系，避免开发者为像素和语义各写一套无关页面。
继续由应用定义业务含义和权限，授权内允许批量操作屏幕外数据；语义关系不新增未经授权的动作。AI、脚本、模型平台均可使用，核心不要求聊天框或 Agent 身份。
区分业务版本与显示/布局进度：已应用结果不能声称已经呈现在用户眼前；无视觉依赖的批量操作无需逐条等待动画或重绘。保持局部查询与有界变化获取，悬停、滚动等不触发模型循环。
不强制本轮实现通用 UI 生成 DSL、所有协议、远程服务或分布式协同。

### 5. 迁移两个普通消费者并收口已有缺陷

规则集编辑器迁移到新组合能力，保留当前领域、文件与草稿语义；通知阈值消费者增加采用不同分组/布局的普通窗口入口，保持其不同字段与业务约束。不要只复制固定四字段表单或仅运行第二个无窗口进程来声称 UI 可复用。
使用普通包依赖构建；改变布局、字段顺序、分组、样式和动作绑定时，仅修改消费者的仓颉代码。至少一个页面超过八个控件，以真实布局和滚动处理。
上一里程碑相关输入、关闭、保存/重开、跨实例冲突和外部修改投影欠项合并到本阶段处理，不丢弃已有证据，也不为重复的专用旧表单继续扩业务。
保留原本可不启动外部连接的使用方式。窗口包与不依赖 renderer 的 core 消费者仍能分别使用。

### 复核发现与证据

| 发现 | 源码依据和实际影响 |
| --- | --- |
| 空容器尺寸递归 | [布局器](../../runtime/cjgui/src/composable_ui.cj)的 `preferredHeight` 对行列调用 `naturalHeight`，后者在无子节点时又调用前者。空的行/列作为子组件参与测量可无限递归；现有 19 节点探针没有这个用例 |
| 输入目标与编辑服务未贯通 | [native overlay](../../runtime/cjgui/native/cjgui_internal_renderer.m)只保存 `activeNodeIndex`；投影替换时没有按稳定对象协调输入代理的文本/选区/焦点。随后文本事件使用新的 scene version，旧代理内容可能落到新索引对象。焦点事件到 [窗口控制器](../../runtime/cjgui/src/composable_ui_window.cj)后，两个消费者也未完成共享焦点处理。选区/光标/组合态缺少对应可见绘制 |
| 队列和场景发布缺口 | native 入队保存数组 index 与当前 session version；仓颉每处理一个事件即重投影，并只接受最新版本，可能把同一旧画面已接受的后续输入静默丢弃。`configure` 先发布空数组，逐节点 setter 又更新正在展示/命中的数组，场景并非整批原子切换。两个消费者以算术拼接生成版本，resize 没有独立布局身份。需要真实序列复现，不用“有版本字段”代替正确性 |
| 滚动与文字呈现不完整 | native `scrollWheel` 只接受最上层命中为滚动容器的情况，指针在列表按钮上不会向父滚动容器转交。文本绘制只检查与 clip 相交，未设置文字裁剪；固定 `NSColor.labelColor`，仓颉 `textColor` 未穿过 ABI；文字测量仍是固定 80/22 等尺寸。现有 readback 只证明矩形样点 |
| 第二消费者没有完整共同编辑 | [通知窗口](../../runtime/cjgui/examples/notification_threshold_window_app/src/main.cj)把草稿存在 controller，外部 [context](../../runtime/cjgui/examples/notification_threshold_application/src/notification_threshold_editing.cj)只返回已应用配置。人的旧草稿通过 `configureFromHuman` 使用调用当时的最新版本，可能覆盖 AI 在编辑期间刚提交的值。通知 changes 的实例身份仍是常量。组件树展平后也没有把分组/字段/选择关系接到公开上下文；AX 列表不能替代这一能力 |
| 保存验证范围应缩小陈述 | [保存测试](../../runtime/cjgui/examples/rule_set_application/src/rule_set_editing_test.cj)使用两个领域对象、人工创建租约目录，再顺序保存；有价值，但并非两个进程真实竞争。目录租约异常退出后的遗留及错误分类仍需验证。保持本阶段的真实双实例要求，不扩建存储产品 |

### 交付场景与连续工作范围

本轮完整结果是：**人能连续编辑一个自绘窗口，AI 能理解对应结构和当前编辑内容，双方在同一份工作上交替修改，开发者能把这条能力复用到另一个不同窗口。** 以下工作连续完成，修一个 bug、过一个 probe 或提交一段进展都不是交付终点。

**1. 让基础组件能够正常持续使用。**
完成行列/空容器/动态子节点的布局，文字的必要测量、样式和裁剪，以及 resize、固定/扩展尺寸和滚动内容的正常行为。补齐当前按钮、布尔、单行文本/整数组件需要的焦点、可用/只读状态与可见反馈；不把可用、可见、授权合为一个概念。滚轮能从列表项走到所属滚动区域。重复/无效节点身份或容量边界给出可解释结果，不能普通空内容就崩溃。
完成基本的键盘焦点移动、编辑位置与选区、复制/粘贴/删除、组合字符和基础 macOS IME 的输入/显示/候选位置协同。系统文本服务可以复用，领域草稿和组件编辑反馈需有清楚分工；禁止为了 CUA 便利新增逐控件透明原生表单。范围是当前单行编辑体验，不要求富文本、全套输入法、完整主题库或 GPU 字形光栅化。

**2. 让场景发布与输入时序可靠，并保持轻量。**
场景先完整构建/校验，再在正确线程一次切换可渲染、命中和语义快照；不要逐个 setter 暴露中间场景。事件关联原始稳定节点、业务绑定和必要版本，不能用“现数组第几个”冒充稳定目标。框架管理清晰的布局/投影身份，不让应用靠版本乘法拼接正确性。
“输入后立即应用/切换”“外部修改无关字段”“外部删除/换选择后继续敲键”等序列，要么正确应用于原对象，要么明确处理失效输入并保留可恢复内容；不能静默丢失、复活旧文本或写到另一对象。队列满也要保留已接收输入并有实际可观察结果。不能仅把所有旧版本事件拒绝掉就宣称通过。
区分数据提交、场景提交与平台可确认的呈现进度。无视觉依赖的批量业务修改不逐条等画面；依赖当前画面的动作不能把尚未呈现当已经呈现。正常编辑不每次同步 GPU readback；避免逐节点重建完整 AX 数组、无改动查询触发整树提交等明显成本。用代表性节点数量/提交次数/耗时作一次必要观察，不造通用性能平台或新审计链。

**3. 接通组件关系与当前编辑内容的外部理解。**
从同一份组件声明/绑定提供最小必要的窗口、分组、控件、对象/字段、标签、当前选择、草稿、相关动作和显示进度关系。只扩展实际使用需要的查询/投影，不建设第二份可写语义数据库或通用对象平台。
接入已有 core、descriptor、client 和应用操作，应用业务含义定义一次；外部调用按授权查询相关上下文，不每次输出全部内容，不要求通过 AX 或截图定位字段。可见关系和屏幕外对象数据分别表达，授权内的屏外操作继续直接执行。无 renderer 的消费者保持可用；纯 UI 使用也不强制启用连接或模型。

**4. 用两个普通消费者完成共同编辑与接手。**
继续使用规则集和通知阈值的不同领域/布局，不增加备份执行或实际通知业务。通知样例把当前草稿和必要基线交给可被双方读取/操作的明确应用模块，外部写入后旧草稿不能套用最新版本静默覆盖；优先复用已有字段/草稿契约和业务边界，避免把规则集领域硬塞进 core。
至少跑通：人在窗口形成草稿 → 外部从真实上下文发现对应字段与草稿 → 在已有授权下修改相关内容 → 人在窗口看到结果并继续编辑/应用；同字段真实冲突可解释，无关字段修改保留人的工作。外部无需截图/坐标，人的窗口不依赖模型才能操作。保留含 100 条以上对象的屏外批量操作与可见滚动对应结果。
规则集既有保存/另存为/重开、撤销/重做和关闭决策按最终窗口代码完成使用周期；补真实双进程竞争保存和异常退出后的租约行为。正常失败不得破坏已保存文件，不自动清理不明实例锁；区分协作应用互斥与不合作的第三方文件写入边界。通知实例/文档变化游标也应避免重启后误报无变化。

**5. 完成与场景对应的验证和开发者交付。**
针对上述可达缺陷先有失败复现，再验证实际修复；无需为每个低风险 helper 写镜像测试。至少覆盖空/动态布局、文字裁剪和颜色、真实滚轮路由、焦点和队列边界、场景发布期间输入、草稿并发、上下文关系和游标、双进程文件写入。探针直接调 ABI、普通消费者、真实系统键鼠/IME 和真实 Agent 的结果分别标记。
两个普通 bundle 在最终源码上构建；有桌面时用正常入口做连续编辑、外部接手和资源关闭验证。独立 Agent 只得到当前真实 descriptor、通用客户端/使用说明和自然语言目标，自己发现关系/草稿/可用动作，不能预先硬编码成一串业务请求。它只做验收，不再派生开发任务。使用已有允许的 Luna/Terra 验收能力，不替换执行任务模型。
按 AGENTS.md 完成相关 core/领域/进程/native 验证、`cjpm build --skip-script`、公开声明与受保护路径检查、`git diff --check`。检查 public/native/FFI 影响；图工具不覆盖时直接分析源码和消费者，不为了获得一个图结果停工。
开发者入口保留 experimental：说明如何组合/改样式、绑定共享编辑、选择是否启用连接、遇到冲突或无效结构如何排查。重要资产替换时同步设计导航；当前状态只在 ACTIVE_DIRECTION 维护，旧阶段结果按原范围引用，不继续叠加多个“本阶段”。

**指导结论：仍为部分完成，继续现有大阶段；“除 IME 外全部完成”的结论不予采用。** 本次未重跑构建或桌面，只核对代码、测试入口和报告。保存测试现在确实启动两个 OS 进程，通知草稿也由领域管理；这些进展保留。CodeLattice 对新关系类返回 stale_baseline/matchCount=0，不能作为低风险或覆盖证明，以下依据直接源码。

**主要偏差是同一组件定义尚未形成共同入口。** 通知领域的 `contextSnapshot` 手写 `notificationWindow/channelCard/thresholdCard` 等关系，规则领域也手写 `ruleSetWindow/ruleDetail/ruleDraftApply`；实际组件则在各自窗口的 `buildUi` 另行定义，nodeId/semanticId 也并非这些关系的统一身份。当前测试只检查这些字符串存在。因此移动或改名一个分组会使外部关系过期，无 renderer 的领域消费者也输出一个并不存在的运行中窗口。这不是从组件绑定生成关系的实现。

#### 完整交付做法

保持原来的五个工作范围，优先把下列同一条链路真正接通；无需再复制任务清单或申请新批准。

1. **组件声明只写一次。** 应用领域定义真实资源、字段、动作、草稿与规则；应用的组件树引用这些绑定。框架从实际组件树/布局快照自动派生窗口、分组、控件和对应绑定。领域不硬编码某个窗口的组名或排布。保留只读值契约与可选投影提供入口，具体类型和文件拆分由执行 AI 决定；无需第二数据库、通用对象服务或新 Agent 层。
2. **普通调用能读到实际窗口上下文。** 将可选窗口投影接到既有连接/客户端，查询的节点能与当前组件、字段和实际操作确定对应。无窗口时业务上下文仍可使用，窗口投影为空或明确不存在；不能把界面蓝图声称为正在显示的窗口。必要局部焦点/选区由交互模块拥有，按需读取，不为每次移动调用模型。资源、窗口、控件关系同时遵守已有授权和查询范围；可读的屏外业务对象不因没渲染而禁用。投影消失、节点移除、窗口关闭都有正确生命周期结果。
3. **版本和操作与这份上下文对应。** 数据提交、场景提交、平台可确认呈现分别表达；实现没有的平台确认就诚实返回 pending/unavailable，不把 `DISPLAYS resource` 关系当“人已看见”的证明。继续验证有界队列、原始业务绑定和草稿版本。业务层的“编辑 A 后应用 A”单测不能替代实际窗口控制器的“编辑→立即应用/换选/删除”序列；该路径需要用真实 controller 和 native 事件入口验收。关闭/恢复动作不符的现象以当前构建复现定位或保留原因未定。

#### 必须通过的消费场景

- 只改普通消费者里的组件排列或条件结构（例如将阈值字段移到另一组，再移除/新增一个控件），不改领域里的关系表、不改 native、不改通用客户端；外部查询和实际组件/窗口都跟随改变，旧节点不残留。至少两个不同领域消费者使用同一投影机制。
- 一个消费者只启动 core，读回业务/草稿，但没有虚构活动窗口；窗口消费者启用可选投影时，实际 nodeId、字段/资源目标、当前草稿与动作参数能够互相定位。不能在测试中另造一份“预期窗口树”供实现读取。
- 有限资源授权和显式 targets 查询不会通过关系泄露被排除对象；授权内的屏外批量操作仍走原领域。人移动焦点/选区后按需查询，外部能取得当前交互范围；外部修改后数据版本和显示进度能解释当前是否已经呈现。
- 两个正常窗口的连续编辑和接手仍要通过；最终使用当前通用入口验证，从外部关系发现并编辑当前草稿，不由验收脚本把控件到业务目标的映射硬编码出来。

实际字形测量与更完整字体能力仍可作为后续明确能力，当前 13pt 估计保持标注；但当前单行输入使用的字体、文字原点、选区/光标和系统编辑服务必须对应，不能以“只是估计”掩盖文本交互错位。不要扩成字体引擎或多平台工作。

`cjpm test` 链接失败属于可推进的本地工程工作：定位并修正相关测试链接或提供可直接覆盖组合/窗口控制器的正常测试入口，必要时按授权最小调整 cjpm 配置；不能长期用无关领域测试替代。对本机真实构建约束先查已有反馈记录，新的 sidecar 链接问题不可无依据归为旧 SDK 上游 issue。已通过且未受影响的进程保存和旧领域用例不必为每个内部步骤重跑。

### 2026-09-12 文本与选择接续

### 2026-09-12 文本与选择接续执行回报

**根因与修复。** 生产 `NSTextView` 的 `textDidChange:` 已经把每个值排入
composable FIFO，`pump_event` 也把它交给仓颉；实际窗口中仍出现领域收到空字符串。
有限诊断确定断点是跨主线程 foreign call 返回了 `NSString.UTF8String` 的借用指针：
第一个焦点值可转换，后续文本在 `CString.toString()` 时为空。native session 现保留每个
pumped 值的 NUL 终止 UTF-8 `NSData` 副本，bridge 返回该会话持有的字节；不再跨线程
借用 NSString 内部缓存。临时诊断已经移除。

`textViewDidChangeSelection:` 现排入 event 33。`CjguiComposableUiWindow` 只将它写入
focused control/selection projection，不调用 controller、领域操作或场景重建。event 33
因此能在纯移动插入点或选择范围后被外部查询，同时不把平台交互状态伪装成业务版本。
`WINDOW_NATIVE_SUBMISSION_VERSION -1` 继续表示 native 尚未提供该读数，不表示已提交。

**新增正常入口与实测。** `verify_composable_ui_appkit_text.sh` 编译 production renderer
和 production Cangjie window，测试专用入口只驱动同一 `NSTextView` 的真实编辑委托及
overlay press；同一 FIFO batch 中的 `邮件-kbd` 文本先于 Apply 抵达 controller，随后
selection-only 事件只更新投影。既有直接 FIFO probe 仍通过，范围不再被误说成上游
AppKit 证据。

最终源码上，通知窗口实际键入 `邮件-kbd`，外部 `get` 读回 UTF-8 draft、版本和
`delivery-channel 6 6`；外部 `EDIT_DRAFT_TEXT` 改为 `外部-管道` 后窗口刷新，人继续
