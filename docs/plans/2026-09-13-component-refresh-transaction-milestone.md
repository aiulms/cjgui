# 大阶段：组件刷新的一致提交与失败恢复

2026-09-13，原执行任务Terra/xhigh，原目录。目标是动态应用无需自行协调组件注册、scene提交与命令替换，成功时同步生效，失败时保留可用界面和对应身份/动作。

## 接续判断

接受前阶段组件身份、绑定替换、独立消费、同窗30轮和idle恢复、公开GET标识修复与42/42 core的已验范围。规则集最终源码bundle已构建签名，但最后一次修复后未重跑规则实窗，不能沿用更早实例为最新运行证据；用户同bundleId应用运行中，避免干扰其未保存工作。

当前源码风险：registry.use立即加入实例，finish即销毁未声明项且即使issue存在仍继续销毁；消费者在buildUi调用finish，窗口尚未接受scene。adaptive主循环又在pump后单独replaceCommands并忽略结果。因此失败可能先改变实例生命周期，或新scene与旧命令暂不同步。先确定性复现，不把静态推断先写成已发生。

六主线取舍：已有布局/渲染/资源/文字与公开操作基础，组件组合仍需应用手动协调失败恢复，优先把这些能力接入可靠的框架刷新。保留GPU自绘、仓颉owner、窄native和外部可选接口，不新增另一状态机或Agent。下一候选为正常应用交互与系统输入验收；长文本尾部、历史Escape未定位不要求清零。

复用DESIGN_INTENT_INDEX的组件、窗口/scheduler、normal Host及现有native staging/失败恢复。历史避坑的布局双真相、重入/生命周期与过早API固化必须落实：候选投影可丢弃，内容owner不由失败的渲染反向回滚，原生对象不公开。

## 完整实现与消费

1. 确定性复现：旧界面A/B都可用，候选删除A或重挂B后，分别触发duplicate key、测量/布局失败、部分native setter失败、present未接受。验证旧组件句柄isLive、旧scene、焦点、命令目标与AX一致；重试同一候选不能反复生成新身份或遗留注册。故障通过既有测试注入或有界测试入口，不污染公共业务API。
2. 引入最小仓颉构建/提交批次或等效机制，将组件候选身份与声明命令绑定到一次scene刷新。准备/校验不销毁已提交实例，真正接受时统一更新；失败撤销候选资源与未生效绑定。成功销毁旧实例只一次，陈旧native输入/AX不能写新实例。复用现有accepted/submitted/nativeInputScene与recoverable failure规则，不把GPU完成等同接受，也不在已提交GPU后误回滚内容owner。说明不可逆边界与失败后的实际行为。
3. 提供公开可消费的controller/host接入，应用声明UI、实例key和命令即可，不在每轮pump后无条件replace。支持绑定无变化不重做、binding失败保留旧有效集、空组件集合/临时retain/销毁重挂。保留旧低层API兼容，不新增必须遵守的复杂执行卡或两套业务树；普通无外部连接应用同样可用。
4. 两种真实消费者迁移到同一流程，至少一个有多个编辑/动作组件的动态删除重排。独立Luna/Terra只按公开文档创建或迁移组件消费，实际运行、更新/失败恢复/命令/owner读回，记录去掉的应用协调步骤和剩余限制。不只是框架probe。
5. 同一正常窗口反复成功/失败/重试、组件增删与外部owner更新交错（至少30轮），记录身份/绑定/队列/资源上限、端到端与build/layout/submit、idle恢复CPU/RSS；失败重试不能变成盲目刷新循环，未变UI不重复构建/绑定。与现有安全完整刷新对照验证结果一致，不仅看减少setter。
