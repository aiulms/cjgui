# CJGUI 架构契约：共同状态、界面与外部接入

更新：2026-09-19。本文件集中维护运行结构、状态归属、共同定义和生成式接入契约；保留原文件路径以兼容已有链接。项目目标见[项目方向](GUI_PROJECT_DIRECTION.md)，验收见[验收标准](CJGUI_UI_FRAMEWORK_COMPLETENESS_CRITERIA.md)，实现程度与当前任务只见[当前状态](../../runtime/cjgui/ACTIVE_DIRECTION.md)。下述架构包含待实现的目标，不代表全部能力已经运行。

## 总体结构与职责

人通过可视组件参与，外部系统通过共同定义和公开调用参与；界面实例可以手写、运行时生成或混合。各入口复用下列职责，不为 AI 再建立一套业务或渲染运行时。

| 部分 | 持有或处理什么 | 边界 |
| --- | --- | --- |
| 应用业务与编辑模块 | 真实内容、生效值、草稿、业务规则、相关版本及授权执行 | 界面和外部请求都调用这里；可按业务拆分，不要求全局 store |
| 共同定义与绑定 | 字段/动作身份、类型、规则引用、参数、读取与修改入口 | 手写绑定、外部描述和生成式绑定由同一来源派生；投影不是第二份可写真相 |
| 界面定义与组件实例 | 手写或已接受的生成结构，结构版本、稳定身份，以及归属明确的焦点/选区/视口状态 | 界面结构与业务内容分开持有；候选失败不得提前替换已接受绑定、清草稿或销毁旧实例 |
| 仓颉布局、场景与调度 | 组件组织、测量布局、场景候选提交、输入分发、失效和资源使用 | 绘制、命中和语义使用一致的已接受布局/身份；高频视觉更新不承担模型往返 |
| 窄平台桥接与自绘后端 | 系统窗口/事件/文字与输入法服务、GPU 资源和场景合成 | 当前 macOS 使用 AppKit/Metal；原生层不持业务规则，原生句柄不泄漏成公共业务接口 |
| 外部连接适配 | 按授权查询定义/状态，提交业务动作或界面结构，返回结果和变化 | 编码与传输可替换；按平台要求调度到已有执行路径，不从连接线程直接改视图 |

内容更新路径：人类输入或外部动作 → 同一业务/编辑操作与校验 → 状态更新 → 组件/语义投影 → 布局与自绘反馈。结构更新路径：手写组合或外部结构描述 → 校验与绑定解析 → 现有组件及候选场景提交；提交结构本身不隐含执行业务动作。生成式具体事务见下文，系统输入瞬态与业务草稿按各自归属协调，不把原生编辑缓冲当永久业务 owner。

## 用一个场景理解

人选中一段文章，外部系统能直接读到这段内容及选择范围，提交修改，人在正文看到结果；人再编辑，外部系统随后能获取更新。
交流可以发生在外部助手、应用批注、聊天栏或其他入口，均由应用开发者决定。
CJGUI 提供对应内容与动作的能力，不内置固定聊天产品或 Agent 运行时。

## 最小共同模型

先明确以下信息，不提前锁定类名、DSL 或序列化格式：

| 信息 | 含义 |
| --- | --- |
| 对象身份 | 内容、控件与业务对象之间的稳定关联，避免依赖坐标或显示文案寻址 |
| 当前内容与版本 | 调用方读取的是什么，执行时是否仍有效 |
| 交互上下文 | 当前文档/窗口、选择、筛选、草稿及其作用范围 |
| 可用操作 | 操作含义、参数、目标范围、授权与业务前提 |
| 操作结果 | 实际改变了什么、失败原因、新的版本 |
| 变化获取 | 人或其他调用方改动后，可按需获取相关更新 |

这些信息可以很小。不是要求先实现通用对象数据库、完整语义树或分布式协作平台。
基础控件从首次真实使用起，同时提供显示、语义和动作绑定；业务含义由应用定义一次并复用。
读取必须涵盖应用实际编辑状态，不能只读磁盘上的旧文件来冒充人当前看到的内容。

## 共同信息只定义一次

共同的业务信息由应用定义一次，框架据此提供手写界面绑定、AI 能力查询和运行时生成界面的接入。开发者补充框架无法推断的业务含义；布局和呈现方式可以独立变化。这是首选架构原则，具体 API 仍以接入成本、正确性、性能和不同应用的复用来检验，不预先锁定编码或另造配置语言。

以“保留天数”为例，共同定义包含稳定字段身份、名称、整数类型、单位“天”、范围规则、当前备份规则的取值/草稿入口，以及修改/应用动作。手写界面只引用字段；AI 查询从同一处得到类型、规则和操作；AI 生成面板也引用同一字段和动作。框架连接当前数据、输入、错误反馈与变更通知，应用无需为三种使用方式分别维护业务接线。

| 信息 | 由谁提供 | 如何使用 |
| --- | --- | --- |
| 共同定义 | 应用的类型、字段/动作声明及共享规则来源 | 稳定身份、标签、单位、类型、范围、参数和绑定关系由框架派生为界面与外部描述 |
| 当前数据与编辑状态 | 原业务/编辑 owner | 按对象身份读取当前生效值、草稿、版本与错误；不复制到可独立写入的 AI 数据镜像 |
| 当前操作条件 | 原业务规则结合当前上下文计算 | 按授权查询当前是否可执行及原因；真正操作时重验，查询结果不是永久执行许可 |
| 界面组织 | 开发者或外部生成方 | 选择组件、布局、样式和展示范围，引用共同字段/动作，不重新定义业务限制 |

规则共用必须落实到执行：若范围从1～365改为1～730，字段描述、默认控件约束与最终业务校验均消费同一规则来源，不能在声明与修改函数里各手写一个上限。复杂的“备份进行中不可修改”等条件可以保留为仓颉业务代码，由同一规则入口提供可执行性与机器可识别的原因；不要求把所有业务程序翻译成描述语言，也不能仅生成说明却另写一套执行逻辑。

定义及规则变化须有可识别的版本/失效机制，让界面和外部调用方重新获取适用约束；读取应携带对应定义及状态的版本信息，不拼接互不一致的旧缓存。最终写入仍检查当前条件与相关版本。更改静态代码中的定义按正常构建流程生效；运行期可变定义按已实现的更新机制生效，不将“一处修改”误写成旧进程或远端缓存无条件立即更新。

草稿与生效值分开。把365改成30时，空字符串可以是合法的编辑中状态，最终应用才要求得到满足范围的整数。界面和 AI 通过同一编辑入口更新草稿；“修改草稿”“应用”“取消”必须明确，布局更新不得暗中提交或清空草稿。即时生效的字段也须由应用显式说明其策略，不能让不同入口默认采用不同语义。

框架可依据整数类型提供默认数字输入，开发者或 AI 可选择兼容的滑块、预设选项等呈现；它们保持同一绑定与业务约束。整数类型无法推断单位、业务意义或执行条件。字段机制只是表单切入点；画布等能力可用对象关系与动作契约表达，不把框架固定成自动表单产品。

共同定义优先复用仓颉类型、注册代码和现有业务入口；面向连接层的 schema/描述由框架派生，避免要求开发者再手写 UI、AI、校验三份说明。读侧投影与缓存可存在，但来源、版本和失效必须明确。新增字段仍需实现它本身的业务行为，并为不同界面选择放置位置；应省去的是重复绑定、重复规则和 AI 专用接线，不能把“定义一次”宣传成无需业务开发。

当前字段描述/表单绑定仅是部分基础，不代表完整规则派生、可执行性查询和生成式接入已实现。具体验收见[共同定义的接入成本验收](CJGUI_UI_FRAMEWORK_COMPLETENESS_CRITERIA.md#共同定义的接入成本验收)。

## 状态、画面与动作

应用业务模块持有真实内容与规则；组件可持有选择、焦点、滚动等局部状态。
界面与语义描述从这些已归属的状态产生，不另建可独立写入的语义数据库。
人类输入和外部结构化请求最终调用相同的业务动作。外部调用不必合成鼠标事件。
动作链要真正执行、更新状态和反馈结果；只计算 allowed/readiness 等摘要不算操作已经完成。
后台外部请求需按平台要求进入应用执行线程，不能直接从任意线程修改视图或原生对象。

## 权限与可见性分别处理

已有有效授权覆盖操作目标与参数时，允许直接完成批量操作，包括屏幕外对象。
弹窗、AI 身份、没有滚动到目标位置，都不单独构成重复确认条件。
授权撤销、未覆盖的目标、缺少必要信息、业务约束和实际状态冲突仍由应用处理。
如果弹窗只是等待一项已被有效授权的确认，可复用该授权；如果等待的是缺失输入，则不能猜造答案。

按动作性质检查：
- 对象操作，如改记录、填字段：检查授权、业务条件、目标有效性与相关版本。
- 视觉操作，如拖动、坐标点击：还需正确布局、位置、遮挡与生命周期信息。
- 不能把 enabled、visible、authorized、业务可执行等概念合并成一个 Bool。

## 快速操作与显示同步

内容已提交和画面已显示是两件事，应能报告各自的进度。
没有视觉依赖的对象操作无需逐次等动画结束，可批量执行后按需重绘。
依赖位置或要求用户看见结果的步骤，要等待相应画面真正更新；不能把旧画面当新结果。
版本过期时拒绝、重读或显式合并；不得悄悄覆盖用户的新修改。
第一阶段可用简单顺序执行和相关版本检查，暂不要求通用事务系统或多人实时合并算法。
撤回行为由应用动作明确支持；不得假设所有外部副作用都能撤销。

## 上下文与变化成本

按当前窗口、选区或明确查询范围返回相关信息，避免每次输出整个界面树与全部内容。
局部高频状态仍在组件内；必要时提供快照、查询或合并后的变化通知。
同步状态不等于每次击键都调用模型。何时调用模型由应用/外部系统决定。
外部端可以使用查询、变化订阅或两者组合，具体方法在真实消费中选择。

## 框架与连接层

框架提供可读取、可操作、可获知结果的接口；适配层选择进程内调用、进程间连接和具体编码。
第一阶段选一条实际可用的外部连接即可，不能先实现所有协议、所有模型的统一网关。
Agent、模型平台、脚本和其他应用都可成为调用方，不在核心接口要求某种 Agent 身份。
外部系统操作应用，与应用主动发消息给外部系统的对话会话，是不同能力。
聊天 UI 可作为以后独立组件；连接哪个会话、如何管理模型与历史，不进入框架默认运行路径。
S 表达式和 JSON 等是可替换候选，比较方式见 [协议实验](AI_ACTION_PROTOCOL_EXPERIMENT.md)。

## 运行时生成与修改界面

这是框架的建设方向，应用可按需启用；不是强制对话窗或 Agent runtime。开发者可以写固定界面，也可以只规定组件、数据和动作的能力边界，让外部系统生成界面实例，或在手写外壳中开放可生成区域。

同等开发权与数据权按相同角色/授权解释，不以人或 AI 的身份划出不同等级。能力注册服务于共同的类型、绑定和业务边界，不能长期把 AI 限制为只选预设模板或只能操作少数按钮。应用新增自定义组件/字段/动作时，应有复用同一描述与绑定的扩展路径，避免再维护一套 AI 专用业务接线；代码开发与运行时组合都向 AI 开放，但任意新底层实现仍按其实际编译/部署方式交付，不冒充运行时已有组件。

例如：规则编辑器保留开发者编写的导航。人选中一批记录，外部系统读取应用允许的字段和动作，在运行中的窗口里生成一个包含名称、启用状态和应用按钮的编辑面板。人修改尚未提交的名称；外部系统重新排列面板、添加说明时，草稿和焦点仍对应原字段。按钮调用原业务动作；人继续编辑，外部端读取到具体结果。只切换预先写好的两套页面，不足以证明生成能力。

能力契约先于编码，至少覆盖：

| 契约 | 责任与边界 |
| --- | --- |
| 可用能力 | 应用注册共同的组件及有类型的属性、可绑定字段、动作和参数；外部可按授权查询与扩展消费，不设 AI 专属低配集合。当前尚未提供或无权使用的能力明确说明，不能从生成内容获得额外权限 |
| 界面结构 | 受限组件树、稳定 key、层级、布局/样式、资源引用、字段绑定与事件到动作的映射；编码可替换，不能传原生指针、任意回调或待执行源码 |
| 状态归属 | 一个界面定义持有者负责已接受的结构及版本，组件实例持有局部交互状态；业务字段、草稿和校验仍由原 owner 持有。绑定是引用，不能复制为可独立写入的业务镜像 |
| 版本与结果 | 界面结构版本与业务内容版本分别检查；返回接受/拒绝、具体位置与原因、已接受结构版本，按需读取真实当前结构与绑定。结构更新不得顺便执行按钮或隐含提交草稿 |
| 更新与失败 | 校验完整候选后复用既有场景 prepare/commit/rollback 路径；结构、实例身份、绑定及事件路由保持一致。非法结构或渲染提交失败保留上一份可交互界面；接受场景不等于已经物理呈现 |
| 编辑接续 | 稳定组件及同一字段重排时保留草稿、选区和焦点；删除、换绑、禁用、类型变化与组合输入须有明确拒绝/取消策略，不把旧输入投给新对象。必要时拒绝会丢草稿的更新，而非暗中丢弃 |
| 成本与回收 | 限制描述大小、深度、节点、属性和资源；无变化不重建，局部更新不无故重建全部结构。移除实例与资源应释放；悬停、光标与每次击键不触发模型或重新解析描述 |

实现路径应为：外部结构描述 → 受限校验与绑定解析 → 现有仓颉组件 → 现有布局/场景/自绘；交互仍回到同一业务 owner。无需让 AI 为每次生成界面重编译应用，也不为生成能力重造控件库。旧生成 demo 仅提供实验参考，不能凭名称认定此链路已通。

生成式验收须同时覆盖运行中新增结构、后续结构修改、真实字段编辑与外部读回、失败保持旧界面和第二个公共消费者。脚本提交描述与真实模型生成分开记录；没有实际模型参与，不声明“真实 AI 生成已验证”。具体检查见[框架验收](CJGUI_UI_FRAMEWORK_COMPLETENESS_CRITERIA.md#运行时生成式界面验收)。

## 实施顺序

从正常窗口中的少量控件开始，一起实现人类交互与最小外部操作契约。
显示、输入和语义应在同一个可用阶段汇合；不再要求先造完整传统 GUI 才准验证外部交互。
完整文本编辑、IME、无障碍、画布和多平台按真实需求逐阶段增加。运行时界面生成应在已有少量可组合控件与正常窗口后尽早闭环，不等传统控件库全部完成；当前阶段及接续顺序由 ACTIVE 指定。
最低验收见 [框架验收标准](CJGUI_UI_FRAMEWORK_COMPLETENESS_CRITERIA.md)。
