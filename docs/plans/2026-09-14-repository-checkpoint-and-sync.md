# 优先阶段：仓库提交、主分支同步与开发接续

2026-09-14 用户明确要求：先合并分支并提交远端，做完回到主线。本次授权覆盖必要暂存、提交、安全合并/快进、切换本地 main 与推送 `origin/main`，优先于此前“未经用户要求不提交”及旧阶段“不切分支、不提交推送”的约束。它是当前成果的一次同步，不是后续每个开发阶段的永久自动发布授权；不打发布 tag、不安装/公证/发布产品。

## 目标与现场

指导只读初查：当前分支 `codex/cjgui-internal-renderer-slice` 与本地 `main` 同为 `827acdf`，本地 main 按现有远端跟踪记录领先 `origin/main` 一次提交；origin 为 `https://gitcode.com/aiulms/cjgui.git`。这些是检查时的本地状态，执行须 fetch 后确认。若远端未分叉，当前成果提交后把 main 快进到它即可，无需制造多余 merge commit。

本轮同时交付：可审阅且可重新构建的 CJGUI 源码/文档提交、远端实际指向该提交的证据、未提交残留说明，以及恢复[动态复合组件阶段](2026-09-14-dynamic-component-composition-milestone.md)的准确入口。提交不代表历史未验项目完成；不要为了把状态写成绿色展开无关修复。

## 执行顺序

1. **单一写入与完整保存。** Terra协调现有Luna到安全边界，记录当前新阶段哪些改动已落地、哪些未闭合，暂停并发源码/文档/构建产物写入后再确定提交集。不得在暂存与验证后继续混入另一个模型的新改动。已形成完整、可验证单元的新阶段修复可纳入；不把半个事务/API迁移硬塞进可用基线，不回退或删除现有工作。若确有无法安全分开的部分，先完成最小必要衔接或带精确写集向指导升级，继续可独立的整理。
2. **核对全部成果。** 盘点 tracked/untracked、分支/远端、现有忽略规则和文件大小。此次范围包含此前多轮尚未入库的仓颉核心、自绘/native桥接、公共API、正常应用消费、模板、资源、测试/脚本、方向治理调整、必要历史归档与可公开证据。不要只提交最后一轮，否则新框架无法从远端重建。将自动生成包、target、动态库/二进制、缓存、__pycache__、临时独立消费目录和本地会话文件与真正源码区分；preview目录按实际生成/源码归属判断，不凭名字整删。必要时最小补充 .gitignore，保持本地可用且不删除文件。明确清单暂存，禁止盲目 git add -A。
3. **核对公开内容。** 提交的日志与证据须可公开：排除真实密码/token、活跃capability/descriptor、私人正文/机器会话数据及无关大产物。用文件名和命中类别报告问题，不把秘密打印进输出；只对待提交副本/可公开证据整理，原始本地证据按需要保留。源码fixture中的明确无效测试凭据与真实授权材料区分。保留失败/未验标签，不伪造原始stdout。文档中的本机证据路径可如实标本机取证，不能伪称远端可下载；新必要说明提供可重现入口。
4. **提交候选验证。** 检查暂存差异、声明/FFI影响和配置/路径完整性；根build与本次实际变动相关回归串行运行一次，已有可信当前证据可以复用，不重复全仓重测。最终正式导出/含空格独立消费若仍未做，完成一次以验证提交集含必要源文件，核对所有实际消费输入都在提交或明确可重建来源；若被新开发不完整状态阻塞，先闭合必要衔接。系统IME/物理输入/呈现等旧未验不要求为提交全部清零，不用旧报告替代当前源码构建。git diff --cached --check及本地文档链接/生成依赖检查通过；不要默认跳过真实hook，也不要机械恢复退役的审计链，冲突按AGENTS处理。
5. **提交与同步。** 可按真正可审阅的源码/文档边界做少量连贯commit，不逐文件切片；保留既有本地提交历史。fetch origin，确认远端main最新状态。先提交当前分支的完整候选，再在所有执行者暂停写入的条件下将main快进；如存在真实远端分叉，以不丢双方历史的正常合并处理，冲突解决后补相关验证。不得force push、reset、clean、删除分支、覆盖未知改动或绕过远端保护。普通推送 `origin main`；若保护要求PR或身份认证受限，保留已完成本地提交，准确报告服务器原因与可行入口，不循环重试或声称同步成功。
6. **读回并自动接续。** 对比最终本地main、origin/main与真实远端ref的hash，报告提交hash、推送目标、验证范围、未暂存/忽略残留及未验边界。只做到本地commit不算推送完成。成功后继续在同一目录、本地main恢复动态复合组件阶段，默认又回到无新用户授权不自动提交推送的规则；不新建worktree，不删除原分支。ACTIVE先写清本次同步结果，再把动态复合组件恢复为唯一当前开发任务。给指导发送同步完成报告后直接继续，不等待下一个30分钟提醒。

## 分工

Terra负责当前写入协调、提交集/依赖完整性、分支冲突与最终Git操作。可复用Luna做边界明确的只读文件归属/日志整理检查，但不能两人同时改同文件、操作index或同target构建。无需额外执行卡或定时任务。指导负责关键取舍和完成复核，不进入开发。按AGENTS保护用户应用，任务内复用验证实例、整轮结束回收自有临时实例，保留必要日志。
