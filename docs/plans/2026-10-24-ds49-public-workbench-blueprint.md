# DS49 施工图：公共多对象接入与可持续使用的界面文档工作台

日期：2026-10-24。本文是用户要求的下一整包施工图，包含 DS48 必要返工和新增框架能力。执行者由用户选择并以 goal 长跑；收到本任务即自主实施、自验和集中交付，不按文件或小修逐次请示。C 的 Python 已归 DS，Linux 继续封存。

## 1. 目的、优先级和本包终点

DS48 已把多定义一票据、界面文档、工作区组件目录和公共工具接通，不能重做这些已成立的底座。本次要把它们交给普通应用开发者持续使用：两个业务实际复用同一多对象适配，界面文件可以安全保存、预览、重新载入和恢复已存版本，人在运行时改版后继续编辑原对象。

当前最大的 DS 缺口不是再多一种控件名，而是公共接口与正常应用之间仍有重复胶水，文档导入的“预览是什么、执行什么”还有契约漏洞。Sol 新线程独立修窗口生命周期/刷新/普通性能。JPEG、完整 SVG、DatePicker 等保留为后续能力，不在本包扩 native 写集，也不以本包结束宣布框架首版整体成熟。

本包结束时应能从一个 SDK 完成以下真实工作：

1. 开发者把已有业务对象绑定到公共适配，不复制一整份多对象 provider；手写、生成、外部操作共用原业务 owner。
2. 模型从公开事实现场规划多定义/工作区修改，预览与接受内容一致，A/B 草稿、身份和合法交互保留。
3. 用户保存当前已接受的界面、编辑文件并预览重载、拒绝错误文件、恢复已存界面；这些操作不偷偷 Apply/Cancel 业务草稿。
4. mixed 与 rules 的正常界面都有可发现、可达、可读的入口；第二业务不仅构造探针通过。
5. 一个最终 SDK、一个公共指南、必要候选与原始证据。内部编译成功不是终点，微小报告修正也不是单独停工点。

## 3. 复核发现：先修这些真实缺口

### 3.1 导入计划会改变已保存的操作含义

指导用当前生产 Python 和既有测试夹具做了两个**不向端点提交**的反例，原件为 [guidance-review-20261024.json](../../runtime/cjgui/artifacts/ds48-runtime-ui-document-20261023/evidence/guidance-review-20261024.json)：

- 将 `expected_structure_sha256` 改成 64 个 `0`，`apply_saved_ui_import` 仍返回新预览，不核对保存的预期。
- 将 `replace_definitions` 从 JSON `false` 改为字符串 `"false"`，解析使用 `bool(...)` 得到 true；同一基线从 `removals=[]` 变成删除 `runtimePresetCard`。保存的预期摘要仍是原值，却未被拒绝。

这不是端点已被错误写入的证据，但已证明公共入口允许产生与保存计划不同的候选。修入口后再检验真实提交只使用核准的同一预览。

### 3.2 多对象适配仍停在独立探针

`src/composable_ui_generated_multi_object.cj` 有新类型，但当前普通 `templates/` 和 `examples/` 没有构造 `CjguiGeneratedUiMultiObjectBinding`；mixed 仍用 `MixedPresetProvider`，rules 仍用自己的 provider。因此“两个业务实际使用公共适配”的终点没有完成。

此外，新适配没有转发 range 五项能力，继承默认“不支持/拒绝”；`applyFieldIntent` 只重新解析 key 后委托，没有像 action 路径那样核原 owner target。探针测了 action 退休，不能替代 field/range 的身份边界。不要直接把普通应用换成这个类型后牺牲已有输入契约。

### 3.3 拒绝关闭的提示需要额外输入

[关闭 README](../../runtime/cjgui/artifacts/ds48-runtime-ui-document-20261023/evidence/rules-close-20261023/README.md)明确记录：未保存 ⌘Q 被拒后补按 Tab 才重绘。保留 saved ⌘W/⌘Q exit 0；“无需额外输入即可看见拒绝原因”尚未成立。

本次 Sol 新线程已收到公共调度部分。DS 在消费者范围检查现有公共刷新调用时机；不要用定时器、补 Tab、重复 Quit 或强行放弃草稿补绿。如果现有 public API 正确接线即可修，DS 修消费者；确为 Host/window 挂起就使用 Sol 的明确交接，不能抢写 runtime。

### 3.4 模型使用与第二业务还有消费差距

原施工图要求 DS 自己按自然目标读取事实、规划并操作公共入口，**不要求独立模型服务**。只运行固定链后写“不声称独立模型服务”没有完成该项。rules 的新生成区还需要普通用户可达的真实编辑链，不能用接受版本或在折叠线以下的截图代替。

这几项与下一部分一起做，不再分别产出四份“补缺证”小包。

## 4. 写集、共享基线和执行顺序

DS 拥有 generated/composition/region、common controls、多对象适配、UI 文档、原 C 全部 Python、mixed/rules 消费者、创建工具、exporter/SDK/指南及相关测试。只改同一交付所需内容。

Sol 新线程按 [运行时施工图](2026-10-24-sol-runtime-continuation.md)负责 window/session/Mac host/native/prepared layout/owner budget/调度。禁止覆盖其在途文件；没有新交接就继续消费 DS48 已接受运行时。transport 当前仍归 DS，若 Sol 实证需要改共同唤醒接缝，按具体函数协调，不能整文件并写。

普通源码修改在主树；构建输入使用准确闭包，复用每个消费者一个工作目录。不要为了隔离每阶段复制整树，不要求 Git worktree；不 stage/commit/push/reset/stash/切分支。构建 target、桌面有共享副作用，先核谁在使用；无关 Python/文档工作可在等待时继续。

推荐顺序：A 文档可信性 → B 多对象公共接入 → C 界面文档工作流 → D 正常消费/模型操作/SDK。必要编译可汇合，不逐函数跑全库。本文已是任务说明，不另开执行卡或治理台账。

## 5. A：文档、预览、执行必须说同一件事

### A1. 收紧保存计划，不再另造宽松入口

入口在 `shared_operation_core/cjgui_ui_document.py` 的 `parse_saved_ui_import_plan`、`saved_ui_import_plan`、`apply_saved_ui_import`，对照既有 editor 保存计划实现。

1. JSON 类型精确检查：布尔只接受 bool；版本/代数只接受合法整数，拒绝 bool、字符串/浮点强转；摘要校验格式；端点身份和所有键保持严格。非法输入返回具名公共错误，而非 ValueError/TypeError traceback。
2. 按当前端点、accepted 版本/完整摘要、当前目录重新建立预览，再核它与已保存的 candidate/expected/diff 事实一致。现有字段不足以表达用户核准的操作时，以兼容、具名的版本策略补齐；不要删除旧校验或静默改变旧 v1 含义。
3. `saved_ui_import_plan(preview, document, replace_definitions=...)` 也须拒绝不一致组合，不能仅把外部参数和随便一个 preview 拼起来。执行 API 与 CLI 最终只使用这一个经守卫的 preview。
4. 若调用方确实要改变 merge/replace 策略，应重新生成预览/计划；不是解析时“尽量猜对”。replace 的 REMOVE 要在预览中可见，缺失定义的默认导入仍是保留。
5. 沿既有 CAS、ticket、原子 snapshot 和 receipt 路径提交。超时有真实 ticket 就保留，status/resume 不重提；不要为了 import 又造一个提交循环或成功状态机。

先将指导两条 RED 加入适用测试并转绿，再加一条“合法旧计划仍可执行”的正控。未知/篡改拒绝必须零提交。无需把旧 257 项按每个小改反复跑。

### A2. 同一文件在 Python 与仓颉入口行为一致

当前仓颉读取器 `File.readFrom` 之后才检查大小，实际不是有界读取；它只跳过 `requirements` 的 span，未验证该字段结构。Python 的 stat 后 `read_text` 同样不能把文件增长或特殊文件读限制在已检查长度内。两端 byte limit 也不同。这里按实际入口修，不开展通用安全审计工程。

- 从现有仓颉 JSON/文件工具中选择可复用实现；不要再手写第二套“看似 JSON”的解析器。若保留局部解析，必须完整拒绝本格式的坏 JSON、重复键、类型错误、未知字段、坏 UTF-8/转义，并以同一组文件反例和 Python 对照。读取中限额，拒绝超限而非先把任意文件装进内存。
- 明确同一文件上限、结构格式和摘要覆盖范围。仓颉启动加载的要求与 Python 导入一致；最终组件/field/action/style/resource 可用性仍由当前 catalog 准入，文件不获得授权。
- `requirements` 由实际结构引用派生。当前字体收集写死版本 1，需消费声明的真实版本；资源、style、field/action 和组合信息不能在文档中写一套、正文中用另一套。选择“核对派生值并拒绝不一致”或兼容的规范化方式，并文档化，不把 requirements 当权限来源。
- UI 文档是完整可复用描述；delta 的 REMOVE、端点、ticket/基线版本、业务草稿不是该文件的隐含状态。已有支持范围之外的未知/有损内容可只读显示，但不能重编码、保存成可执行文档或导入时静默丢失。
- 文件写入继续原子替换。临时写/rename 失败保留旧文件，失败的载入保留 accepted 结构和业务数据。startup 的拒绝不崩溃、不关掉仍可用的默认界面。

对外签名标 experimental，注明边界；不宣称校验代替服务端 CAS，也不宣称只校验 SHA 就可信。

## 6. B：让公共多对象适配真正替代重复接线

### B1. 明确最薄的职责

应用提供对象解析、原业务 binding/snapshot、授权和持久化；框架一致转发反馈、字段/动作、Select 和范围会话。保持一个 owner 正文、草稿、选择和版本源，不增加框架 cards 表、另一个规则缓存或 per-object controller 状态机。

优先组合现有 `CjguiGeneratedUiFormBinding` 与其 provider 能力，避免让每个对象又实现一套重复接口。接口名称可根据实际重复收敛，但已有单 owner、旧自定义 provider 保持兼容。此包不承诺业务字段无需代码，也不以“删行数”换隐藏职责。

对象命名由应用声明，不把 `card`/`rule` 前缀写进框架。普通布局 key、对象 instanceKey、空实例旧路由严格分开。对象被删除后仍必须识别为退休对象，不能在 `namesObject=false` 时落到默认表单；未知对象同理。

### B2. 不丢失现有编辑与身份契约

- 在 accepted 已冻结的 owner target/incarnation 基础上转发。field intent、ACTION、Select、range 一致；旧 key 换到新对象不能重定向原事件。region/holder 已有代次守卫直接复用，provider 补自己的对象身份证明，不能另造两套 incarnation。
- `rangeTextEditSupported / fieldTextVersion / applyTextEdit / confirmFieldTextVersion / rebaseFieldTextSelection` 的旧单 owner 与实例重载都接齐；默认单 owner 委托不是返回“不支持”。未知对象拒绝，未知历史映射 None，不猜文尾、不伪票据。
- owner target 相同但实例被删除重建时，旧会话仍按 accepted 代次退休；A/B 即使正文、版本相同也不能互串。范围会话恢复、外部整值修改所需的历史继续归原 owner/provider，不挪进通用桥缓存。
- 一个字段投影采用同份 formFeedback；BOOLEAN 首建/刷新/呈现变化不得一半冻结一半 live。Select 的选项、disabledReason、可用性/错误和写入仍来自同一字段声明，A/B 独立弹层查询/高亮。
- revision 来源须反映关联业务对象变化，不能只看默认 form 的版本导致 B 外部写入不刷新；又不能在每次只读查询上无条件升版。
- action 是否可用、原目标、事务执行必须一致；适配器不能在 `ownerBlockedReason` 生效时从旧重载绕过。无需给所有分支再加独立状态表。

### B3. 迁移两个真实消费者

先接 mixed，确认保住原来的卡片 range/Select/Apply/Cancel/删除/换绑/手写详情同对象；再接 rules，复用同一公共适配。业务封装可各自保留，重复的框架路由逻辑应删去或退到明确兼容层，不保留两条生产入口互相兜底。

rules notes 已有 160 上限和持久化，直接消费：手写、生成、外部三入口都进入同一 writer；合法/非法输入、锁定、Apply/Cancel 的返回和可见反馈一致。上次 80→160 的域/目录证据可复用；需要补的是普通应用真实编辑与拒绝，不能再只打印 `maxlen=160`。

最小反例聚焦：默认路径 range 仍支持；A/B 隔离；旧 target field intent 拒绝；删除/重建同 key 旧 range/Select 拒绝；反馈与 live 相反仍取冻结值。先看现有测试是否等价，不按本段每个句子新建测试。

结束时给两个消费者的接线位置：应用还负责哪些真实业务代码、框架消除了哪些重复转发。不能拿独立 FakeObject 探针代替实际接入完成。

## 7. C：新增可持续使用的界面文档工作流

这一部分是本包新增能力，不只是补更多验收。现有 `ui-export/ui-import/ui-apply` 已经会做核心工作，现在提供可被应用选择接入的薄文档会话和可见命令，让开发者不必反复拼私有脚本。

### C1. 状态只保留必要事实

一个可选文档会话最多持有：当前文件路径、最后成功保存/载入的文档摘要、对应已接受结构的比较基线、当前操作结果。当前界面始终从 region 的 accepted snapshot 读取，业务草稿始终在 owner；不要保存第二份可变节点树、自己结算 ticket 或把草稿放进 UI 文件。

接口可用薄组合/辅助对象实现，先查现有保存计划和文件绑定是否能复用。它不承担文件监听、自动保存、协同合并、无限 undo 历史或任意代码加载。仅显式操作，普通数据更新不会把 UI 文档标脏。

“未保存界面更改”与“未应用/未保存业务数据”是两个独立事实。UI 导入/撤回只能改变界面结构，不能调用业务 Apply/Cancel。关闭策略由应用决定；若当前参考应用只提示 UI 文档状态、不阻止关闭，也要明确，不暗中修改原 rules 业务策略。

### C2. 提供可发现的普通入口

在现有命令声明链中接入以下动作，标签可按业务调整：

- 保存当前界面：导出**已接受**文档，原子写到显式路径；失败保留旧文件/旧保存基线。
- 预览重新载入：按当前目录和 accepted 基线生成预览，显示将改变的定义/节点/绑定和 REMOVE。
- 确认载入：用该预览的同一计划和 CAS 执行；期间基线变化则具名拒绝并让用户重新预览，不悄悄套到新结构。
- 恢复已存界面：从已保存文件重新建立当前端点计划；不是重放旧 ticket，不回滚业务数据。
- 查看当前界面文件/变更状态和最后拒绝原因：使用同一文档会话事实，可被人看见、可由公共工具读到已有可发布范围。

路径先用现有 `--ui-document`/显式配置，不强做新 native 文件对话框。正常原生菜单/工具栏/面板消费同一 `CjguiComposableUiCommand`，执行复用 invoke 链。不能做一份菜单动作表、另一份 Python 动作表；Python 仍用已有公共文档 API 操作同一格式，GUI 组合已有机制。

可见预览复用文本、表格/列表、弹层；只需让人知道这次会改什么、确认还是取消。不是可视化拖拽设计器，不建设另一个 IDE。应用未启用这套文档入口时，ui-only 仍保持轻量。

### C3. 工作区是真正可用的入口

mixed/rules 的生成区域必须能从普通导航到达；低位字段用已有 Scroll/reveal，必要的页签/入口可在正常窗口看见。不用持续加高窗口或 AX 直接调屏外控件掩盖不可达。

修本包消费里的深底深字、错误/状态不可读：优先现有主题/命名样式与语义投影，不在每控件散落固定颜色。窄窗不裁掉保存、预览、取消/应用和拒绝原因；不要靠缩字号掩盖布局。

保持组件可组合，不把本工作台的布局/打印业务硬编码入公共控件。已有通用 Tabs/Scroll/Split/Select 足够完成本包，不扩一套“工作台专用节点种类”。

## 8. D：一次模型现场操作与两个正常消费收口

### D1. 真实模型操作的最小定义

DS 自己就是执行模型，无需再连接服务或找顾问。在最终正常应用已有 A/B 未应用草稿后，读取当时的公开 catalog/structure/instances，依据下面目标**现场规划**公共调用：

> 把详情改成“常用 / 附加”两页；保留两对象草稿，布尔字段用可搜索 Select；让较长说明在窄窗可读；把两个运行时定义的间距与标题一起改，并保留可见业务状态。然后保存成可重载界面。

不得提前把最终答案固化成固定 JSON 再称模型生成，不需要每次运行都随机造新问题。记录自然目标、实际发现、为什么选这些已有能力、公开调用和 accepted 结果即可。可以编写本次短脚本调用公开 API，但不能借私有写入直接替换 consumer 源码/内存。之后人工真实输入续写，证明模型改版没有夺走人的编辑能力。

### D2. 最终连续链集中执行

冻结最终源后，在 mixed 同一实例串起：

1. 公共适配下 A/B 身份与不同未应用草稿；人输入 A，公开读回 B 保持。
2. 现场多定义/工作区改版接受；焦点和合法选区仍对应原对象，立即续写。
3. A/B 的 Select 查询、Esc 零写、确认实际变值；锁定/退休目标拒绝后合法操作继续。
4. 保存已接受界面；用公开工具改布局形成 UI 文档 dirty，业务草稿不变。
5. 预览载入并取消，零结构写；再次预览后确认，得到同预览的精确结构。
6. 坏文件/篡改导入计划被拒，旧 accepted/文件/业务保留；一次合法重载继续。
7. 恢复已存界面，A/B 草稿仍保留；窄窗页签/滚动/分栏可达；分别 Apply、按对象精确读回、正常关闭。
8. 新端点从保存文件启动并正常编辑；旧 endpoint-bound plan 拒绝，正常关闭。

rules 做较短但真实的第二链：公共适配 A/B → 正常导航进入生成详情 → notes 手写/生成/外部互见与非法边界 → 界面文档保存/重载 → 业务 Apply/保存 → 未保存关闭的拒绝原因无需补键可见 → 明确保存或放弃后正常关闭 → 重开读回。顺序可根据业务状态合理调整，不能用 SIGTERM 替代正常终点。

若 Sol 的公共刷新修复尚未交接，独立文档和适配工作继续，暂留相关一步；不能把全部阶段搁置等，也不能把补 Tab 记为通过。交接时给当前基底和首个失败，不重复发同义催促。
