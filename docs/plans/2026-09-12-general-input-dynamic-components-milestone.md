## 完整交付

开发者用同一套组件构造包含按钮、布尔项、单行输入和多行文档的窗口，人能通过鼠标定位/拖选文字、键盘移动/选择、Tab 导航和键盘激活动作完成工作。应用动态增删、重排或换绑组件后，焦点、输入、选区和外部语义仍对应正确对象；外部修改后人能继续操作。新增能力在文档与既有表单两个普通消费者复用，不再为每个样例增加 native 分支。

这是补齐 GUI 框架通用输入与组件生命周期的大阶段，同时承接滚动缺口。不是再做一个专用编辑器，不要求清零所有历史遗留；保持仓颉核心、自绘/Metal 与窄平台服务路线。

## 复核依据与资产取舍

依据 [设计导航](DESIGN_INTENT_INDEX.md)、[可用性尺度](../core/CJGUI_UI_FRAMEWORK_COMPLETENESS_CRITERIA.md)、[前置阶段](2026-09-12-developer-interop-document-viewport-milestone.md)。历史 [高频交互研究](../research/ai-native-gui-runtime-architecture-intake.md) 关于内容修改和局部视觉更新分工可复用，旧暂停/审批文字不重新生效。

- 复用 [组件与布局](../../runtime/cjgui/src/composable_ui.cj)、[窗口控制器](../../runtime/cjgui/src/composable_ui_window.cj) 的身份、布局、版本及真实动作入口；输入/焦点策略应可供普通消费者使用，平台对象不进入公共 API。
- 复用 [native](../../runtime/cjgui/native/cjgui_internal_renderer.m) 的 TextKit 绘制与输入代理，但当前 `mouseDown` 仅按节点聚焦，没有从可见文字位置建立插入点/拖选路径；先复现再补齐。
- `doCommandBySelector` 当前把 `moveBackward:`/`moveForward:` 和 Tab 一起用于找下个输入框，有截获正常左右键的风险；导航仅查找可编辑文字，按钮/布尔项尚未形成完整键盘焦点链。
- 文末光标使用整个文本容器 `usedRect` 的最大 X，空文本不绘制光标；应覆盖长首行+短末行、尾随换行、空文档、换行边界。不要靠整体边框或文字像素存在代替正确插入点。
- `setNodesFromProjection` 找活动替代节点只比较 nodeId，再改写 resourceId；需要验证组件换绑资源时旧本地输入、组合态和排队事件是否会串入新对象。当前 `nodeId:resourceId` 滚动字典也需随节点退场回收。
- 前置自绘已经绘制可见 glyph 范围，但仍对整个容器 `ensureLayout`，非活动节点每次 draw 新建 TextKit 对象；不能写成已实现按可见行布局。此轮复用有界排版缓存及失效机制，观测实际工作量，不要求另写全套大文件编辑引擎。
- 复用文档 core 的批次/撤销与 [公开客户端](../../runtime/cjgui/shared_operation_core/client.py)。协作保存已有进程证据，不重复重做；不宣称能对非协作编辑器提供原子比较交换。旧 Action Router 摘要与退役 Bool 链不复活。

指导只做静态复核，接受执行报告 core 22/22、客户端 4/4、进程保存与针对性探针的范围。前置跨端周期已有外部 Unicode 修改、人类 ASCII 续写、撤销/重做、保存重开证据；它没有证明鼠标跨行选区。独立 Agent 的文档调用已报告通过，既有表单的独立动态调用需补明确结果，不能用文档 SELECT 动作代替不同领域消费。

## 连续实施

### 一、同一坐标与排版下的真实文字交互

把可见文字、点击定位、拖动选择、光标与选区背景使用的行片段/坐标转换统一。覆盖单行和多行、滚动后点击、跨行拖选、Shift 扩选、空文本、末尾换行、中文/emoji 与组合字符边界；越界拖动时采用有界滚动并保证释放捕获。窗口/节点退出、失焦或被禁用后不能保留悬挂拖动。

左右/上下键、Home/End 或对应 macOS 文本命令由正常文本语义处理，不用它们切换控件。剪贴板和系统文字服务继续复用；输入代理屏外不意味着候选定位可以屏外，补必要的字符范围到实际屏幕位置映射，并用探针证明坐标。物理中文 IME 候选/组合/提交仍需真实验收，不能用程序化字符串替代；宿主不允许时保留待验。

重绘不反复对未变化的全文设置属性/新建排版对象。按内容版本、宽度、字体/样式等失效，缓存有界且组件移除可回收；对于确实仍需全文布局的情况明确成本和限制。测试长短文档重复重绘、滚动与一次局部编辑的布局/缓存工作量，无硬编码帧率承诺。

### 二、可复用键盘导航与动作

给组件统一的焦点资格与可预测导航顺序，覆盖输入、按钮、布尔项；Tab/Shift-Tab、焦点可见反馈、按钮键盘激活和布尔项切换进入已有真实操作。只读文本的选择/复制与禁止修改分开处理；禁用/隐藏/移除节点不能继续接收动作。文档内 Tab 是导航还是文本插入应有明确、可由应用选择的策略，不能偷改所有消费者体验。

提供小而完整的窗口级命令绑定入口，至少让应用绑定保存、撤销/重做或等价已有动作；文本编辑命令与应用命令有清楚优先级，不硬编码业务动作到 native。平台菜单体系、任意快捷键编辑器和聊天入口不在范围。鼠标、键盘和辅助功能激活复用相同动作判定，失败不伪造成功。

### 三、动态身份与共同操作一致性

明确 nodeId、resourceId、组件类型与投影版本的有效绑定周期。删除、重排、同 ID 换资源/类型、变只读/禁用时，失效的本地输入、选区、组合态和排队事件不能作用到新对象；保留正常同对象刷新中的未完成输入。用确定性事件顺序区分该拒绝的旧事件与应保留的有效输入，不以全量丢弃事件规避问题。

焦点变化、选择与滚动是局部交互，不应制造业务内容版本；外部读取应获得当前有效对象和选择，节点删除后不返回悬空关系。公开客户端对人刚选中的范围做版本化替换后，人继续编辑与撤销；两个资源来回切换不能串内容或视口。不要为了支持输入再造可独立写入的文档 owner。

### 四、正常消费与完整验收

在现有文档窗口与一个既有表单窗口消费新输入/命令能力。必要时调整其普通组件构造以包含动态增删/换绑场景，不新做一款产品。验收一个完整周期：鼠标跨行选择 → 外部公开客户端读相同范围 → 修改 → 人用键盘继续编辑/撤销 → 保存/重开；另一个表单用键盘导航与激活实际改变领域，公开客户端动态读回。

补前置超一屏滚动空白修复后的真实窗口复测，包括滚动后失焦/聚焦、resize、不同文档切换。给无实现上下文的 Luna/Terra 独立验收 Agent 公开 README、CLI 帮助/导入 API、当前 descriptor 与自然语言任务，补不同表单领域的动态消费；不读实现/测试/阶段报告，不预填业务 ID。

按 AGENTS.md 对公共输入契约、native/FFI 和跨模块影响做必要检查。CodeLattice 此次仍只返回 protected_live_workspace 路由、未读取项目源码；以实际调用路径和针对性运行补证，不反复重建索引。相关 core、窗口、原生输入与客户端回归及正常构建适量执行；新输入回归必须经过生产事件路径，不能只调用私有 setter 或硬编码请求。给出测试与真实窗口各自覆盖范围。

### 2026-09-12 执行交付

已在原目录、原任务完成本阶段实现，未 stage、commit、push、切换分支或清理工作区。

- 通用输入：native 文字命中、拖选和选区使用同一 TextKit 坐标/组合字符边界；候选框
  `firstRectForCharacterRange:` 映射到实际自绘文字位置。只读文本现在可焦点/选择/复制，但不能
  把编辑事件送入 controller。
- 键盘与命令：焦点链覆盖文本、按钮和布尔节点；Tab/Shift-Tab、Space/Return、仅多行可选的
  `tabInsertsText` 与窗口 `save`/`undo`/`redo` 绑定均复用既有 controller 动作。为让原生文本
  代理不吞掉 Command 命令，输入代理只把带 Command 的 `keyDown:` 转交 overlay；当前真实窗口
  已验证 Cmd-Z 与 Cmd-S。
- 生命周期与成本：所有输入/选区/拖动事件按 node、resource、kind 与 projection version 解析；
  同对象刷新不丢局部状态，换绑/删除/变不可交互则不接受陈旧事件。非活动多行 TextKit layout
  以语义身份 LRU 缓存，容量 16，并在节点移除时回收；active layout 仅在文本或样式/宽度失效时
  完整重排。它仍不是完整富文本/增量排版引擎。
- 通用协议修复：规则集真实窗口的公开 `get` 暴露空 `filePath` 会形成末尾空字段；core 与公开
  Python 客户端统一用 `-` 表示零字节 UTF-8 值，批量文本替换的空插入/删除也采用相同 token，
  没有增加任何消费者或 native 特判。
