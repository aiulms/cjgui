# 跨工具使用

可移植单元是完整的 `cjgui-app-dev/` 目录：`SKILL.md`、references、scripts 与 assets（`PROJECT_RULE.md`
规则模板，`activate.py` 依赖它；只拷前三个目录会让项目接入失败）。
`agents/openai.yaml` 只是可选宿主元数据；主流程不依赖它，也不要求专用 MCP 或子代理。
模型能力影响使用结果，不能用模型名称代替问题归因。

## 加载与安装

| 当前工具的入口 | 使用方法 |
| --- | --- |
| 支持 Skill 发现目录 | 将完整目录链接或复制到该工具实际扫描的位置，再按它的机制刷新/开启会话并核对技能清单 |
| 可以读取文件，未提供 Skill 加载器 | 指定 `SKILL.md` 的实际路径，先读入口、按任务读相关 reference；无需先安装到全局目录 |
| 只有聊天/附件 | 提供完整技能资料与本次实际 SDK 的相关文档/声明；助手只给有依据的建议，无法执行的构建、窗口与文件读回保持未验 |

安装器仅管理文件，不修改其他工具的配置：

| 参数 | 目标目录 |
| --- | --- |
| `--host codex` | `${CODEX_HOME:-$HOME/.codex}/skills/cjgui-app-dev` |
| `--host dsh` | `~/.dsh/skills/cjgui-app-dev` |
| `--host agents` | `~/.agents/skills/cjgui-app-dev`；仅用于确认扫描该共享目录的工具 |
| `--skills-dir DIRECTORY` | `DIRECTORY/cjgui-app-dev`；支持自定义和项目级目录 |

本次 DSH 评测确认扫描 `.dsh/skills` 和 `.agents/skills`；其他宿主按其当前配置核对，不能假设通用目录。
使用 `--dry-run` 只看目标，返回 `discovery: not_checked`；安装成功也仍需从宿主核实发现结果。
同一机器多个入口可链接到同一维护源，不复制维护多份。Windows 或不能建链接时用 `--mode copy`；
这只提供文件复制方式，不代表已验 Windows 工具或 CJGUI Windows 应用运行。

复制安装附逐文件哈希与历史来源收据；原源消失仍可使用副本，收据路径不是自动更新地址。
更新前比较来源与本地修改，再由安装管理者迁移；安装器不覆盖已有目录或用户修改。

希望无需每次提醒时，还需[接入项目触发规则](activation.md)。规则放入宿主实际加载的位置，
安装目录可见和模型主动使用分别验证；无需改动已经在其他工具配置好的全局记忆。

## 解释器与工具能力

依赖识别和检索使用标准库 `tomllib`，需要 Python 3.11+。先核 `python3 --version`，不满足时
显式换用本机已有的合适解释器；所有脚本可在任意当前目录用绝对路径调用，含空格路径要加引号。
没有 Python 时仍可手工读应用 `cjpm.toml` 的依赖、同版清单和公开文档；保留未知身份。
没有桌面工具时可继续源码/编译工作，不能把编译成功说成窗口交互通过。
反馈脚本不可用时，按反馈指南保存同字段的本地 JSON/文字，说明尚未由脚本入库；有工具后再导入，避免丢掉原始失败。

给另一个开发 AI 的最小任务上下文可直接写：

> 读取 `<实际技能目录>/SKILL.md` 并按任务加载所需指南。应用在 `<APP>`；若要新建，指定 SDK 为 `<SDK>`。
> 先定位这个版本的用法再开发。首次遇到值得保留的障碍，加载 references/feedback.md，
> 按其流程保存观察与原件；原因不明先待分类。区分框架缺陷、易用性障碍和单次接入错误，不把未执行操作说成已验证。

不需要给其他工具复制 Codex 的调用语法、内置工具名或专属模型分工。
