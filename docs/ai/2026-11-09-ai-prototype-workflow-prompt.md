## 1. 唯一目标与完成含义

把已有 CJGUIPrototypeHost 交付为一个本机可用的 AI 原型工作流：

> 用户打开应用，新建或打开原型项目，把需求与应用提供的连接说明交给外部 AI；AI 经公开能力目录生成可操作界面，主动检查布局与视觉质量并迭代；用户实际输入和操作；项目可保存、关闭、搬移、重开，并由 AI 重新连接继续修改。

普通原型创作不要求用户先建立仓颉应用、安装编译工具链、查启动日志找 descriptor，或每次改界面重新编译。框架开发者首次构建交付物，与原型使用者日常运行是两条使用路径，文档须分清。

**完成判据是这条工作流可重复使用，并完成一个新需求的真实消费。** 欢迎页、模板、截图或测试单独通过均不是完成。保持仓颉核心、自绘 GUI、窄平台桥接、人和 AI 共用真实 owner 与公开操作的方向；候选仍为 `experimental/additive_only`，本阶段不宣称成熟首版或稳定 API/ABI。

本阶段推进的是“运行时界面生成能力能被普通使用者发现、使用、保存并持续修改”，同时把重复的使用障碍收束到公共入口和配方。宿主仍是普通消费者，不成为另一套框架、DSL 或模型运行时。

## 4. 必须交付的工作流

### 4.1 普通启动、新建、打开

1. 无参数双击宿主进入清晰的起始界面，能新建项目、打开已有项目、试用示例。空工作区应说明下一步，不能只留下空白生成区。
2. 新建使用当前项目声明与模板系统，至少提供空白起点和一个可操作模板；现有 form/list/cards 配方按需复用。用户只需选择名称、位置和起点，不手工拼一套目录或复制仓库路径。
3. 打开入口优先复用已有文件/目录选择能力；项目根仍是界面、数据、资源与会话的唯一路径锚点。继续支持原 `--project <绝对路径>` 路径，原三项目仍能打开。
4. 模板是可复制的声明、资源与界面文档，使用者修改的是自己的项目；不把可写项目放在 app bundle、SDK 或共享只读模板内。新建遇到已有目标、无写权限、非法声明等要具名报错，保全已有文件；打开失败保留当前项目及草稿。复用现有加载和原子切换，不再造一套会话权威。
5. 当前项目身份、连接状态、保存结果要可见。切换项目后标题/主要身份显示应一致；未应用草稿与未保存界面沿用明确的保留/放弃语义，不静默丢弃。诊断细节放到适当入口，避免占据原型主体。

界面布局由执行者设计，不要求照搬系统设置。使用现有框架能力实现最小完整入口，不另起可视化编辑器、插件市场或工程管理系统。

### 4.2 把正确上下文交给外部 AI

提供可发现的“交给 AI / 复制连接说明”入口。输出必须基于当前实例与项目生成，至少让模型获得：

- 当前项目位置、可编辑文件及保存位置；当前有效 descriptor 和连接是否就绪。
- 随交付物提供的公开客户端位置、正确命令及实际依赖；不要求回作者 checkout 找脚本或临时 `work/` 下的 readback 工具。
- 查询 capabilities、读取 accepted 结构/字段、提交与精确读回、导出界面文档的最短流程；预算由当前 capabilities 返回，不照抄旧数字。
- 公共主题/布局配方和主动质量检查入口；项目字段与动作必须来自声明/owner，不能生成表面可点却不写真实状态的控件。
- 重开后重新获取 descriptor、重新读取版本再续改的规则。过期连接、过期候选和跨项目请求应清楚拒绝，不能自动改投别的项目或隐式覆盖。

复用 `cjgui_generated_edit.py`、typed client 与既有发现协议。CLI/帮助材料应可随 app 或配套工具目录搬移；若模型客户端仍需 Python，清楚检查并说明依赖，不把“GUI 无需编译环境”夸成“所有模型工具零依赖”。不内嵌模型服务、API Key、聊天代理或新的脚本执行引擎。descriptor 只作为当前本地会话连接，不作为公开网页内容或长期可复用凭据。

模型可在用户授权的项目目录内建立/调整声明与示例数据，再走现有重载入口；运行中的界面修改必须消费公开结构接口。需要改变现有规则/删除字段而既有契约拒绝时，应明确边界；本轮固定验收不要求另造通用 schema 迁移系统，也不允许删除用户项目重来以假装原位修改成功。

### 4.3 从自然语言需求跑一次新原型

使用一个独立的“书籍／章节管理”原型项目验证通用性，全部为虚构数据，独立于现有小说工作台。最低需求如下，具体视觉和布局由模型依据能力目录设计：

> 为一本虚构书籍制作章节管理原型，至少 24 个章节。可筛选和选择章节，查看并编辑标题、摘要、字数和完成状态；支持有效性提示、应用与取消。宽窗便于同时浏览列表和详情，窄窗仍可完整操作。空筛选结果有明确说明与清除入口，不将旧章节详情伪装成当前匹配项。能保存界面和草稿，关闭重开后接续修改。

这是管理原型，不要求完整正文编辑器、写作模型、同步服务或新增/删除章节业务引擎。书名、记录、字段和动作由项目声明驱动；不能按项目名在宿主源码中硬编码整页。

开发完入口后，执行 AI 亲自作为模型消费者，从新建项目和公开入口完成以下连续过程，并保留实际请求、响应和读回：

1. 从需求与空生成区生成首个可操作版本；不得复制一张完成页面后声称模型从零生成。
2. 根据真实窗口的检查结果改进布局/主题/操作区域，再进行一次正常需求修改。合计至少两轮续改，普通界面修改不重编译、不重启。
3. 使用已支持的声明扩展新增一个普通字段，经重载、capabilities、生成控件、实际输入到 owner 读回走通；保留原字段草稿。若当前公共入口不够易用，在已有机制上补齐接线。
4. 提交一次有明确错误的候选，确认具名拒绝和旧界面/状态保留，再以正确候选继续。
5. 人的交互路径用正常窗口真实输入/点击验收；模型路径读回同一 owner。至少覆盖选择非首条记录、输入/校验、Apply、Cancel，不用直接写 session 文件冒充操作。

本执行 AI 的公开消费属于真实模型消费，但不是“陌生开发者盲测”。不自动启动另一个模型或线程凑独立性，也不把等待用户逐项纠错作为验收前提。

### 4.4 保存、重开与可搬移交付

界面文档与业务会话保存职责清楚，允许复用既有按钮或做更易懂的组合入口，但不能把保存草稿等同于 Apply。验证一次非首条记录存在未应用草稿时的保存、普通关闭、重开；选中记录、详情 owner、draft/applied 和实际画面必须对应，恢复不能隐式应用。

把本轮私有项目副本及交付物放到仓库外的含空格/中文路径，正常打开并续改。内部资源按项目/包位置解析，无作者机器的绝对路径依赖。旧进程退出后用新连接继续，旧 descriptor 失效。数据文件、UI 文档和会话的实际格式/版本按现有实现说明，不将封装会话文件误称为可随意手改的普通 JSON。

交付预构建 `.app`、必要的模板/公开模型工具、简短快速开始和新原型项目。普通运行不得要求仓颉 SDK/编译器或作者源码目录；如受系统库或系统权限影响应具名说明并验证实际可行入口，不通过关闭系统安全设置实现“开箱”。本轮为本地分发候选，不包含公证、商店上架或互联网发布。

## 5. 主动质量检查与 HTML 对照

使用现有 v7 skill 的视觉复核流程。本阶段要让模型在用户指出前主动发现常见问题，**不是再写一个只要求“认真检查”的提示词，也不是另开发一个大而全的视觉测试平台**。把检查时机、可取得的事实及结果接到本次真实工作流中，必要的共用说明放入模板/配方/交付指南；不修改 skill。

审美沿用 [Apple macOS HIG](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos)，重点是清晰层级、合理密度、可调整窗口和一致操作；布局组织参考 [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout) 与 [ArkUI 自适应/响应式组件布局](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-multi-device-component-layout/)。这只是设计依据，不是逐像素复刻或完整 HIG 认证，也不要求追逐新的系统视觉特效。

每次功能改动完成后，先做受影响连续操作，再检查真实画面及必要的 accepted 几何/AX 事实：

| 检查 | 要分清的问题 |
| --- | --- |
| 工作区利用与缩放 | 列表/编辑区应按语义利用剩余空间，操作可达；自然高度短表单允许留白，不为填满而拉长所有控件或填充无意义内容。 |
| 文字完整性 | 检查全可见行的两行文字、基线、行高、padding 与 clip；滚动视口边缘正常出现的半行不是同一种缺陷。 |
| 对齐 | 操作按钮按命名配方居中，列表与输入按各自语义对齐；不能把“所有文字居中”当成统一审美。 |
| 亮暗与状态 | 主题角色、普通/选中/禁用/只读/校验错误下保持可读，检查真实前景背景；AX 名存在不证明文字在画面里可见。 |
| 内容与交互 | 空态、无结果、长标题、中英数字、非首条记录、错误提示和焦点反馈；不显示误导性的旧详情。 |
| 语义与可操作性 | 键盘焦点可达、可访问名称和 owner 一致、真实点击/输入生效；AX 操作不得冒称真实 VoiceOver。 |

必须实际查看截图，不是只产出截图文件或 DOM/AX 断言。若需要补诊断，先复用已有 `diagnosticSnapshot` 等只读事实，只补直接影响归因的缺口。故障归因和修复证据记录到同一反馈；没有足够证据时保留未知，不编造字体/渲染器根因。

为同一新需求做一份独立 HTML 对照，使用相同数据、状态和窗口内容区尺寸；不走 HTML 转 CJGUI 的生产链，也不将 HTML 自身的设计缺点当正确答案。最低覆盖宽窗亮色、宽窗暗色、720 宽窄窗，再补空筛选结果和滚动到后段的受影响状态。每个状态保留一对必要原图并写明具体差异及归属，不做全部尺寸×状态排列或逐像素相等门禁。

参考尺寸可使用内容区 `1280×820` 与 `720×820`，另做一次连续缩小高度以确认操作仍可达；记录实际测得内容区而非把整个窗口或图片像素直接当逻辑尺寸。既有三例/旧 HTML 只跑受影响路径，不重新开全矩阵。

## 6. 实施与验证顺序

先实现可运行的最短纵向链：无参启动 → 新建项目 → 获取连接 → 首次生成 → 输入 → 保存重开，再补视觉质量、模板和错误路径。不要先花几轮只整理规范或增加测试数量。

对缺陷保留能区分根因的原始 RED，再做最小适当修复和 GREEN；对新入口直接用正常消费验收及必要反例，不为低风险文字改动制造镜像单测。公共 API/native/跨模块变更按 AGENTS 检查影响；图工具不足用源码和运行证据补足，旧索引不是停工理由。同一 `cjpm target` 的 build/test 串行，测试须核对实际构建身份，不能复用陈旧二进制数字。

汇合后一次完成必要的框架构建、相关测试、`git diff --check` 及受影响窗口/公开模型链。新项目、新入口的交互与保存失败必须有真实结果；对未改的旧功能复用适用旧证据并注明身份，不声称在新版本重验。

记录以下使用成本，时间起止点应可复核：

- 解压/打开到能新建或打开项目；模型获得有效连接到首个可交互原型。
- 至少两轮修改从提出修改到 accepted 并可见的时间，编译/重启次数及原因。
- 实际需要用户提醒的次数；模型主动发现的问题、归属、已修/未修及理由。
