# CJGUI 治理总则

更新：2026-09-19。目标：帮助开发 AI 交付可用框架，控制实际风险，减少重复决策与上下文负担。
统一操作入口为 [AGENTS.md](../../AGENTS.md)。本文件用于解释治理，不是每轮必读表单。

## 规则的有效范围

用户最新明确决定优先。各类信息的维护入口见[文档归属](../README.md#各类信息只在一处维护)：项目方向管目标，架构契约管机制，验收文件管完成依据，AGENTS 管协作，ACTIVE 管当前状态，阶段页管本阶段交付。
当前阶段可在这些边界内具体化任务，不能覆盖方向、架构或降低验收。确有冲突时由指导修正对应维护入口和任务引用；只暂停依赖该冲突的工作，不能把阶段日期更新当作自动推翻架构。
阶段已明确允许的实现，不因旧文档的“本轮不授权”“暂不实现”再次申请许可。
历史 stop-line 只描述当时任务；旧 plans、归档、research、技能模板均不能单独增加当前审批。

当前状态只在 ACTIVE_DIRECTION.md 维护。README 和 tracker 是入口，不重复长篇完成记录。历史报告放阶段页或归档；不得把多轮“当前任务/继续执行”追加回 ACTIVE。执行提示词引用阶段页，不另存一套逐项任务；定时提示词只保留读取入口、监督职责和触发条件。
指导 AI 给出大阶段目标、必要边界与验收；执行 AI 决定具体步骤、内部文件组织和验证顺序。
角色细则见 [协作分工](HUMAN_COLLABORATION_GOVERNANCE.md)。

## 一个阶段怎样工作

1. 下发阶段目标：说清用户能做什么、框架需提供什么、范围与完成证据。提示词本身可以作为阶段说明。
2. 执行 AI 检查当前源码、未提交改动和最小相关资料，直接开始能推进目标的实现。
3. 在同一阶段内自主处理依赖步骤、缺陷和必要重构，不按 helper、符号或 Bool 包装拆成审批链。
4. 运行与风险对应的检查，证明真实应用链路。发现问题先定位和修复。
5. 更新当前状态并做一次阶段交付摘要；指导 AI 在阶段结束或实质偏离时审阅。

不要求每次都有 preflight、decision、execution card、manifest、closure 五件套。
已经有阶段说明时，不另建内容相同的执行卡。交付摘要可写在同一阶段文档或回复中。
例行进度只更新一处，不同步复制到 README、tracker、topic manifest 等多个索引。
明确的文档整理任务可以只改文档；实现任务不能用文案、摘要类型或验证包装代替可用行为。

## 执行 AI 的自主范围

- 已下发阶段内，允许实现完整功能路径，调整相关内部文件、添加必要测试和修复构建问题。
- 文件清单描述起点与责任范围，不默认是逐文件许可表。为同一目标补充相关文件，说明理由即可。
- 输入、文字、语义入口、真实状态写入、基础事件循环等若是阶段必要能力，应实现并验证，不能因名字在旧禁区中而长期停工。
- 必要 experimental API 可随阶段提供给真实样例消费，标明稳定性；不能为了维持 internal-only 而永远只把源码复制进探针。
- 公共 API、FFI 和共享模块需要较强影响检查，但“风险较高”不自动等于每步需要新文档或人类确认。
- 不以固定行数、固定文件数或固定子步骤数判断可否开工。

## 何时需要升级讨论

只暂停相关风险部分，继续不依赖它的工作。升级时带上已查明的事实、候选方案和推荐意见。

- 改变项目定位、技术路线，或引入阶段外的重型依赖、多平台工作。
- 破坏已承诺的稳定公共契约，迁移/删除真实用户数据，或需要尚未获得的外部权限与发布行为。
- 新发现的状态所有权、FFI 生命周期、并发或实际授权风险无法在当前阶段内可靠解决。
- 发现其他任务正在修改同一关键路径，无法安全保留其工作。
- 广泛生产变更的影响分析出现 HIGH/CRITICAL；先核实实际影响并说明，不能直接忽略。

工具缺失、索引过期、未知符号、首次测试失败、没有现成模板或需要多读一个相关源码文件，不是独立的暂停理由。
“需要更多验证”应落实为具体可执行检查，不能变成无限 preflight。
已有授权不反复询问；无法执行的检查必须说明原因和受影响结论，不得伪造通过。

## 保留的质量底线

- 应用的真实状态与业务操作有明确归属。语义与像素都从真实状态得到结果。
- 不伪造运行、写入、readback、后端就绪、外部调用或发布状态。
- FFI 资源生命周期、线程要求、错误边界以及公开接口保持可验证。
- 不覆盖他人工作；不擅自提交、推送、改系统配置或清理不明进程。
- 不恢复 stage145–892，也不新增同构审计链。
- 只清理妨碍当前真实交付的旧代码，不把全面清理变成新的长期前置工程。

## 验证与交付

具体检查矩阵在 [AGENTS.md](../../AGENTS.md)。实现阶段至少区分：
源码存在、针对性检查通过、正常应用已消费、真实外部调用已跑通、是否发布。
窗口截图用于证明可见结果，状态读回用于证明内容；两者不能相互替代。
外部调用测试工具只能证明接口；要证明真实 AI 协作，还须实际模型/Agent 调用同一路径。
接入环境不可用时，完成本地可做部分并明确外部验收缺口，不把阶段标为完整完成。

每次交付说明：新增的可用行为、真实消费入口、已执行检查、剩余问题。
状态写入另说明前后值、失败/撤回处理和写入位置。
只改文档时做链接、冲突、差异和源码保护检查，不要求启动窗口、运行构建或重复 native 探针。

## 对治理本身的限制

默认阅读入口短且唯一。长资料通过具体问题按需查询，不要求全文预读。
发现重复规则时合并到现有入口，不再创建治理包装。新规则需要对应实际发生的问题。
只增加 decision / readiness / receipt / report 而没有改变用户可用能力时，返回真实执行路径。
指导 AI 通过阶段目标与验收把关，不逐函数指挥，也不把执行 AI 当填空器。
