## 方法与口径

- 三态判定规则写死在 capability-matrix.md 文件头：**真实现**要求仓颉分支 + native 实现双源可指；**静默空壳**指到常量桩；**没接**给出反证。"源码存在 / 有测试 / 有真实消费者验证"三种状态分开，不混成"有"。
- 关键不对称事实：macOS 原生代码在 `runtime/cjgui/native/`（不在 platforms/ 下）；OHOS 的仓颉侧是 `platforms/ohos/snapshot/src/` 冻结快照（不含 `@When`，不参与主树条件编译），判定基于快照 + `platforms/ohos/host/`。
- `os != "macOS"` 只说明"非 macOS"；内部可能只有 Windows 逻辑，Linux 落进去拿空值。逐格核对，未按对称性猜。
- 质量抽检：矩阵随机 10 格回源码复核 10/10 判定一致（1 处引用行号偏差已修正）；fallback 清单抽 5 条后果核实成立；包 A 数字与独立基线（458 处 / 24 文件 / 11 形态）逐项一致。
- 边界：全程零构建、零运行；除本目录 6 个文件外无任何仓库改动；判据不足的格子标"待确认"（矩阵 5 格），未硬填。

## 局限

- "真实现"= 双源码可指，**不等价于已通过运行验收**；运行证据按仓库规则另行采信。
- 行号随工作区变动漂移；提交这批改动后请以 git blame 对应 commit 重查。
- OHOS 各格代表"快照 + OHOS 宿主"的现状，主树第四平台兜底分支的后果按未来主树 target 计（见 silent-fallback-audit.md 口径节）。
