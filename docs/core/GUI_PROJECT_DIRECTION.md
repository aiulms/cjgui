# CJGUI 项目方向

更新：2026-09-12。状态：用户已确认的方向；不代表下述能力已经实现。

## 目标

CJGUI 的目标是基于仓颉、类似 GPUI 的高性能 GUI 框架，保持自绘/GPU、轻量与可组合方向；GPUI 是目标参照，不要求逐接口复刻或预先宣称性能相当。它让人通过视窗理解、操作应用，让外部智能系统通过与界面对应的内容、上下文和动作理解、操作应用。双方可以读取、生成、修改，并接手对方的工作。

例如：人在文章中选中一段，提出修改想法；外部系统直接知道所指内容，修改后人在正文看见结果；人继续修改，外部系统能在后续工作中获取新内容。此例解释能力，不指定必须做文章产品。

价值要通过实际工作验证：减少复制内容、重新解释上下文、模拟鼠标和检查纠错的成本。不能以代码量、阶段数量或模型更强为由预先认定成功。

## 开发者的决定权

应用开发者决定界面、业务、交流方式和接入对象。应用可以没有聊天框，也可以使用批注、侧栏、语音或外部助手。
框架不强制聊天壳、Agent 运行时、模型供应商、对话历史或某种产品布局。
外部调用方可以是 Agent、直接使用模型的平台、自动化工具或其他应用；不依赖对未来 Agent 形态的预测。
界面生成与动态对话组件是可选扩展，不能成为首个可用框架的前置条件。

## 应用、框架、外部系统的边界

- 应用定义内容、业务规则、权限和具体体验。
- 框架提供窗口、显示、输入、状态更新，以及对应的语义读取、操作调用和变化获取能力。
- 外部系统自行决定如何理解请求、规划和调用。框架不承担模型推理、任务规划、工具循环或长期记忆。
- 连接适配层选择传输与编码。能调用应用不等于能控制外部系统的聊天会话，不能宣称兼容任意底座。

## 同源与授权

- 内容和业务状态各有明确负责人；图像、语义快照、调试输出不各自持有一套业务真相。
- 人与外部调用进入同一套实际业务操作与校验；不要求经过相同的鼠标事件。
- 选择、筛选、正在编辑但尚未保存的内容也属于交互上下文，要有明确作用范围。
- 有效授权内允许批量操作视口之外的数据；屏幕可见性不能替代权限判断。
- 已有授权满足操作条件时直接执行，不因为弹窗或 AI 身份机械重复确认。
- 业务约束、授权撤销、缺少信息与版本冲突仍然有效；生成内容不能自行授予权限。
- 操作完成与画面显示进度应能区分，不把未显示的结果声称为人已经看见。

## 技术路线与自由度

继续以仓颉核心、macOS 首个平台、AppKit/Metal 窗口和自绘为当前路线。平台桥接可处理必要复杂性，向上接口应明确且窄。
不因本次方向调整替换为重型 GUI 框架或扩展多平台；有必要时另做明确取舍。
模型、通信格式、传输和聊天组件都不写进不可替换的核心。
S 表达式保留为候选；先明确对象、动作、参数、上下文和结果，再以实际任务比较编码方案。
业务含义需要开发者表达，框架应减少重复定义，不能声称自动理解任意业务。

## 如何推进

用户提供期望的框架与使用体验，指导 AI 负责主动判断技术方案、阶段优先级与路线是否偏离，不依赖用户先发现缺项或提出架构调整。既定目标内的实现取舍和推进顺序可直接调整；若建议改变项目定位或放弃仓颉/自绘路线，应由指导 AI 先给具体证据、推荐方案与代价，再与用户讨论，而非让用户自行诊断。

持续建设的框架主线包括：仓颉组件表达与复用、布局/样式/资源、场景到自绘及 GPU 输出、输入/焦点/文本/无障碍、状态更新与调度，以及对应的语义、动作和变化获取。
轻量、高效、可解释仍是原始目标；用包消费负担、接入代码、输入响应和绘制成本检验，不能用文件数量或固定性能口号代替测量。
系统窗口、文字、输入法等服务可复用；框架自己的组件组织、布局、状态和交互职责不能因某个样例或测试工具的便利性而长期下沉为专用平台表单。

输入法明确只做系统集成，不开发输入法产品或引擎。CJGUI 负责向系统提供文本上下文、选区和候选定位，接收组合、提交/取消，并协调焦点与外部修改；识别、词库、候选生成与排序由系统输入法负责。验收针对受支持系统输入法的正常集成路径，不穷举全部输入法，也不让系统输入法自身问题无限阻塞框架主线。
一个阶段可以只打通其中一部分，但要说明它与已有资产的关系。自绘、共同操作或参考应用中的任何单项都不能代替整个框架方向。
历史资产和设计目的通过[设计意图与资产导航](../plans/DESIGN_INTENT_INDEX.md)按需恢复；后置能力仍保留导航，不因本轮不做而遗忘。

每次阶段接续要由指导 AI 判断当前最大的框架能力或风险缺口，以及为什么值得先做；将判断简写进 ACTIVE_DIRECTION 或下一阶段提示词即可，不新建评审台账。高性能以真实输入到更新的延迟、CPU/GPU 与内存/资源成本、实际工作量及测量条件说明，少创建节点或少提交几次只证明局部优化。不能以样例功能增加、测试数或界面能显示推定框架成熟；必要时主动把后续投入转向渲染、调度、资源、正常包消费或独立使用验证。

从第一组可用控件开始同时提供人的入口与外部入口。基础文字、选择、点击、语义信息和真实动作可以在同一阶段实现。
用正常应用消费框架来验收。样例是检验框架的使用者，不限定未来应用类型，也不允许把框架行为全写在样例私有代码里。
