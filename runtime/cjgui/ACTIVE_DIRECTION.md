**首个成熟版本优先（用户最新决定，2026-10-19）：** 以高性能、可供普通应用稳定使用的公共框架为目标，先补齐[首版范围内的实际缺口](../../docs/plans/2026-09-26-framework-capability-roadmap.md#first-mature-version)，再扩展平台与高级能力。布局表达、正常输入与无障碍、手写/生成共同接入、开发分发与轻量诊断、普通负载性能和资源责任共同收束；已有能力复用，不能凭组件名或关键词缺失重造，也不能凭测试数宣称成熟。后续每簇解决一个有交付收益的缺口，不继续堆样例功能；必要验证随实现汇合，不为每个小修复重跑历史矩阵。

**2026-10-21 整体接续校准：** 三条在途包照常完成；随后 Sol 主责共同运行时/Mac 连续输入、普通负载性能与资源，DS 主责公共 API/能力与语义契约、开发接入和统一 SDK 出口，Linux 主责同一已接受核心及应用源码的第二平台消费和普通桌面可用性。现有布局、Inspector、生成/绑定和建项资产复用，不无限扩控件或诊断样例；最终汇合一个有明确支持范围、兼容规则和性能/资源边界的候选。Mac 首版与 Linux 支持子集分别验收，不等待全平台追平。后续整包仍由指导下发，本段不打断或自动扩展当前任务。详见[关键缺口、分工与首版结束条件](../../docs/plans/2026-09-26-framework-capability-roadmap.md#first-mature-three-lines-20261021)。

既有三阶段及其范围：

1. **普通应用组件组合与公共接入收束（已按原范围交付）**：复用组件、虚拟列表、可搜索面板、主题、弹层与视觉效果，打通列表筛选、详情编辑、菜单与弹层、键盘导航、窗口缩放、图片及状态反馈。已有能力直接消费，缺失才补；沿用现有普通消费者，不新造大应用。完成标准：**既定七类操作完成一条正常连续会话，并实际换一次业务字段和布局，不需要修改 native，也不需要在应用里复制输入或提交状态机。** 满足后进入阶段 2，不顺手扩成完整控件库；必要失败检查仍按改动风险执行。
2. **手写与动态界面的共同接入与开发分发（已交付）**：通知混合表单与新建 `mixed-form` 打印预设共用字段、动作和 owner；公开生成／同 key 重排后人继续编辑，独立客户端可读写／Apply，默认手写无需连接。复用现有创建脚本与公共 catalog，未另造解释器或控件库。最终候选受影响连续链通过；共享target测试结束后一次根skip-script成功、输入前后无漂移。开发预览包从仓库外解压根完成独立创建／编译与人＋公开客户端短链，实际分发出口已交付。后续新能力另按完整任务簇安排。
3. **首版 macOS 范围收束后，选择一个其他平台做稳定能力簇的复用移植（待选择，不自动启动）**：迁移同一组组件和同一个消费者，检查平台还需补哪些接口；若仍要复制大量业务或共同状态逻辑，先修正共享边界。完成后再安排其余平台。用户另行安排的 Linux 线按其当前任务独立推进，不以本阶段尚未启动为阻塞，也不自动扩成全量移植。

性能随能力做，不做无限专项：普通操作卡顿、输入丢失、内存持续增长仍须处理；已确认的滚动纹理反复分配在相关绘制能力中优化；1GiB 极端编辑、轻微残余顿挫、所有平台统一性能数字保留未完成状态，退出主线关键路径。每簇采用「必要反例 + 一次正常连续消费」，没有新问题不重复整包；不能用缩小负载把旧门改成通过，但可以明确后置旧门。

阶段2候选、公共接入和根构建已按原范围收口，不等于首个成熟版本已完成。当前先补首版公共能力与使用质量的实际缺口；既有可用版本、缺口和原证据保留，H/W暂缓追新，Linux遵循用户另行分工；第3阶段全量能力簇移植仍待选择。
