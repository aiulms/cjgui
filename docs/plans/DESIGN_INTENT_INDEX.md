# P1 设计意图导航索引

状态：docs-only / navigation aid / design intent index

## 文件定位

本文件是 `docs/plans/` 的设计意图导航入口，用来帮助后续执行者在历史计划文档膨胀后快速定位主题、owner、stop-line、canonical tail 和当前主线结论。

它不是 runtime truth，不替代 [GUI_TASK_TRACKER.md](/Users/jiangxuanyang/Desktop/cangjie/GUI_TASK_TRACKER.md)，也不替代具体的 manifest、preflight、closure review 或 execution card。遇到冲突时，当前状态仍以 tracker 与对应主题的最新原文为准。

## 使用流程

1. 开新 `P1`、future slot、external surface 或 renderer implementation gate 前，先查本索引。
2. 再查对应 [topic-manifests](/Users/jiangxuanyang/Desktop/cangjie/docs/plans/topic-manifests/README.md) 里的主题 manifest。
3. 再读取主题 manifest 指向的 3 到 10 份关键原文，确认 owner、truth、stop-line 和当前后续入口。
4. 若主题不存在，本轮 gate 或 closure 后必须补充新的 topic manifest，或把新主题接入已有 topic manifest 的维护备注。

## 维护规则

- 新 manifest、milestone 或 branch closure 改变主题状态时，同步更新对应 topic manifest。
- 不移动、重命名或删除历史 plans，不要求后续执行者全量阅读 `docs/plans/`。
- 只维护主题级 summary，不复制长文全文，不把索引写成新的 runtime truth。
- 新增或修改 Markdown 继续使用中文正文和中文章节标题；英文只用于代码符号、文件路径、API 名称、工具命令和固定治理术语。
- 后续新增 `.cj` runtime owner 文件仍需保留文件头维护注释，覆盖 Owner / Truth / Stop-line / Same-shape Boundary Brake。

## 出口机制

完成 gate、closure、manifest 或 milestone 后，必须执行设计意图出口自检。若本轮改变主题当前状态、canonical tail / endpoint、owner file、default draft、runtime input、current truth、stop-line、Same-shape Boundary Brake、唯一 next opening、future radar / forbidden / deferred 结论、public allowlist、protected path policy 或 docs language / owner comment governance，就必须同步对应 topic manifest。

阶段出口建议在 branch milestone manifest、long chain manifest stabilization、某条主线推进 5 到 10 轮、`docs/plans/` 新增约 30 到 50 份文档、README / tracker / topic manifest next opening 不一致、执行 AI 重复发明已有设计或用户明确感觉“文档太多、方向开始埋了”时，开 docs-only navigation reconciliation。

周期出口是软规则：高频推进期间每周或每新增 30 到 50 份 plans 做一次 docs-only reconciliation；低频维护时只在主题状态变化、导航滞后或用户要求时做。当前不是自动归类系统，topic manifest 仍由 AI / 人维护。

协议原文见 [P1 设计意图导航出口协议](/Users/jiangxuanyang/Desktop/cangjie/docs/plans/2026-05-06-p1-design-intent-navigation-exit-protocol.md)。
