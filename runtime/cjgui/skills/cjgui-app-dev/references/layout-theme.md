# 布局与主题

先读实际 `FRAMEWORK/LAYOUT_PRIMITIVES.md` 的相关配方和
`FRAMEWORK/STYLE_ROLES.md`；没有某文档/角色的旧包先核对应公开声明，不自动套新版。
需要文字规则时加载 `STYLED_TEXT.md`、`FIELD_CONTROLS.md` 中相关段落。
具体构造器与默认值从同版模板取，不复制一套固定版本的大示例到技能。

## 定位布局问题

从出问题节点向父容器追踪可用区域与约束，使用同版 Inspector/只读快照：

1. 确定父轴、可用宽高，查 fixed/min/ideal/max 是否已耗尽空间。
2. 区分主轴余量与交叉轴拉伸：纵排看 growY，横排看 growX；横排子栏铺满高度看子项自己的 alignY/stretch。
   不把容器 align 当作所有孩子的默认样式。是否有单 grow 特殊分配规则，以本版配方为准。
3. 长正文与可增高编辑器检查是否处在有确定高度的普通容器内；不要从外框高度减一个猜测标题栏高度。
   版本提供 `window.contentBounds()` 时按其可空结果使用。
4. 滚动内容按同版单内容约束组织，viewport 在窗口生命周期内复用；不要每次构树重置。
   内容超出视口是正常滚动几何，需区分裁剪、不可达内容与真实溢出。
5. 固定/最小宽总和超过窄窗时，应用选择最小尺寸、折叠栏或响应式组合；不要期待 grow 自动消除固定约束。
6. 文字省略只改呈现，保留完整业务值；使用受限宽度、textMaxLines/textOverflow 的同版入口。
   alignX/alignY 定位节点，不表示按钮内部文字对齐。隐藏的面板不留无目的固定高空节点。

完成后从正常窗口连续缩放、滚动、输入，核对底栏/操作仍可见且可用。
诊断只能给几何/接受事实，不能单凭布局矩形宣称最终像素或性能达标。

## 主题与完整状态

选择同版公开主题，使用语义角色：导航、资料行、主/次/弱操作、输入、表面、说明与反馈。
同版提供 `boundStyle()` 时整组应用基础样式和交互态，避免只换 normal 色值。
几何密度按公开覆盖参数调整，颜色集中在主题/命名定义中。

owner 只提供其允许的业务状态（如 SELECTED/CHECKED）；焦点、hover、pressed 交给框架，
真正禁用使用 enabled，而非伪造 owner bits。导航选中与键盘焦点应可同时识别。
按任务核正常、选中/checked、键盘焦点、hover、按下、disabled，以及实际会出现的错误/空/加载/成功反馈。
不必为应用从未使用的状态发明业务流程；不能仅凭颜色声明已验交互。

生成式界面复用同一 catalog 的命名角色与 owner，注册和更新使用同版公开方法；
重复 register 不等于切换主题，未知样式被拒时保留旧 accepted 界面。
若排查最终是遗漏 stretch 等接入错误，仍记录为什么容易误解、配方是否好找及诊断改进建议。

## 显示判断依据

[显示质量审查](diagnostics.md#显示质量审查只读)按证据类型逐项判断，不设统一美学规则：

- 裁字：同一 accepted 版本的文字行框、可绘区域、有效 clip、overflow 策略与最终像素互相印证；
  几何缺这些字段时写 unknown 并按[反馈指南](feedback.md)记录诊断缺口，不单凭节点矩形或业务值完整下结论。
- 遮挡：矩形只是线索，还需最终像素与必要命中证据。
- 控件不可达：由真实键盘/指针路径证明，不能只凭屏幕外几何断言。
- 对齐、间距、状态辨识：按控件用途、同版角色配方与同用途成熟参考判断。按钮标签要实际测量
  标签在按钮盒内的左右余量，与该角色的配方预期核对，不凭整体印象断言居中或偏移；
  命令/动作类角色与列表行、表单标签的对齐预期可以不同，不规定所有文字居中。
- 留白、密度、层次：结合整窗、内容状态与设计意图给出理由，不按空白面积比例直接判错。

合理留白、正确左对齐、显式省略（完整业务值保留）与滚动边缘半行属正常对照，不得报成缺陷；
把疑似排除为正常对照时写出排除依据。确认与疑似分列，依据不足的只写疑似并列出所缺证据。

参照从简：HIG 与同版本 AppKit 实例可作 macOS 布局、控件角色与交互参照；ArkUI 可参考组件组织、
文本对齐、行高与自适应表达，不移植其像素值；HTML 不是天然正确答案。确需对照样例时只做少量
同用途、同文字、同尺寸、同主题样例，记录系统/实现版本、语言、字体回退、backing scale、主题与
控件状态；参考样例自身也要验收，不建庞大参考库。
