## 必须完成的体验

从正常包消费的 macOS 配置窗口开始，展示规则标签、启用状态、保留份数、排除类型。
人选择一个字段并修改内容，还没点“应用”；已授权 Agent 从公开接口读取当前草稿、正在编辑的字段、已应用配置以及必要版本信息。
Agent 根据自然语言要求修改另一个获授权字段，窗口及时更新，人的未应用编辑和输入位置得到保留。
人继续编辑，再应用有效草稿。窗口、领域状态和外部读回一致；非法值、取消、旧请求与并发变化分别有明确结果。
同一字段已被人更新时，旧 Agent 请求不能覆盖；已应用配置发生变化后，基于旧配置的草稿也不能被人的“应用”按钮静默写回。

这里的“应用”指更新当前运行中的配置。除非样例确实实现了应用自己拥有的文件保存，否则界面和报告不能写成已保存到磁盘。

## 一次完成的代码交付

### 1. 可复用的基础表单组件与绑定

- 提供本阶段所需的标签、单行文本输入、整数编辑、布尔开关、操作按钮和字段错误提示。应用开发者显式组合界面和绑定，不要求自动把全部动作描述生成表单。
- 字段以稳定身份关联应用内容和动作。业务名称、保留份数范围、排除类型等由消费者定义，不能进入 renderer 或通用连接的业务分支。
- 保持仓颉核心、自绘与窄 macOS 桥接路线。布局/字段绑定/业务校验保持清楚归属；native 只承担必要绘制、文字测量、平台输入和生命周期，不接管领域状态。
- 完成实际焦点切换、键盘编辑、删除、基础选区和粘贴，足以编辑数字及中文标签。整数输入必须容纳输入过程中的空文本/暂时非法文本，不能每键都强制还原为旧整数。
- 中文至少实际验证 Unicode 粘贴、显示、删除与选区边界；按本阶段真实输入需要实现基本输入法接入，不要求完整多行富文本编辑器。组合输入与已进入草稿的文本要有明确边界，不伪称完整 IME 已支持。
- 外部修改其他字段不能重置当前焦点、光标或清空正在输入的文本；字段删除/窗口关闭等生命周期事件要明确清理绑定与资源。

### 2. 同一份可读取、可修改的编辑状态

- 明确已应用配置、当前草稿、草稿基于的配置版本、草稿版本、当前字段及必要选区/校验状态。它们是职责不同的状态，不是两份争夺同一事实的业务数据库。
- 可复用编辑状态由明确仓颉模块持有，窗口与外部上下文从它读。不得把真实草稿只藏在 native 文本缓存，外部接口却返回旧配置。
- 人类字段输入和外部草稿修改汇入同一实际编辑实现；领域“应用”仍进入应用拥有的 handler。新的 trusted human 入口不能成为绕过旧草稿冲突检查的捷径。
- 有效草稿原子应用；非法字段给具体错误，保留用户原始输入且不污染已应用配置。取消/重新载入的语义由样例明确展示。
- 基础焦点/光标变化不应让无关字段修改无理由失败；至少区分编辑上下文变化与内容修改的版本意义。无需实现 CRDT、自动文本合并或分布式事务。
- 碰到过期内容明确拒绝并允许重读，不能默默覆盖；拒绝时保留双方已有工作，不自动丢弃草稿或重新提交。

### 3. 通过既有共同操作契约接入外部系统

- 复用 shared_operation_core 的公开资源/动作/参数/结果契约、私有 descriptor 和通用客户端，补足实际需要的上下文字段和版本信息。
- 外部调用能区分当前草稿与已应用值，读取相关字段和校验结果，修改明确获授权的草稿，再读取真实结果。
- 修改草稿和应用配置是不同动作；应用可以只授权 Agent 修改某些字段、把应用动作留给人。也必须允许应用显式授予外部应用动作，授权后正常执行，不固定成“AI 永远必须等人确认”。
- 读取与写入均按实际授权过滤。只获得某字段修改权限不能改其他字段；缺少应用权限不能借编辑动作提交整份配置；拒绝不得泄露未授权字段内容。
- 需要刷新时可使用已存在的有界读取和版本比较；不为本阶段另造订阅服务、事件总线或模型运行时。通用 transport/client 不增加备份规则或表单字段专属分支。

### 4. 一个正常窗口消费者和可无窗口运行的同源验收

- 将现有备份规则领域实现按需提取为该样例可复用的应用代码，由 GUI 与无窗口消费者共用，不把 BackupRuleDomain 搬进框架核心，也不复制两套领域状态与规则。
- 正常 app 包消费框架表单、共同编辑能力和既有核心包。窗口必须可以用可复现命令构建、签名、启动和关闭。
- 通过另一组字段定义/标签/校验规则或一个很小的独立消费者验证组件绑定复用，避免仅为四个备份字段硬编码布局和行为；不要求第二个完整 GUI 产品。
- shared_operation_core 保持不依赖 renderer/AppKit/Metal/FFI。草稿、校验、应用/取消、冲突和真实 socket 验收也必须可以不打开窗口运行。
- 保留 101 条列表的行为回归与现有两类消费者，必要迁移同步完成，不把过去的 integrated green 当作新代码的证明。

## 验收场景与证据

自动化验证至少覆盖：

- 人的真实编辑事件处理路径更新草稿；外部读取新草稿；外部修改另一字段后，人的未应用修改仍在。
- 空整数、非法范围、中文/选区/粘贴边界；失败保留输入，不修改已应用配置。
- 取消、有效应用、重复应用的明确结果；旧草稿对新配置的冲突保护。
- 人和外部交错修改同一字段，以及并发的应用/修改请求；版本检查与真正写入必须在正确的原子边界内。
- 只读、字段修改、应用动作三类授权，以及错误 capability、未知字段/动作、畸形/分片 frame。
- 两个独立进程通过公开接口完成编辑到应用的往返；普通库消费、实例隔离、正常关闭与重启清理。

至少一次真实独立 Agent 只获得 descriptor、通用客户端和自然语言目标，从实际上下文发现字段与动作，修改获授权草稿并读回。可以使用已有授权的 Codex Luna；不得给预写目标 ID/动作或完成脚本冒充 Agent 决策。另验证获准应用和未获准应用两种边界，测试与真实 Agent 轨迹分别标记。

图形环境可用时，完成当前正常 app 上的真实键盘/鼠标编辑、错误显示、外部修改反馈、人类接续、应用/取消、旧写冲突以及关闭清理，并留明确前后状态和画面证据。
程序化调用人类 handler 或 native probe 不能替代以上真实 GUI 验收。
