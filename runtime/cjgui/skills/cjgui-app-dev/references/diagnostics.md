# 诊断与正常应用验证

优先正常 runner 的具名报错和实际同版公开说明：导出包根 README；checkout 的
`FRAMEWORK/preview/MACOS_DEVELOPER_QUICKSTART.md`（路径映射见来源指南），以及
`FRAMEWORK/MACOS_APPLICATION_HOST.md`、`FRAMEWORK/README.md`（有的开发包是精简导航）。
Inspector 用法可从 `command_surface`/`mixed_form` 模板查得，无需先读 native 实现。

## 有界观察

- 打开应用已有的“开发：Inspector”只读副窗，或按同版模板显式接入。
  常态关闭；成本采样只在本次问题需要时开启，按已有生命周期关闭。
- 若版本提供 `diagnosticSnapshot`/layout overlay，按其签名读取有限节点，
  对零尺寸/屏幕外问题使用 includeNonVisible；检查 constraints、父区域、溢出、裁剪和交互态。
  分页保留 session 与 accepted version，过期重新取相关页，不把不同版本拼成一个场景。
- accepted scene、submitted frame、GPU completed frame 是不同事实；快照不等于最终呈现。
  未发布的计数/成本值保持未知，不能把 -1 当零；可见候选矩形也不等于无遮挡像素。
- 只读观察不试探执行命令、不写 owner。查布局不用启动模型、协作连接或后台采样。

## 已有公开连接

复用该版本 `shared_operation_core/client.py`、typed generated client 与应用 wrapper，
先看 `--help` 和本应用 README 的参数次序。`generated-capabilities` 的 SURFACE 描述协议，
SUPPORT 来自应用注册/准入，EVIDENCE 是该应用声明的交付证据；available、registered、verified 不可混用。
未列出的能力保持 unknown，不能写成整个 CJGUI 不支持。窗口诊断还需对应本连接存活的 target 与权限，
拒绝时不能静默转到另一窗口。descriptor 含会话凭据，不复制到反馈或报告。

## 显示质量审查（只读）

可见修改完成且受影响功能链验证后，必须再进行这一独立阶段；"能操作、owner 正确"不能直接推出"显示合格"。
审查只读：不改应用、不写 owner、不顺手修复新发现的问题。

1. 选本次受影响的代表状态，不跑无关矩阵：一张完整窗口；受影响文字/控件的必要局部；
   一个有判别力的变化（尺寸、长短内容、空态或主题，按本次修改面选其一）。
2. 实际查看这些图像（用可用的读图/显示能力），不是只保存截图。每项观察对应图像身份
   （路径或哈希）、查看区域和从中得到的结论；局部裁切注明来自哪张全窗。
3. 按[显示判断依据](layout-theme.md#显示判断依据)逐项核对：裁字、遮挡、可达性、对齐、间距与状态辨识。
   几何/诊断与最终像素互相印证；正常对照（合理留白、正确左对齐、显式省略、滚动边缘半行）不得报成缺陷。
4. 分开记录结论：功能是否通过；实际审查了哪些画面与状态；确认问题与疑似问题分列；哪些范围未检查。
   确认问题至少写位置、实际现象、判断依据、影响、证据和置信状态；依据不足的写疑似并列出所缺证据。
5. 白名单限制修复，不限制发现。白名单外问题记录现象与证据，未经复核和授权不扩修；
   值得保留的障碍按[反馈指南](feedback.md)入库。

诊断复用：先按实际依赖版本核对 Inspector、`diagnosticSnapshot` 与其他公开诊断实际提供什么。
缺少文字行框、可绘区域、有效 clip、overflow 策略或坐标代次时，明确写 unknown 并反馈诊断缺口；
不在技能内另造一套文字测量算法，不用旧状态几何配新状态像素。只有公开数据足够时才加少量自动检测，
且须用已知反例与正常对照分别验证；自动候选只是疑似，排除滚动边缘、显式省略等正常情形后才可写确认。

## 验证与停止条件

每次验证回答具体问题：改了什么，哪个身份的应用，用什么输入，实际 owner/文件与窗口结果是什么。
正常入口进行受影响的连续操作；真实按键、AX 赋值、Unicode 注入、系统候选提交分开标记。
编译或 stdout 不能代替可见反馈；模拟客户端不能标成真实模型消费。
UI 修改通常只需一次构建与对应短链；新失败先保原件再修，不重复无关整包门。
无法观察窗口/系统输入时保留具体未验边界，继续独立工作。

报告参考源、构建输入和运行实例的不同证据；附必要日志/读回，不上传业务正文。
将值得保留的阻碍送到 [反馈记录](feedback.md)，疑似框架缺陷先留复现，应用任务不擅自改框架。
