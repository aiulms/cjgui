# 本轮修复与验证原件（2026-10-06 返工）

## 1. pump(0)/pump(1) 零超时系统消息服务

- 反例 harness：`pump_zerotimeout_probe.c`（同线程、FIFO 空、PostQuitMessage 后对比）
- 修复前（renderer sha 6bb6dc61，lib 直跑）：
  `pump0 kind=0 status=0`（WM_QUIT 未被搬运）/ `pump1 kind=42 status=0`
- 修复后（renderer sha 56627473）：
  `pump0 kind=42 status=0`（已就界搬运）/ `pump1 kind=0 status=0`
- 修复点：`drain_ready_system_messages` 有界（≤256 条）搬运；`remaining==0` 路径不再提前返回。

## 2. pread 位置语义（cjgui_windows_posix_compat.c）

- 反例 harness：`pread_position_probe.c`（两偏移交错 + 共享句柄位置读）
- 修复前：`pos_after_pread1=8 / pos_after_pread2=4 / read_after_preads=4567` → `POSITION_BROKEN`
- 修复后：`pos_after_pread1=0 / pos_after_pread2=0 / read_after_preads=0123` → `POSITION_PRESERVED`
- 修复点：pread 保存当前位置 → seek → read → 恢复位置。

## 3. relay 准入（llc_wrapper.c v2 + pharos-windows-relay-build.ps1）

- v2 门控：bc/obj 双内容哈希（expect 文件）+ 捕获失败非零 + 不匹配非零（94/95/91）。
- 负控：不同 BC → 94（REJECT bc_mismatch）；缺 expect → 94；正控：真 BC → 0（INJECTED bc=5f3c10f8 obj=9b32ddac）。
- 正式入口端到端：`RELAY_OK bc=5f3c10f8 obj=9b32ddac`，`LLC_RESTORED sha=1ea68362…`（与 SDK 原版一致）。
- 隔离目录实验（PATH / CANGJIE_HOME / exe 路径 junction / bin 实体复制）均不能重定向 cjc 的 llc；
  cjc 用 SDK 绝对路径（`-V` 输出实证），故采用“构建期交换 + finally 校验恢复”。

## 5. SendInput 真实鼠标与几何（accept12 + click-test）

- 默认窗口（客户区逻辑 1100x780）下，模式按钮 node_rect=1082,10,64,28 **溢出布局右缘**
  （中心 frac=1.0127>1，默认裁剪 0..1100 把中心裁掉）：缝点击与 SendInput 点击均无事件。
- MoveWindow 到已验证几何（2640x1620，布局 1307x774，按钮 frac=0.852）后：
  SendInput 点击 `sent=2` 送达，`CJGUI_DBG45` 全条件通过（pv=2==sceneV=2, epoch=1, hit=114），
  但 up 事件（PRESS_END/ACTIVATE）未排水 → `PHAROS_MODE` 未出现。
  与打字同一类根因：场景重发布使旧版本事件被消费侧严格版本门拒绝；
  现行重盖只覆盖 28/51/52/33，不含 45/46/27（按压链）。
- 结论：验收需先 resize 到可用几何（并等场景稳定）；按压链的版本差由输入交接修复（A 项）统一解决。
