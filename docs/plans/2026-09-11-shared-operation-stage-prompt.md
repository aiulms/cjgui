### 阶段范围与做法

- 在 runtime/cjgui 内实现必要的基础显示、输入、实际业务动作、状态更新及最小外部读取/操作接口。
- 把可复用能力放在框架中；样例只定义记录内容与业务规则，通过正常包/库入口消费。
- 用同一对象身份和操作实现连接人的输入与外部请求。读取应包含当前选择与状态；修改要产生真实结果。
- 已授权目标内允许批量操作，包括视口外记录；已有有效授权不因弹窗或外部调用身份重复确认。
- 对过期请求做明确处理，不能静默覆盖人的新修改。内容完成与画面更新的证据分别记录。
- 选择一条最容易实际接入的外部连接，编码可替换；无需先造统一协议平台、模型运行时或聊天窗。
- 阶段内可自主选择文件组织、实验性消费接口、具体步骤和必要局部重构。无需逐函数/逐文件审批。
- 主要范围为 runtime/cjgui；可为兼容复用同步 labs/macos_bridge_smoke 的必要部分以及当前说明。
- runtime_state.cj、cjpm.toml 如为正常消费所必需，可最小调整并做影响检查与验证，不为绕开受保护文件而另造状态主线。
- 允许阶段所需的基础文字和交互；完整 IME、富文本、多平台、生成式 UI 和全仓清理不属于本阶段。
- 新的 native/FFI 能力要验证线程与生命周期，公共接口写清 experimental 稳定性。不改变仓颉核心和当前平台路线。

你可以先闭合人的操作，再接外部调用；这只是内部实施顺序，不需要为每步新建任务卡。
若旧脚本只检查退役审计文案，说明冲突并做适当调整；保留真实行为检查，禁止通过恢复包装链让旧检查变绿。

### 完成时必须展示的体验

1. 从可复现命令启动一个普通窗口应用，使用实际 CJGUI 库，不靠复制 wrapper 到临时 probe 冒充消费。
2. 人用鼠标或键盘完成选择与一次修改，窗口反映真实内容变化。
3. 独立外部客户端读取同一上下文，修改明确范围内的记录，应用内容与画面更新。
4. 人再次修改，外部读取新结果；至少复现一次过期请求并说明如何防止覆盖。
5. 至少一次真实模型或 Agent 在已有授权连接上完成同一路径的操作；明确模型、连接、结果和局限，不使用硬编码请求冒充模型选择。
6. 给下一位开发者最短运行说明；标记框架 API 稳定性及尚不支持的能力。

如果暂无可用的模型连接，先完成其余工作，只询问缺少的连接信息，保持该项未验收。
