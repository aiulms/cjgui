# 外部操作编码实验

更新：2026-09-11。状态：保留实验经验，编码方案未冻结。

## 历史观察及其限度

旧实验使用同一道复杂 UI 操作题比较 RPN、JSON 和 Lisp-style S-expression，参与模型为当时记录中的千问 3.5、DeepSeek-v4 轻量版、Gemini 3.1。
记录认为 S 表达式的显式结构有利于作用域与表达成本，RPN 风险较高；用户也反馈 S 表达式在当时任务中较快、较少出错。
这是有限任务上的探索与经验，不是本轮重新运行的 benchmark，不证明所有模型与应用都更适合 S 表达式。
原始说明与结论保留在 [实验快照](../archive/2026-09-11-direction-governance/docs--core--AI_ACTION_PROTOCOL_EXPERIMENT.before.md)。

## 当前选择原则

先定义对象、动作、参数、上下文、授权与结果，再选择编码。核心业务操作不能直接依赖某个字符串格式。
S 表达式、受 schema 约束的 JSON、工具调用等都可以成为适配方式；旧版“JSON 不作为默认首选”不再约束实现。
编码不能赋予额外权限，解析成功也不表示业务操作已成功。
若采用 S 表达式，仅解析需要的数据与动作结构，不因格式选择引入任意 eval、宏或通用脚本运行时。

## 怎样比较

在同一任务、同一模型与相同可用能力下比较：
- 完成率、错误目标/参数、作用域和版本错误。
- 总耗时、调用次数、输入输出成本，以及人的检查纠错成本。
- 批量修改、人的中途修改、失败恢复与真实应用接入成本。

不只比较指令字符串长度或一次输出是否语法正确。
新模型能力变化可以触发小范围复测，不需要重写框架或先建大型评测平台。
第一阶段可选最容易接通真实外部调用的一种编码，记录取舍即可；无需先证明全局最优。
