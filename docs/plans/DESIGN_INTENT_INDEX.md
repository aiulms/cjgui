# P1 设计意图导航索引

状态：docs-only / navigation aid / design intent index

## 文件定位

本文件是 `docs/plans/` 的设计意图导航入口，用来帮助后续执行者在历史计划文档膨胀后快速定位主题、owner、stop-line、canonical tail 和当前主线结论。

它不是 runtime truth，不替代 [GUI_TASK_TRACKER.md](/Users/jiangxuanyang/Desktop/cangjie/GUI_TASK_TRACKER.md)，也不替代具体的 manifest、preflight、closure review 或 execution card。遇到冲突时，当前状态仍以 tracker 与对应主题的最新原文为准。

## 使用流程

1. 新线程先读本索引的当前主题段和 [GUI_TASK_TRACKER.md](/Users/jiangxuanyang/Desktop/cangjie/GUI_TASK_TRACKER.md) 的最新状态，不默认全量追历史。
2. 只有当 next route、owner、truth 或 stop-line 不清楚时，再查对应 [topic-manifests](/Users/jiangxuanyang/Desktop/cangjie/docs/plans/topic-manifests/README.md)。
3. 只有遇到冲突、缺证据、硬边界或 blocker / recovery 时，才读取 topic manifest 指向的关键原文。
4. 若主题不存在，先按文档预算治理处理：普通推进可在 automation report 中记录延后同步；阶段包边界、硬边界或 blocker / recovery 应补充新的 topic manifest、把新主题接入已有 topic manifest 的维护备注，或说明暂缓理由。

本索引的“最新落点”段是压缩地图，不是逐条必读的任务队列。自动化线程默认只需要当前最新段、最近 report / compact manifest 和 current next route；旧段用于追溯证据，不用于限制当前窗口的工程推进量。

## 维护规则

- 新 manifest、milestone 或 branch closure 改变主题状态时，同步更新对应 topic manifest。
- 不移动、重命名或删除历史 plans，不要求后续执行者全量阅读 `docs/plans/`。
- 只维护主题级 summary，不复制长文全文，不把索引写成新的 runtime truth。
- 新增或修改 Markdown 继续使用中文正文和中文章节标题；英文只用于代码符号、文件路径、API 名称、工具命令和固定治理术语。
- 后续新增 `.cj` runtime owner 文件仍需保留文件头维护注释，覆盖 Owner / Truth / Stop-line / Same-shape Boundary Brake。
- 自动化推进必须遵守 [P1 自动化文档预算治理](/Users/jiangxuanyang/Desktop/cangjie/docs/plans/2026-05-17-p1-automation-documentation-budget-governance.md)：自动化窗口以工程阶段包为目标，普通推进只写 report，阶段边界写 compact manifest，硬边界才写完整封账包。
- 文档留痕必须保留，但默认压缩到阶段 report / compact manifest；不要把历史长链复制成新的 active 阻塞清单。

## 出口机制

普通 automation report 只做轻量出口记录，不要求单独生成出口文档。若阶段包、硬边界、blocker / recovery 或 milestone 改变主题当前状态、canonical tail / endpoint、owner file、default draft、runtime input、current truth、stop-line、Same-shape Boundary Brake、唯一 next opening、future radar / forbidden / deferred 结论、public allowlist、protected path policy 或 docs language / owner comment governance，先按 [P1 自动化文档预算治理](/Users/jiangxuanyang/Desktop/cangjie/docs/plans/2026-05-17-p1-automation-documentation-budget-governance.md) 处理：普通推进可延后到下一阶段包边界，阶段包边界、硬边界或 blocker / recovery 应同步对应 topic manifest，若暂缓则写清接续点。

阶段出口建议在 branch milestone manifest、long chain manifest stabilization、某条主线完成一个工程阶段包、`docs/plans/` 新增约 10 到 20 份普通 report、README / tracker / topic manifest next opening 不一致、执行 AI 重复发明已有设计、连续生成同构文档或用户明确感觉“文档太多、方向开始埋了”时，开 docs-only navigation reconciliation / compact manifest。

周期出口是软规则：高频推进期间每周、每完成一个工程阶段包，或每新增 10 到 20 份普通 report 做一次 docs-only reconciliation / compact manifest；低频维护时只在主题状态变化、导航滞后或用户要求时做。当前不是自动归类系统，topic manifest 仍由 AI / 人维护。

协议原文见 [P1 设计意图导航出口协议](/Users/jiangxuanyang/Desktop/cangjie/docs/plans/2026-05-06-p1-design-intent-navigation-exit-protocol.md)。
