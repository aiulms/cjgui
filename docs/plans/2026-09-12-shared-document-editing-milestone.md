## 完整交付

开发者可在普通仓颉窗口中嵌入可复用的多行纯文本文档组件。人输入、选择和滚动；外部系统直接读到当前文档、选区及必要片段，按已有授权执行版本化片段替换；窗口显示结果，人能继续编辑、撤销或保存。第二个无窗口消费者使用同一文档操作模块，说明它不依赖截图、鼠标或模型平台。

例如，人选中说明文档中的一段，外部系统从结构化上下文得知所指内容，将该段改写；另一段保持不变。若人已经修改过对应版本，旧请求应明确冲突；不能把补丁应用到另一篇文档。对已授权的屏外段落，可直接替换，不要求逐行滚动。

交付是框架的文档状态、可组合多行编辑与共享片段操作，样例仅用于消费验证。保持现有仓颉核心、自绘/Metal 和窄平台文字服务路线；本阶段以纯文本为边界，不展开富文本排版、Markdown 编辑产品、完整代码 IDE、聊天壳或分布式 OT/CRDT。

## 必要旧问题与新能力连续推进

### 1. 先修正输入快照与语义版本的对应，补独立消费验收

上轮新发现：[窗口 syncProjection](../../runtime/cjgui/src/composable_ui_window.cj) 在平铺画面等价、层级变化时递增 renderedScene.version 而不提交 native；pump 却仍用该版本严格 resolveInput，native 事件带的旧版本会被拒绝。现有 hierarchy 探针检查关系和 native 版本后即关闭，没有继续点按钮/编辑。

先补“层级-only 更新后真实事件仍进入原对象，真正过期/删除目标仍拒绝”的生产窗口回归，再修正输入快照与可读语义版本的职责。可以分别保存最后 native 输入快照与语义修订；不能简单删除版本校验或把所有旧事件接受。这阻塞依赖它的动态交互验收，但不阻塞纯文档模型等独立开发。

在合适时机准备真实 descriptor、公开客户端及自然语言目标，安排一个无实现历史上下文的独立验收 Agent，使用已允许的 Luna/Terra，验证既有表单发现/读改以及新增文档片段能力。不要预先给资源 ID、动作调用序列或源码答案；让它通过公开描述发现。它只做有限验收，不派生开发任务。脚本发现已通过不等于该项已完成；若桌面不可用，先验证无窗口文档路径，GUI 部分如实承接。

### 2. 可复用纯文本文档与编辑操作

提供明确的文档身份、内容、版本及 insert/delete/replace-range 操作；所有人类和外部编辑进入同一实际操作模块。声明位置单位、换行处理及 UTF-8/平台 UTF-16/组合字符之间的转换边界，避免拆坏中文、emoji 或组合字符。

文档内容版本与视图的焦点、选区、滚动分别管理。操作返回实际范围、结果版本和失败原因；旧版本、非法范围、只读/未授权、文档已关闭必须有确定结果。可先用严格版本冲突拒绝加重读，不要求自动并发合并。

提供有界撤销/重做，明确人的连续输入分组和外部替换如何进入历史。撤销不悄悄覆盖历史之后的其他工作；在当前严格顺序模型中给出可解释规则并验证即可。删除/替换后选区按明确规则调整，不能留下越界光标或转投另一文档。

文档模块不依赖 AppKit、Metal 或连接开启；范围、缓存和历史容量要明确，可先以中等文档作为目标，不预设 rope 等复杂结构。不要每改一个字符就复制多个真相副本或强迫外部读取全文。

### 3. 多行编辑组件接入正常窗口

开发者能将多行编辑器与现有按钮、标签、滚动容器组合，绑定不同文档；支持换行、基本键盘移动、跨行选择、粘贴/删除、滚动及窗口/字体改变后的继续编辑。画面文字、光标/选择、命中和系统输入服务使用一致的行片段/坐标信息，复用已有测量与缓存。

视口外文档内容仍存在；布局/绘制以可见范围及必要上下文工作，避免为每个字符生成一个组件或把整个文档拼入每个状态查询。提供一份普通文档窗口消费者，至少两个可切换或并列的独立文档实例验证绑定，防止排队输入、撤销与选区串文档。

正常输入服务可复用平台能力，但平台对象保持内部，文本变化必须回到仓颉文档操作；不能以整页专用原生编辑产品替代可组合框架入口。保留物理 IME 待验，程序化组合/Unicode 探针只标自身范围。

### 4. 外部可读选区、片段与真实替换

公开可发现的文档描述、内容版本、当前选区及其所依据版本；支持有界的范围读取、必要上下文片段与版本化替换。选区空、焦点离开、文档关闭、选择已过期时语义明确。外部读回的是正在编辑的内存文档，不是旧磁盘内容。

通过现有授权允许操作屏外片段，可将若干互不重叠替换作为一次明确的批次；验证原始版本、范围与冲突，成功/部分失败/原子失败的规则必须选定并说明，不伪造全部成功。GUI 更新按一次业务批次合并，不逐字符等待模型或重绘。

客户端能直接依据发现的参数与结果操作，失败后重读再提交；结构化内容不强绑 S 表达式或特定 Agent。新文档大内容不能无界塞进 WINDOW_FIELD_VALUE 或突破传输限制，必要正文由范围读取承载。范围/授权过滤、版本和当前视图的对应通过测试证明。

### 5. 普通使用、持久化与完整验收

普通文档窗口通过正常包依赖构建，可完全不启用外部连接；需要共同操作时显式启用已有连接。示例提供受控的本地 UTF-8 打开/保存/重开路径，只用任务临时文件验收。未保存编辑、外部文件变更或保存失败要有明确状态，复用已有保存原则，不扩建通用文件管理系统。

至少完成这些连贯场景：

- 人输入含中文、emoji、换行的文本并选择跨行片段；外部读出对应范围/版本，替换该片段；窗口反馈，人继续输入和撤销/重做，其他片段保持正确。
- 人在外部读后先修改文档；旧范围请求明确拒绝，重新读取后正确更新。切换两个文档、删除选区内容、关闭其中一个实例，旧操作不串对象。
- 长文档滚动/缩放字体/resize 后选择和行位置仍对应，已授权屏外批次无需滚动即可完成；纯查询不造成业务写入，更新次数与读回量有界。
- 正常包中的保存/重开得到同一文本；无窗口消费者执行同一模型操作；既有规则/通知的动态外观及人机接续至少补一轮完整验收。

先为上述真实缺陷/边界写有意义的回归，再实施验证，不逐 helper 重跑全套。按 AGENTS.md 做相关 native/FFI/公共契约影响检查、针对性测试、根包 build --skip-script 和必要包构建、声明扫描、git diff --check。给出普通开发者如何嵌入组件、选择是否接外部系统的简明入口。API 继续 experimental；发布、多平台与完整富文本不在本轮验收声明中。

## 交付报告（执行：2026-09-12）

本阶段已交付可复用的纯文本文档核心、多行可组合输入和两个消费者；它们共享同一文档/版本/授权操作路径，而不是由 AppKit 文本框或截图保存业务真相。

### 实现

- `shared_operation_core` 新增无平台 `CjguiTextDocument`、工作区与受控文件绑定：正文版本和 UTF-8 字节范围是文档事实；焦点、选区和上下文版本独立。严格拒绝过期版本、已关闭文档、未授权范围及 emoji/组合字符的内部边界；AppKit UTF-16 选区在进入文档前转换为 UTF-8 字节位置。撤销/重做历史有界，外部操作不越过人的历史边界。
- 共同操作协议提供 `READ_RANGE`，资源上下文只公布元数据、版本、位置单位和当前选区；正文只能经授权的有界范围读取。窗口选区明确输出 `WINDOW_SELECTION_POSITION_UNIT UTF16_CODE_UNIT`，避免与文档范围的 `UTF8_BYTE` 混淆。
- `composable_ui` 新增多行文本节点，native renderer 以内部 `NSTextView`/`NSScrollView` 提供换行、选择、键盘和滚动，仍把变化回送仓颉控制器。发现多行滚动代理接管后文字透明的真实缺陷后，补了 opacity 回归并修正两个代理均为可见状态。
- 普通窗口消费者 `examples/shared_document_window_app` 默认完全不启动外部连接；`--with-connection` 才公开私有 descriptor，`--file PATH` 提供受控 UTF-8 打开/原子保存/重开。无窗口的 `examples/shared_document_second_consumer` 使用同一文档模块，但只授予两个可编辑文档的范围能力。
- 层级-only 语义更新不再替换 native 输入快照；真实旧事件仍可映射到原节点，已删除目标仍会拒绝。随后补的选择事件揭示 probe FIFO 上界漏掉事件 `33`；先得到退出码 37，再只扩展测试侧允许边界并通过完整控制器链路。
