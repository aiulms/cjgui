# 架构判断的简短参考

更新：2026-09-11。当前定位以 [项目方向](GUI_PROJECT_DIRECTION.md) 为准。
本文件不是每轮开工流程，也不要求按某种哲学模型命名 runtime。

遇到设计取舍时回答：
- 人或外部系统因此能完成什么具体工作？
- 应用开发者是否可以自由决定体验，而无需接受固定聊天或 Agent 形态？
- 内容、选择和操作结果是否来自同一实际应用状态？
- 能否先用少量可用能力验证，再增加抽象？
- 是否减少了重复定义、重新解释上下文或人工检查成本？

“场与波”、治理分层及旧元逻辑循环可作历史研究，不是代码结构、类型名或新的审批要求。
业务模块可以分别持有状态；“同源”不要求一个全局 God Object。
