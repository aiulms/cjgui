## 以下工作包属于一个里程碑，完成后自动接续

### A. 先稳住实际输入与绘制路线

恢复框架自己的控件绘制、布局/绑定和输入状态归属，复用现有窗口/渲染平台桥。原生层可提供文字测量/绘制、系统输入法、剪贴板、无障碍和窗口等必要服务；平台输入代理可以保留，但不能把一套可见原生表单作为自绘框架的最终实现，也不能把应用字段名与业务规则塞进 native。

修复跨字段、文本到按钮、焦点切换和关闭等事件的顺序/生命周期。若合并连续文本事件，不能越过动作边界或混合不同目标；任何有界队列的满载处理都不能静默丢失已接受编辑。
完成基础中文输入/粘贴、删除和选区，包含多字节字符及代理对/组合字符的边界；输入法组合态与已进入草稿的文本保持清楚区分。保留真实 macOS 输入支持，不需要完整富文本编辑器。

### B. 组合成可反复使用的列表与详情窗口

提供当前应用所需的可复用列表/选择、滚动、文本/整数/布尔编辑、按钮、错误与保存状态提示以及最小布局组合能力。一个正常窗口中能切换记录并编辑详情；需要更多字段/记录时应通过布局和视口处理，不把 native 的八个槽当作应用数据上限。

应用通过公共 API 定义字段、操作、布局和绑定。更换字段组合、名称或业务约束不应要求修改 renderer/通用 transport。公共组件不是专供四个备份字段的界面；不要求先做全部通用 widget 或任意 schema 自动生成界面。

### C. 完整记录与草稿生命周期

同一份领域状态支持新增、复制、重命名、编辑、删除记录，及列表选择、简单筛选。动态对象具有持久稳定 ID；在重排、筛选、删除、重新打开后都不会把旧请求指向另一条对象。
切换记录不能悄悄丢弃未应用草稿；应用要明确保留、应用或放弃的行为，并让外部系统读取相同上下文。领域校验失败保留原输入且不污染已应用配置。
至少用 100 条记录验证当前选区、屏幕外对象和多条不同草稿。基础记录操作、批量动作和视图导航各有明确版本语义，不让滚动使无关内容请求失效。

### D. 文件保存、载入与重启接续

参考应用拥有带格式版本的规则集文件和存储适配；框架只提供通用消费/事件或必要的小型复用能力，不强迫所有应用采用一个数据库或文件格式。
正常支持打开、创建、保存、另存为，并在重启后恢复已保存内容与稳定 ID。草稿的恢复/未保存关闭处理有可理解的说明与动作；不要把“应用到内存”“保存成功”“可恢复草稿”混成一个状态。
写入失败、无效/截断文件、格式不支持和磁盘文件被其他实例改动时，不能伪报成功或损坏原文件。使用实际失败路径验证原子保存/读回边界；保存前处理外部文件变化，不能盲目覆盖。
测试只使用本任务拥有的临时数据，不修改用户真实备份配置或不相关工作文件。正常 app 对用户明确打开/选择的文件执行对应操作。

### E. 人与 Agent 共用可恢复的业务操作

让记录创建与修改均可被外部智能系统调用；通过自然语言任务由真实 Agent 生成一组规则或字段内容，并在授权范围内批量更新，包含不可见记录。通用客户端不得为业务动作新增硬编码分支。
有效授权可分别覆盖读取、草稿修改、应用、记录管理及文件保存；权限范围不足的动作拒绝，已有有效授权不因弹窗或 AI 身份重复确认。对象/字段授权也约束撤销与批量操作。
用户及 Agent 的修改走同一实际命令入口；提供有限、明确的撤销/重做以恢复本地内容误改。它是当前内容操作历史，不承担真实外部副作用回滚，也不要求重启后保存全部历史。撤销面对新版本时不能覆盖其他调用者的后续修改。
处理重复请求与批量失败：至少在明确支持的会话边界内，同一修改/创建请求重试不会重复生成记录或翻转结果；断开连接后的结果未知必须能通过读回确认。说明重启后的保证边界，不假造全局 exactly-once。

### F. 低成本获取当前上下文与变化

对外同时提供需要时的快照/范围查询，以及有界的“自某个版本之后有哪些内容变化”。使外部系统在人的修改后可以获取相关变化，不必每次全量读取所有对象。
变化记录从实际领域提交产生，权限过滤涵盖新增、修改和删除；它不是第二份可独立写入的业务真相。游标过期/历史截断/实例重启时明确要求重新同步，不能返回空变化冒充没有修改。
焦点、选择与内容提交区分表达；不为每次击键调用模型，也不为了增量读取建消息平台、无限日志或分布式协作系统。

### G. 开发者能实际消费与复现

提供一个正常包消费的参考 app、一条无窗口全链验证入口、一条正常 GUI 构建/运行入口和简短开发者指南。
由一个只依赖公开 API 的独立消费者使用不同字段/约束跑通创建、读取、修改及结果获取，证明复用不是复制备份领域实现；该消费者无需另做完整产品。
保持 core/transport 与不需要桌面的编辑/存储验证不依赖 renderer/AppKit/Metal/FFI。公共 API 保持 experimental，必要迁移说明集中写明；不保留两条独立的业务执行主线。
无需为了“预览”发版、推送或上传；本地构建产物与最短复现步骤即可。

## 统一收官场景

使用普通构建产物，从一个新规则文件开始：人新增并编辑记录，暂留草稿；独立 Agent 仅凭 descriptor、通用客户端和自然语言目标发现当前内容，生成/批改获授权记录；人看到结果并接续，撤销一次误改，再保存文件。关闭后重开，记录、稳定 ID 和已保存结果正确；再次连接的 Agent 读取恢复内容并继续工作。

在同一参考应用中演示非法字段、旧版本、未授权对象、重复请求、失败保存和外部文件冲突的可恢复结果。单独展示变化读取相较全量读取返回了什么、何时需要重新同步；数字以实际调用和字节数为准，不做未经测量的性能承诺。

需要真实 GUI 输入的项目包括中文输入/粘贴/删除/选区、快速输入后应用/切换、列表与详情接续、外部更新投影、撤销/重做、保存/重开和关闭清理。程序化 handler 调用或 AX 值写入不能替代实际键盘/剪贴板路径；独立 socket/Agent 轨迹与 GUI 证据分别记录。

### 必须补齐的实现与复核点

1. **未保存关闭与普通文件操作。** `CJGuiInternalSession.windowShouldClose` 直接返回 YES，集合窗口收到关闭事件就销毁；README 明确写关闭未保存窗口丢弃内存内容。需让真正关闭发生在应用已处理草稿/未保存状态之后，提供保存、明确放弃、取消关闭或适用的恢复行为。普通用户能在窗口进行打开/新建/另存为，不能把启动时的 `--open`/`--save-as` 当完整文件操作 UI。已有授权的 Agent 可走对应动作，不因弹窗再索取同一授权。

2. **批量动作和撤销不能吞掉无关草稿。** `batchSetEnabledUnlocked` 对每个目标调用 `resetDraftUnlocked`，会重置正在编辑的其他字段；`restoreHistoryUnlocked` 只从已应用记录重建全部状态，也丢弃所有草稿/输入上下文。分别复现“人留着名称草稿，Agent 只批改启用”和“另一条记录有草稿，撤销当前操作”。保留未受本次动作影响的工作；受影响的草稿明确处理冲突，不能暗中回滚。

3. **对象身份与撤销变化。** 历史恢复把 `nextId` 一起回退，撤销新增后再新增可能复用原对象 ID；基于旧对象的授权不能因此命中新对象。`changedIdsForHistory` 在恢复后才读取旧/新集合，撤销新增等删除对象的变化可能被遗漏。保证身份不复用并从实际变更前后集合生成完整变化，验证删除/恢复/重做以及请求过期后的行为。

4. **授权覆盖实际影响范围。** 当前 UNDO/REDO 分支直接恢复全规则集，不能仅通过请求中一个获准目标的 scope 检查就允许影响其他对象。审查并验证撤销、重做、保存、批量/字段动作的实际影响集合；作用范围不足必须拒绝且不变更。界面原始行号与字段槽也不能在外部修改集合/切换记录后被重新解释为另一目标：以当时展示的稳定对象/上下文定位并验证，复现队列中的点击/编辑尚未消费时外部删除、选择变化的场景。

5. **重试不能伪报另一项操作成功。** 当前 `appliedRequestVersions` 只按 requestId 缓存版本且在动作内容校验前返回成功。相同请求可读回原结果；相同 ID 配不同动作、目标或参数必须冲突，不能返回 `already_applied_request` 冒充新请求成功。去重有明确作用域、容量/淘汰和打开另一文件后的边界；保持已约定的重启保证范围，不需要发明分布式执行系统。

6. **安全保存与重新同步。** 当前临时路径由目标路径与 version 拼接且直接写入；同版本的两个实例可能共用临时路径，清理也可能触及另一个写入。改为本次写操作拥有的独占临时文件，复核文件变更检查与替换的并发边界，验证失败不破坏原文件或另一实例的产物。`GET_CHANGES` 不能在重启/换文件但版本号恰好相同或变小时把旧游标解释成有效“无变化”；用明确实例/文档身份或等价机制要求重新同步，保持授权过滤。

7. **完成用户可用入口与实际独立消费。** 对照 B/C/G 检查复制、重命名、简单筛选、更多字段布局及运行/错误提示是否真正可达。当前 `rule_set_second_consumer` 直接实例化同一个规则集领域，只证明第二个进程消费该领域；补一个使用不同字段/约束的公开契约消费者，验证通用绑定/窗口契约复用。现有规则集上的创建/批量生成/保存重开也仍需本轮真实 Agent 决策轨迹，不能沿用旧单规则表单的 Agent 记录。

这些属于原里程碑的正确性、可用入口与验收补齐，不扩大到新产品、协议平台或完整控件库。先按风险安排复现和修复，再做最终统一集成验证；临时检查单可以很短，不新增一套治理卡。
