## 1. 本阶段真正要交付什么

一个开发者从 SDK 新建 mixed-form，打开空生成区，按文档调用公共客户端就能产生可操作界面；人在其中编辑，外部工具改变布局，双方继续使用同一 owner。随后人能在普通界面里打开、预览、保存、另存一份界面文件，正确看到未保存/文件冲突/候选结算；失败不会弄丢当前界面、草稿或文件。换到规则业务时复用这套实现，不再复制五个按钮、命令路由和文件状态。

这个目标有四个实物：**可直接用的生成入口、完整的公共文件操作组合、可重复挂载的作用域工作区、从同一 SDK 构建的两个正常消费者**。修复下面的旧问题只是起点。不要只交反例、改报告或再冻结一次包就停下；也不要为“任务大”新增不相关控件、另一套编辑器或后台服务。

首版仍欠运行时连续使用质量、普通性能和完整开发闭环。Sol 正在修调度/原始输入顺序/窗口恢复，本包让已具备的组件和运行时组合真正易接入。JPEG、原生全屏等需要平台实现的能力不在这条线顺手扩张；Linux 保持封存。完成本图不等于宣布首版成熟或 16/32ms 门通过。

## 3. 已确认的返工，不再重新猜因

### A1. 无变化被当成有变化

指导实际输出：

```text
CASE no_change preview=preview confirm=submitted submits=1 EXPECT submits=0
```

`cjguiUiDocumentDiffLines` 把无变化结果整理为“结构无变化”，`uiDocBuildPlan` 随后又调用 `uiDocDiffHasChanges`；后者把这行显示文字当成变更。结果是一次无用候选，破坏版本/dirty/无工作量语义。

修法：让“是否发生语义变化”来自结构化比较事实或既有完整规范化比较，显示行只负责展示。不要在这个 helper 里继续增加中文前缀白名单。定义和节点的顺序/值/绑定仍按正式语义比较；参数或元素顺序是否有意义沿当前契约，不擅自排序消掉差异。不要用未经转义的 `|` 拼串承担完整语义判等。

最小正反控：完全相同；只是编码规范化但语义相同；节点重排；定义参数/模板真实变化。前两者零 submit、结构版本不动，后两者产生正确 diff 并且一次提交。预览相同文件可更新“已读取此文件”事实，不以强刷场景达成。

### A2. 文件事实与接受事实混在一起

指导实际输出：

```text
CASE merge_saved reason=accepted current_matches_file=false unsaved=false EXPECT unsaved=true
CASE path_change unsaved=false old_saved_digest_retained=true EXPECT unsaved=true
```

merge 后 accepted 保留 A+B，磁盘文件只有 A；`finishReload` 却把完整 expected 摘要写成 savedDigest。之后界面显示“已与保存一致”。`setPath` 又把这份保存事实沿用到未写过的新文件。现有单测 `uiDocumentSessionAcceptsOnlyTheExpectedCompleteDocument` 断言了错误口径，必须修改这个断言并保留接受结果的正确断言。

固定三个事实，不再混写：

| 事实 | 谁产生 | 何时变化 |
| --- | --- | --- |
| 当前 accepted 文档/版本/摘要 | region/holder | 真正接受候选后 |
| 当前路径最近可靠读入/写入的文件内容及摘要 | 文件操作 | 成功读/原子保存后，且属于这个路径 |
| 本操作 candidate/expected/token | session | 本次预览和提交，直到结算 |

merge 成功只证明 expected 被接受，不证明磁盘已经保存 expected。只要当前完整文档与当前文件基线不一致，就有未保存界面变更；显式保存完整文档后才能变成一致。换路径不能继承旧文件的保存状态；保存失败不能切走原有效路径/基线。允许保留原路径作为“上次文件”展示，但不能用它伪装新路径已保存。

文件语义对照要包括：merge 保留定义、replace 完整恢复、保存后新路径、另存失败、同内容不同路径。正文/owner 草稿改变不能把 UI 文件标脏；布局或绑定改变会。无需建立无限文件历史或自动监听器。

### A3. 操作必须属于原 Surface，票据结算使用已有同锁事实

指导已经证明：在 A 预览后，传入同版本/同摘要的 B，`confirmReload(B)` 实际提交给 B。当前应用固定一个 workspace.surface，未证明现场串写，但这不是可重复挂载的正确公共契约。

会话/操作冻结原 Surface 及其必要生命周期身份。优先绑定构造时的对象与既有 session/generation 事实；兼容旧签名可在首次合法使用建立绑定，再拒绝不匹配者。未知/空身份不能当通配符。显式迁移到另一 Surface 必须先结清当前操作并建立新的基线，不能因为文档相同就悄悄改投。不要新建全局 owner 表或第二张 ticket 表。

`uiDocumentTicket` 已把 currentVersion/currentDigest 和票据放在同一 region 锁下返回；`finishReload` 应消费它，不能再额外读一次 accepted 并称为同一原子事实。核对返回 token、接受版本和冻结操作。已接受后被替代仍报告 accepted_then_changed；真正拒绝/退休/关闭要可见，不无限挂在“等待”。没有事实时保留 unknown，不能编造拒绝。`adoptAcceptedBaseline` 等启动入口也不得抹掉真实在途操作。

单 owner 调用契约明确；若 API 支持并发，检查和取得本次提交资格必须是一个受控状态转换，避免两个调用先后通过同一 idle 检查。不要为此引入线程、定时器或第二调度器。

## 4. B：修好正常生成入口，让目录真的能被直接消费

### B1. 公共图片注册漏口已有源码定位

正常 SDK mixed 空生成区的 `client.py generate` 返回 `unknown_property`，位置是 `preset-beacon/fixedHeight`。`CjguiGeneratedUiWorkspaceCatalog.registerInto(includeImage: true)` 只加入 imageContentProperties，漏掉 leafStyleProperties；底层 IMAGE 已消费 fixedHeight，既有 tabs 图像测试也把两组属性合在一起。

在公共注册责任点补齐真实支持的属性，沿同一 Presentation 的元数据派生，不在 mixed 私添一份属性表。不能删掉图片、删尺寸要求、放宽全局校验或换预种子文件绕过这个正常入口。未知属性、不可消费的属性类型、未发布资源仍具名拒绝。

### B2. 把公开目录到可用界面的路径收好

复用当前客户端和定义/实例编码，让普通入口读取 **本次真实** capabilities、字段、动作、可用资源和 CHOICE，再构建描述。布局方案可以由调用方选择；业务字段、规则、选项、可用性不能重复硬编码成另一套事实。

本包支持子集以已实现且应用选择发布的组件为准：普通布局/标签/动作、已发布字段呈现（含 Select/Slider）、图片、tabs/scroll/split、有限运行时组合。不是要求每个应用自动暴露所有底层组件，也不是按名字重新造 Table/Checkbox 等已有能力。

对正常生成用到的属性，在公共目录/校验/真实挂载三个点保持一致。必要时增加共享的“该呈现的内容属性＋可消费样式属性”组合入口，复用已有函数，不增加平行 schema。调用方要求一个未发布能力时应解释缺项；可选装饰只有在调用方明确允许降级时才可省略，不能静默丢掉用户要求再报成功。

从公开入口开始的真实链必须含一次空区初始化，不先用保存文件或私有 seed 填好。随后更新布局/属性、切换兼容字段呈现、定义一个具名组合并复用给两个不同 owner。每次只走既有候选/票据/CAS/原子结构读回；不借改布局顺手 Apply 业务，也不凭页面标题推断 owner。

测量这一条用途的收益：初次构建后运行期修改不再编译/重启；记录候选规模、接受耗时、已有 build/commit 计数及业务读回。不要把提交解析耗时称为物理呈现延迟，不新增性能仪表工程。

## 5. C：把文件操作从五个按钮做成可用的公共工作流

### C1. 普通用户能打开、另存和处理文件冲突

在原 workspace/session 上扩展，不建第二控制器。新增的最小公共操作是：

- **打开界面文件**：选择/输入路径 → 有界读取 → 与当前 accepted 比较 → 展示 merge/replace 及实际差异 → 确认 → 真实 ticket 结算 → 成功后采用相应文件关联。取消或拒绝保留旧界面、路径事实和业务草稿。
- **另存为**：把当前完整 accepted 文档原子写到新路径；成功才切换路径与保存基线；失败保持旧文件与关联。含空格/中文路径沿用创建脚本与文件层既有能力。
- **保存冲突**：外部改过当前文件时，默认保存不能无声覆盖。复用有界读取和摘要，提供“重新预览外部文件 / 另存 / 取消”的实际入口；如设计显式覆盖，必须来自该文件对应的一次明确用户决策，不以取消/重试冒充。错误原因在界面可见，用户仍能编辑。
- **恢复已存界面**：公开 replace 语义，预览能说明将删除的定义/实例。保留便捷入口可以，但有未保存内容时必须让用户知道将丢弃哪些界面变化；业务 dirty 继续独立。
- **空文档**：已有协议允许的合法空结构与“有定义、无实例”须分别处理。不能把所有无 NODE 文件直接视为损坏或自动当 v0 成功。需要清空时走显式预览/确认，保留外部重新初始化入口；不清业务数据。

建议沿已有 session 采用下面的操作顺序，避免把按钮状态当事务：

1. 打开 B 时，把 B 的路径、读取摘要和预览放进这次 operation；A 的当前路径/保存事实暂时不动。
2. 确认只提交这个 operation 的 candidate，并保存原 Surface/token；取消未提交的预览只销毁 operation。
3. 原 ticket 精确接受后，才将 B 作为当前文件关联。merge 的完整 accepted 若比 B 多定义，就关联 B 但 dirty=true，要求显式保存完整状态。
4. 若原票据被拒/替代，A 的关联保留；若 accepted_then_changed，默认也不自动把新当前状态标成 B 的保存态，显示原接受与随后变更，让调用方明确继续。不可由“最终正文碰巧相等”改判原票据。
5. 另存 C 时先取得当前完整 accepted 快照，按已存在的文件写入工具成功后再改关联。写入后 accepted 又变化，则 C 对应保存时快照，当前仍 dirty；不能用写入后的版本伪装文件也保存了新修改。
6. 预览同义文件的 no-op 可以确认采用该文件关联，但不提交候选、不推进结构版本；工作区确认文案应让人理解这只是文件关联。空预览/取消不改变路径。

这是现有 session 的操作记录和数据转换，不是要求照搬一组新的类名；业务 owner、结构 holder 与文件层的责任保持原样。

不要求本包新增 NSOpenPanel/NSSavePanel 桥。优先用已有可输入路径的公共 Dialog/表单完成正常可操作入口，应用可传入自己的路径选择器；文件对话框显示、焦点/取消仍走原 layer 生命周期。路径输入不意味着授权访问任意业务对象。

文件覆盖守卫要诚实：现有原子 rename 只保证文件替换完整，不自动提供跨进程“比较＋替换”的强 CAS。若仅使用读摘要后 rename，就把边界写清，不宣称任意竞态下绝对无丢更新。本包验证实际外改已发生时的具名拒绝和旧文件保留；不要为此新建文件锁服务。

### C2. 离开/关闭策略是可组合决策，应用保留最终业务决定

工作区公开当前 UI dirty/in-flight/文件问题的只读决策；消费者把它与原业务关闭策略组合。UI 文档已保存不能掩盖业务未保存，业务已保存也不能掩盖 UI 文档丢失。提交中的结构先结算或明确拒绝离开，不能清掉 token 后照常关闭。

最小体验：有未保存界面变更时，“保存并继续 / 放弃界面变更并继续 / 取消”是可达操作；取消零文件写、零结构提交。业务域自己的保存/放弃继续原路径；不让框架自动替应用执行 Apply。关闭拒绝的说明必须无需补一次点击/滚轮便可见；若实际 native 唤醒故障，交 Sol 精确小复现，其余工作继续。

这里是公共文档决策＋现有 Dialog/命令组合，不是框架接管所有窗口关闭或重写宿主。不修改 Sol 的原生事件路由。默认未挂载文档工作区的普通 ui-only 应用不多出文件状态、窗口或后台任务。

## 6. D：作用域身份与公共命令，降低第二次接入成本

现有 workspace 需要消费者分配 nodeBase、semanticPrefix、commandPrefix，mixed/rules 还分别循环 entries 造命令。下一层把这些共同接线收进原公共组合。

- 新增基于 IdentityScope / NodeReference 的挂载入口，保留 manual 构造器兼容。节点、状态区、对话框、动作和命令均有自己的局部 key；不让调用方再手工算 10 个整数，不把 nodeId 暴露到文件格式。
- 公共命令投影直接由 session/actionStates 派生 enabled/原因和路由目标。按钮、工具栏、命令面板/菜单消费同一命令事实。应用仍决定放在哪一页、哪些命令进入菜单、快捷键是否占用；不能夺走业务 ⌘S 或全窗重复注册。
- 同窗两个 workspace 的 action 不能都因 `UI_DOC_SAVE` 命中第一个实例。采用既有 scoped 命令/激活机制，传递真实工作区身份；未知、退休、别域的入口拒绝。不要新造动作注册器或新的事件总线。
- 状态/预览用已有布局、文本和滚动容器，长路径、中文原因、多项差异和窄窗均可达。确认/取消操作不因内容太长藏在屏外；只读 diff 不变成另一个代码编辑器。
- workspace 从场景移除/换绑时取消自己的未提交弹层；在途票据仍由原 Surface 结算，不由新实例接管。相同业务 owner 可以有多个视图，但文档 Surface/操作记录不能因为 owner 相同混用。

在一个已有消费者正常工作区里放两个可区分的工作区实例，分别绑定两个合法区域/文件；使用同一套公共组件。只需一个有业务意义的第二布局区域，例如主详情与辅助摘要，不复制两套打印业务、不增加第三款样例应用。验证打开/取消/保存 A 不动 B，布局交换后身份仍对，A 移除后旧操作不写 B。另一业务再正常接入一套，以证明不同 domain 可复用。

交付说明列实际剩下的应用接线：区域、业务规则、路径选择、菜单位置、最终关闭策略；具体删除了哪些重复循环/状态分支。不要用“代码少了百分之多少”代替可复用事实，也不为了减少行数做无关重构。

## 7. E：两个正常消费者的完整用途

### E1. mixed：从空区开始，人工和公开操作交接

### 10.2 第一段：修正语义比较与文件事实，封住数据损失入口

**A. 真实语义不能由显示文案判定。**

已复现：合法 CPARAM 默认值 `""` → `"空"`，摘要不同，diff 为空，确认零提交。`uiDocShortValue` 的显示替换经 `uiDocParameterFact` 进入 `uiDocDefinitionSignature`，所以改一条提示字符串不能修好。

采用类型化字段比较，或复用无损规范化后的完整语义；每个差异先是事实，之后才渲染文案。空串、缺失、字面“空”/“none”、中文与分隔符必须可区分；树的子顺序、属性、参数、模板、定义增删、绑定都不能因拼字符串撞值。已有 `cjguiUiDocumentDigest` 是结构原文字节摘要，不要直接把它改成语义摘要，也不要只靠原文字节不同就判断重排了格式的文件有语义变化。旧同义文件零提交、merge 保留定义、replace 删除继续成立。

**B. 所有写文件入口使用一致的保护事实。**

已复现：普通 `save` 拒绝外改后，`saveAs` 同路径立即覆盖外部内容。修复不止比较两个路径字符串：当前路径、别名路径、未关联但已存在的目标都不能因保存基线为空获得无条件覆盖权。

优先选择本包可完成的简单策略：另存到不存在的新文件；另存当前文件走同一保存冲突检查；目标已存在且没有可信观察事实时具名拒绝，提供换名或重新打开预览。这样无需本包增加“强制覆盖”功能。若保留显式覆盖，则必须绑定这次真实观察的路径/文件身份/内容和一次明确用户选择，文件再变则拒绝；不能加默认 `force=true`，不能把第二次点击、取消后重试当同意。

文件观察摘要和 UI 语义摘要职责不同。现有 `fileDigest`/文档格式的公开语义不能偷换；如需记录文件字节观察，放在既有操作记录里，避免外部只改元数据/格式却被无声覆盖。路径解析沿平台现有文件能力，至少覆盖当前路径及正常可解析的别名、含空格/中文的新路径；判断不了时保守拒绝，不能猜成新文件。

保持临时文件＋原子替换的正常失败清理。**预读摘要＋rename 不是对任意外部进程的原子 CAS**，要如实说明协作边界；不以延时、循环重读或文件监视器宣称消除了竞态。已有目标、新建目标的发布应选现有文件 API 能提供的最强不覆盖语义，失败保持原文件。

**C. 文件关联按原操作结算。**

打开 B 只创建 B 的预览，A 关联暂留；取消/拒绝/替代保留 A。`accepted_then_changed` 本次明确也保留原 A 关联及其真实文件基线，展示“该票据曾接受、当前已进一步变化”，当前 dirty 按事实派生；用户后续可重新打开 B 或另存 C。不要切到 B 再清空基线，使下一次保存无条件覆盖 B。

`finishReload` 还须核对返回 ticket token 与被冻结提交相符，继续使用同锁 currentVersion/currentDigest，不添加第二次独立读回。Surface 身份仍必须冻结；自定义 Surface 的默认 0 会拒绝操作，须明确如何给每实例分配稳定非零身份，不让所有适配器硬编码同一个数。旧正常 provider 不回退到单 owner。

### 10.4 第三段：从普通空白窗口接通打开、另存与关闭保护

**没有 path 也必须能开始。** mixed 当前把整个 workspace/路径输入/打开/另存放在 `hasPath()` 内，只有预先传 CLI SAVE_TARGET 才能使用。移除这个产品入口依赖；无路径时显示“尚未保存”，保存引导到路径选择/另存，打开始终可达。不要随便赋一个隐藏默认路径假装解决。未改变的空 v0 可以正常关闭；初始化或真实结构修改后，未保存状态必须可见。

公共文件 UI 沿已有表单/Dialog/Popover。至少接通：输入/选路径、打开后 merge/replace 预览、确认、取消、保存、新路径另存、冲突后重新预览/换名/取消。错误和文件路径要在窄窗中可见，确认/取消可到达，操作失败后还能继续编辑。rules 复用同一公共组合，业务文件与 UI 文件有清楚名称，不能只把启动加载参数当打开按钮。

**关闭保护在现有消费者接口组合，不转派给 Sol。** mixed 现在 `requestWindowClose` 无条件 true，rules 只询问业务。把文档 `closeDecision` 组合到两者已有关闭路径，系统关闭按钮、⌘W、⌘Q 结果一致：

- 无未保存 UI、无预览/提交时，再遵循应用原业务关闭策略。
- 未保存 UI 提供“保存界面 / 放弃本次界面改动并关闭 / 取消关闭”；无路径先走另存。界面保存不能自动 Apply/保存业务草稿，放弃 UI 也不能放弃业务内容。
- 未提交预览可取消预览，仍按真实当前 UI 的 dirty 决定；在途 ticket 不能假装取消回滚或直接退出，沿原结算完成后重新判断，用户可取消关闭意图继续使用。不要加轮询计时器/第二套票据状态机。
- 多个 workspace 的未保存/在途事实都须检查，不能只顾第一个。用户的决定绑定到实际文档状态；等待中又有外部更新，不能拿旧“保存成功”关闭新 dirty 文档。
- 拒绝/提示必须由正常刷新途径立即可见，消费方在必要处调用既有 requestRefresh；不能靠额外点击、外部唤醒或重发验证。只有证据指向窄运行时问题时才交 Sol。

这里允许薄的关闭意图协调和通用提示组合，禁止重造文件/业务 owner、候选结算或 native 窗口生命周期。先把 shared 逻辑写好，再由两个消费者调用，避免一边修一边各复制一份完整流程。

### 10.5 第四段：在两个真实区域和第二业务中把完整用途跑通

在 mixed 中挂两个可区分的正常工作区，例如“主详情布局”和“辅助摘要布局”，各有自己的真实 region/Surface、session、文件关联；业务仍可复用已有 owner。不是创建第三个演示应用，不要把同一个 Surface 的两个别名充作隔离。区域如何被外部操作寻址复用现有生成工作区/公开注册，不另设私有协议。

把原 E1 合成一条最终同源链，按可观察状态逐步驱动：

1. SDK 新建、无 UI 文件参数启动，从正常公开 generate 建主区域；人工可编辑字段与实例 Select。保留原有效图像、A/B 不同 owner，不靠 seed 替代空区入口。

3. 从可见界面给区域一另存新文件；修改后 dirty。打开另一文件，预览取消保旧；再确认并结算。区域二的 accepted 摘要、路径、保存事实和业务草稿不受影响。

6. 未保存 UI 时发出真实关闭请求，看见提示且进程存活；取消后继续编辑。再保存/另存并正常关闭。以保存文件重开，结构/定义/实例与文件一致，再编辑并正常关闭。

rules 完成原 E2 的本业务用途：可达的非空详情、实例编辑/Select、通过公共 workspace 打开→预览→取消→确认→另存；业务保存与 UI 保存各自读回；仅 UI dirty、仅业务 dirty 两种关闭情况都能解释且可继续，保存后正常关闭，重开核对。退休对象的旧入口具名拒绝保留旧证据并只补受影响部分。不新增不存在的锁业务。

### 11.2 A：收好无损预览与正常文本入口

**A1 已复现的 Unicode 展示异常。** 机器事实的长度前缀编码保持；不要回到显示字符串参与语义相等。修 `uiDocDisplayValue`/`uiDocShort` 的任意 12 字节切片。公共 `cjguiUiDocumentDiffLines` 对合法 `A中文测试`→`B中文测试` 必须不抛异常，并给出可理解的变化。还要覆盖同一长前缀、尾部不同的值，不能把两边都显示成完全相同的 12 字节而没有省略/差异说明。

过程建议：

1. 复用现有合法 UTF-8/字符串缩略工具，若没有，在文档展示层做有界且合法的摘要。比较始终用完整类型化原值。
2. 机器摘要、完整候选、before/after 事实和展示摘要分清。长值可缩略，但需显示发生省略、长度/摘要等区分事实，且调用者能读完整差异；不要只让人比较两个 SHA 来决定修改了什么。
3. 一个定向测试组涵盖空/字面空、混合 ASCII/CJK/emoji、长共同前缀和真正同义正控即可。沿用原事务反例，不重跑全部 248 项 Python 或两个应用历史矩阵。

**A2 原速路径键入。** 当前证据只证明 30ms/字符 HID 成功；同一次换工具和改速度不能证明原 AppleScript 丢字是工具问题。不要把 30ms 写为产品要求，也不补点击、重发、加 sleep 保通过。

先复用无文件参数的 rules 自有实例，以原长串和绑定到正确 PID 的合法输入作区分：记录发送原文/事件身份、native 实际收到的文本、公共事件顺序与文本、消费者路径草稿、最后 accepted/AX 值。可以只加有界条件日志，不能改处理顺序。不要因日志里叫 scoped 就先归因 scope，也不要把某次源事件根本没投递当作产品丢字。

- 若原通道未投递：保留零投递依据，用已正确投递的通道在**不额外放慢**的条件下复验。
- 若 native 收齐、消费者没收齐：定位公共派发/FIFO/绑定代次；若在 Sol 写集，集中交付最短原序列、源码/二进制/实际 native 归档身份与 first-divergence，独立工作继续。别自己改 native 或先换一份 WIP 碰运气。

- 路径草稿与已经关联的文件是两个事实。逐键更改路径草稿不能自动换关联/保存基线；若避免逐键整场布局，按钮可用性、语义最终值和调用读取仍需正确。

### 11.3 B：把集合从“单例视图”接成可重复挂载的公共组件

这是本包新增能力的主体。不要只在 demo 里 new 两份数据源、改两个字符串，然后宣布公共多挂载完成。

**B1 先画清两个不同的归属。**

| 事实 | 继续归谁 |
| --- | --- |
| 项目稳定 key、业务资源、字段/草稿/动作、权限 | 原应用数据源/owner，不能复制成每个视图自己的业务真相 |
| 选择、过滤、排序是否共享 | 沿应用的显式声明；不能为了隔离滚动偷偷复制或重置它们 |
| viewport、可见范围、变高测量、滚动锚、reveal 目标 | 每个实际挂载自己的视图状态 |
| 节点身份、实例代次、接受/拒绝/移除 | 既有 holder/accepted 绑定事务 |

当前类的 `viewport`、`lastRowsSource` 都是集合对象单例；`buildNode` 在候选构建时覆盖后者。先把它们的用途移到恰当的挂载状态中，而不是在旧字段外再加一个竞争的“当前视图”。

**B2 挂载主键必须能区分三个反例。**

1. 同一数据源在区域 A、B 各呈现一次；
2. 同一区域内，两个不同 instance key 呈现同一 collection；
3. 移除后重加/改绑同 key，旧句柄不能操作新的挂载。

建议沿现有绑定使用“真实 holder/Surface 身份 + canonical instance identity + accepted incarnation”来取得有界视图状态；不要用构造器计数、数组位置、截短语义 id、仅 root scope 名称，或最后一次 build 的对象作为主键。数据行身份再附稳定 row key，表头及各列也位于该挂载域内。当前 `holderScope` 可作为来源之一，但它单独不能区分同一区域两实例。

**B3 发布与退役跟原事务走。**

- 构建时可以准备候选挂载，不能提前把 accepted 的 source/viewport/reveal 目标换掉。
- commit 发布本候选真正存活的挂载与其表示；reject/rollback 丢掉本候选新增的暂态，旧 accepted 视图继续可用。
- 合法重排同一实例保留其滚动/测量状态和合法选择；删除/换绑退休原句柄，旧 reveal/滚动/动作零副作用，新挂载可操作。
- 复用现有 composite/instance 表和 holder 生命周期；不要建立第二个拥有业务数据或选择的全局注册器。若需在 holder 增加窄的 mount-state 钩子，给它明确的 candidate/accepted 所有权与清理点，一次接好所有路径，不留永久 map 项。
- 普通 build 不产生用户滚动、不改选择、不用补刷新制造接受。沿原 viewport 的 stage/commit/rollback 更新几何。

**B4 身份不能只修数据行。** 当前 `buildRow` 表头提前返回，必须让 header、column controls、data rows 及其子节点都走一致的挂载限定；检查局部引用随身份一起解析。区分内部引用与确有意指向外部对象的引用，不一律改写所有 NodeReference。旧手写单挂载不变；没有足够身份信息的 manual 复用可以具名拒绝，不能偷偷重编号后错派业务。

**B5 定位使用真实变高机制。** `revealItem` 当前 `index * rowHeight` 只适合固定行高，而且读取最后 build 的 wrapper。改用既有 VariableHeightList 的稀疏累计几何/稳定 key reveal，或其已有 accepted geometry 接缝。list/table 表头占位、换行变高和窄窗都不能靠常数猜。

公开入口要能明确指定目标挂载。优先返回/解析一个由 accepted 实例授予的 view 句柄，再由该句柄 reveal；也可用同样受守卫的 scoped 重载，具体签名按现有 API 收敛。旧 `revealItem(key)` 的单挂载调用保持兼容；多挂载无目标时不能默默选最后一个或全部滚动。旧句柄退休返回具名结果/false，不重定向。

**B6 连续消费。** mixed 注册同一真实集合一次，呈现一个列表和一个表格，接在两个真实工作区或同一区域两个实例上。它们共用同一 owner/选择声明，滚动位置独立；只在目标视图 reveal。通过现有运行时编辑把其中一个表示换成 table/list、重排、删除再恢复，未影响的视图仍可操作，业务草稿不变。第二业务 rules 只补一个最小真实挂载消费，避免复制打印规则或扩第三业务。布局改版只提交结构，不重启应用。

最小反例集中覆盖：表头/行身份、同区域双实例、viewport 独立、候选拒绝保旧、合法重排保持、删除/重加旧句柄退休、变高 reveal。测试必须断言真实挂载结果/accepted offset 或命中，不只比两个 scope 字符串。

### 11.4 C：无参数与关闭路径按真实状态收口

**C1 先改正旧归因。** typed-path 的打开前 AX 已经显示 `component_not_implemented`，日志还出现非空记录才会触发的 seed。先在这一原序列里核对：初始业务记录、什么时候新增、default seed 的候选内容/票据与失败原因。不要先改 preview，或把已存在的拒绝标签当成本次打开引起的。

- 第一条真实记录创建后，既有正常生成入口要能使用当时 catalog/instance facts 创建有效详情。失败应显示实际原因，修正可用条件后能够继续，不让一次尝试把应用永久锁在旧失败状态。

规则业务文件和 UI 文档各用本轮可写副本，绝不再把历史证据文件当保存目标。UI 文件与业务文件的语义/摘要/保存动作明确分开。

## 12. 下一整包：可事务化的集合挂载与公共集合工作区

### 12.1 目的、最终体验与边界

这包要交付的能力是：**一份集合数据和业务操作声明，可以在手写与运行时界面中安全地重复呈现；视图能独立滚动、定位、卸载和重挂，配置能通过已有公共快照保存恢复。开发者复用一套集合工作区接入，普通用户可以从空应用开始建数据、编辑界面、保存并正常重开。**

“独立视图”先明确责任：记录、字段、草稿、Apply/Cancel 和业务选择归既有 owner；每个挂载拥有 viewport、测量/物化缓存、局部焦点和 reveal 目标。筛选、排序、列配置沿用现有 TableSource/CollectionViewState 的共享范围，本包不暗中把它们改成两份相互冲突的业务状态。若 API 为同一状态提供两个入口，两处应投影同一事实；若调用方显式提供不同视图状态，才分别作用。文档必须说清这种区别。

归属仍为 DS 的 generated/collection/table/文档/workspace/客户端/消费者/exporter。Sol 的 window/native/host/budget/FFI/调度正在推进，不并写、不冻结在途源。Linux 与 C 不恢复，不开代理、顾问或新线程。不扩 JPEG/SVG、全平台、完整 VO/IME、脚本引擎或第二套运行时。

### 12.3 A：把挂载接入真实接受事务

**问题不是再补一遍 `acceptedSceneKeys`。** 目前 `acceptedBuild=true` 只是构建路径的参数，工厂可能先发布/退休，整个 render 随后失败；最后一个实例消失又没有工厂调用来清理。候选的新 key 还可能长留在工厂表中。要修职责位置。

先用真实 `CjguiGeneratedUiHolder` 及既有公共候选流程保存最小 RED，再修改。测试不可手工把 context 的 accepted 设为 true 来代替提交。最少包括：

1. 接受唯一 collection → 提交不含它的合法结构 → 不再调用该工厂，也不额外 buildAccepted → 旧 view retired、accepted lookup 为空、旧 reveal 无效。
2. 同 key 换另一种工厂、整区域释放，旧 collection 也退休；共享同一数据源的另一区域仍工作。
3. 已接受 A → 构建 B 后拒绝/rollback，A 的句柄、offset、查询得到的几何和可操作性不变。重复少量不同新 key 的被拒候选，暂存归零，不按历史次数增长。
4. commit 结束立即可查询新 accepted view；不依赖下一次 build 才发布。兼容重排保持旧有效 view；不兼容换绑产生新代次。
5. 渲染后段失败时，前面工厂的构建不能先退休 accepted view。用可控的后续非法子节点/registry 失败区分这条路径。

实施建议：

- 优先把 mount 生命周期放入 holder 现有接受事务，或增加一个只服务于视图状态的内部参与接口。暂存、发布、回滚、释放各有唯一责任点；不要另造票据或第二套 scene 状态机。
- mount 身份来自真实 holder/Surface 归属 + 完整实例 key + 框架接受代次；仅 canonical scope 字符串、数组下标或“最后构建实例”不足以表示不同 holder 的归属。实际 scoped 节点身份仍沿用现有 IdentityScope。
- candidate 可准备新对象，但 accepted lookup 只能见已发布对象。复用同代对象时，候选的声明、rows/几何等变更也须可丢弃；浅拷贝 map 后继续改共享对象不等于回滚。
- commit 根据整个接受结构对账，必须覆盖空集合、零实例与 kind 替换；发布新表与退休旧表在同一合法时点完成。rollback 只清自己的暂存；dispose 只清自己的 holder；重复释放无害。
- 同时清理 `mounts` 与 `acceptedIncarnations` 等归属索引。不可为了“旧句柄能拒绝”永久保留全量历史表；旧句柄自身可保有退休标记。
- 其他现有工厂保持默认兼容，不要求所有应用立刻实现新的公共生命周期。必要的新公共签名标 experimental，说明实际消费与不变量。

先跑这一组能区分机制的检查，随后进入消费者。无需因每个内部小改动重新跑两个完整应用。

### 12.4 B：变高定位与可恢复的公共集合工作区

这部分是本包的新消费能力，不只修测试。

**B1 真实变高几何。** 在现有 mixed 数据中使用合法的长短说明，让列表实际接受的行高不同。复用 VariableHeightList 的测量与稀疏几何，不用 `index * rowHeight` 作为定位答案。表头计入表格几何；换行宽度、排序/过滤、列配置和正文更新按已有 revision 失效规则更新。若当前某类行明确固定高度，另用既有可变高度行呈现验证，不把固定高度换个名字。

验证一个可区分的连续场景：列表与表格同源同时挂载 → 各自滚到不同位置 → 按稳定 key reveal 尾部对象 → 缩窄使长行换行 → 再 reveal → 运行时重排/换位 → 同一对象仍可编辑。期望位置用接受后的行 bounds/可视范围和实际画面独立核对，不能把被测 reveal 返回值当唯一答案。除共同选择策略明确要求外，操作 A 不应改 B 的 offset。

**B2 复用已有视图快照。** `CjguiComposableUiCollectionViewState/Codec` 已有 mode/query/sort/columns 的完整校验与原子恢复。直接使用；不要另开 JSON schema、把业务记录塞进视图文件，或把 pointer capture、临时焦点、未提交候选序列化。先展示快照保存→改筛选/排序/列→恢复，非法快照保旧；未知/删除列沿已有兼容约定处理。offset/测量缓存是否跨兼容重排保留，依 A 的挂载契约；它们不因本包而自动成为持久化格式。

**B3 公共薄工作区。** 先对照 mixed 与 rules 已有筛选、排序/列控制、视图保存恢复、状态提示的重复接线。将相同部分组合成一个公共入口（优先扩展现有 helper；确有稳定重复才新增 `CjguiCollectionWorkspace` 一类薄组件），两消费者都实际接入。入口接收现有 view state、collection/accepted view、scope 与应用声明的操作，负责组件/命令/语义组合；业务写入、选择授权和文件保存策略仍走已有 owner/公共操作。

不要再造工作区注册器、草稿、选择或恢复状态机。应用留下的是业务列/字段定义与少量绑定，不再复制同一套工具栏事件解释。若只在一个业务上成立，先收窄 helper，不能把打印预设常量固化为框架 API。

手写入口与生成入口应能消费同一个集合和操作事实。运行时 list/table 呈现变更仍由已接受结构/声明决定；公共按钮不得私改一份隐藏模式绕开候选。已有选择、筛选、列控制或参数写入入口足够时直接接它们。外部客户端调用至少一次相同公开操作，读回与窗口对应；无需为此造新传输协议。

### 12.5 C：收回原速输入与 rules seed 的误归因

**C1 原输入分歧。** 指导复核已列出 `type-zero.json` 的 43 次零间隔投递，以及 AX 完整 `.json` → 另存后 `.js` 的同组原件。先保全并沿用，修正 RESULT 的“零投递”概括。后来的 AX 全串成功继续保留，不覆盖它。

在同一接受基线、一个自有 rules 实例中，用原长串和正确 PID 重现。只加有界条件记录：发送原文/事件来源 → native 已有接收事实（能取到才填）→ 公共文本事件的顺序/内容/绑定代 → 路径草稿 → 保存命令读取值 → accepted/AX 值和实际文件名。发送完成、native 显示完整、owner 已消费完不是同一时点。按钮与输入的实际顺序也须留下，不能凭 posted 数推定 FIFO。

- 若公共消费者先拿到完整值，随后又写回旧候选，修本线声明/刷新/读取路径；不要在每轮泵里抢焦点。

### 13.3 A：先收住已发现的身份缺口，校正输入归因

- 运行时换位或同 kind 重排后，原 accepted view 与合法选择保持；移除后重新加入不继承退役手势、按键目标或旧 viewport 句柄。业务数据是否保留由原 owner 决定，不能把视图退休当作删除业务。

定向验证回答三件事就够：手写兼容；两个生成挂载中只有活动者 reveal；旧代/外来 viewport 的输入被挡。其它上下键边界复用 selection 的现有测试，必要时补短行/最后行反例，不复制整套键盘矩阵。

如果现有 window 公共事件根本不能表达某一键，保留精确焦点节点、声明、输入/收到事件形状，交 Sol 一次，继续列控制与公开动作。不要越过写集修 native，也不要把事件级调用说成真实键盘已到达。

### 13.5 C：让公共工作区命令和列操作成为正常入口

`CjguiCollectionWorkspace` 已有 declarations/metadata/ownsCommand，但两应用仍重复定义保存/恢复/重置按钮和 action 分支。本段目标是减少这类接线，形成第二业务可直接使用的薄组合。**不得把已有快照方法再次包装一层后就宣布完成。**

#### C1 共用命令投影与分派

沿用公共 command toolbar/metadata 与 IdentityScope，把保存视图、恢复视图、重置视图及本段的列入口组成可挂载的公共工作区操作区。命令声明、按钮身份、启用/禁用原因和事件判定来自同一组事实；调用方只提供 scope、必要可用性与原持久化回调/动作入口。可以增加薄的构建/事件解析方法，但不能再造命令注册器或把打印/规则业务塞到框架。

mixed 和 rules 都实际接入：移除等价的手写按钮/重复 action 编解码分支；应用继续负责文件位置、命名视图持久化、业务 SELECT/APPLY，框架不接管业务保存。没有持久化动作时，不伪造成功或默认文件路径；用现有状态行表明只是会话内视图快照。

同窗两个工作区的命令必须可区分并回到正确作用域。toolbar、palette/context menu 若同时出现同一命令，声明发布一次，多个呈现复用它；不要重演 Select 的 duplicate identity/duplicate commands。禁用入口和直接 invoke 同守卫，不能仅灰按钮。输入字段占焦点时，其编辑快捷键不被工作区的快捷键夺走。

#### C2 列控制消费已有 TableColumnLayout

提供一块可复用的列设置 UI（复用已有 Popover/层/表单控件），以稳定列 key 控制显隐、宽度、顺序与重置。宽度继续用 TableColumnLayout 的 min/max/默认规则，列序使用现有重排接口；排序由现有表头/工作区接口处理。第一实现可以使用可达的上移/下移与宽度输入，不要求为列头新做拖拽系统。

表头、行内容、对齐及可见列必须读取同一个布局事实；改列后不允许只动表头。隐藏列保留自己的设置，恢复能回来。所有列隐藏、未知/已移除列、非法宽度按现有布局契约拒绝或提供明确空态，不能隐式把别的列打开“修好画面”。视图快照仍只含 mode/query/sort/columns，不保存业务正文、原生焦点句柄、holder 数字 id、临时浮层或待接受候选。

切换 list/table 时，走既有声明 presentation 与结构候选路径；失败要保留旧 accepted 挂载和可用视图，不能先把模式状态改成 table 后假称接受。数据刷新、键盘导航、列宽改变应使用已有失效路径，不逐键重解码整份生成结构。

本段验收用两业务的不同字段/列，至少证明：一列隐藏/恢复、一次宽度或顺序改变、表头与正文同序、快照恢复，以及窄窗里入口可达。不要另建“通用表格样例”回避正常消费者布局。

### 13.6 D：接通可操作集合到原业务，跑批量与外部共同使用

rules 已有 `BATCH_SET_ENABLED`、请求身份、授权/CAS 与隐藏选中提示，先读并复用。当前缺的是将**本包生成集合的真实选择与公共工作区入口**接到这一条既有事务，而不是发明新 batch 服务。

1. 用 B 段键盘/选择在生成集合选择两条记录，既有工具栏或菜单触发启用/停用。结果逐记录读回并显示实际作用数量；不要用“按钮点击成功”代替 owner。涉及隐藏选中的规则沿既有 selection 契约，明确显示隐藏数量，可见性不替代授权。
2. 打开需要冻结目标的上下文操作时，保存本次已选稳定 keys/owner 身份以及已有版本事实，在执行前按原 owner 契约重核。删除/换绑其中目标后，旧请求必须具名拒绝或按既有明确的部分结果合同报告；不能重新抓“现在选中了谁”并静默改投。普通直接按钮则按当前明示选择调用原入口，无需人为增加新事务票据。
3. 让独立客户端读取当前已发布动作/字段，再调用同一个批量或记录操作。未知/退休目标、过期版本、未授权对象仍走已有拒绝；拒绝后合法操作继续。不得给所有资源无限放行，也不得从 Python 直接写 table/viewState 绕过 owner。
4. mixed 用同一公共导航/工作区/列入口，选 A/B 后编辑详情、Apply 与各自读回，证明不是只为 rules 写的业务插件。它没有现成原子批量 Apply 时，不为凑对称而捏造一个跨 owner 原子事务；两次独立 Apply 就明确记成两次。
5. 运行时换布局/重排并继续编辑：保留选中 key 与正确 owner，已有草稿不变；保留的正文选区只在原绑定仍有效时继续。进入详情后的首键/范围替换走现有 range 会话，不能用全选重填或外部写入替代真实续写。

**事实口径**：原子结构/版本/实例读回与多个 owner 的字段读回是不同事情。分别读取 A/B 可以证明各自精确，不能写成“一个跨 owner 原子快照”。同理，新 UI 操作不等于新业务算法；报告说明公共接线减少在哪里、原动作如何复用。

### 15.2 OpenDesign 的职责与本包设计简报

本轮已读 Open Design 的 open-design-mode 技能。它规定设计生成及交付流程，不是一份自带全部字体、间距、配色数值的 CJGUI 桌面设计规范。因此执行阶段应给 OpenDesign 以下完整简报，并取得可检查的设计稿与设计系统；不能只加一句“高级、现代、简洁”后自由堆砌。

- 产品：两个 macOS 桌面工具，规则集编辑器和打印预设编辑器；用户要快速选择对象、编辑字段、看到错误、应用/取消、保存与继续工作。界面文档及 AI 修改是开发工作流，可通过明确入口进入。
- 风格：安静、紧凑但可读的桌面工具；内容优先，中性底色、克制的强调色、清晰控件边界；沿用系统窗口能力。不要营销页式巨型标题、无意义渐变背景或每个区域都加卡片和阴影。
- 输出：两个业务各一张正常宽度主画面与窄窗适配；补足编辑、无修改、禁用、错误、未保存、空列表和界面管理状态的必要局部。给出导航、控件层级、间距/文字/颜色等样式值，以及它们映射到 CJGUI 公共入口的说明。
- 设计前提：业务保存、Apply、UI 文档保存是不同操作，不能合并语义；手写与生成呈现必须读取同一 owner。设计稿必须保留键盘、选择、可见错误、文件冲突与正常关闭的可达路径。
- 生成流程：执行时读取可用的 Open Design 技能并按其真实流程操作；没有工具产物就不得声称已完成 OpenDesign 设计。不得静默切换执行模式或额外启动顾问。工具不可用时说明具体依赖，继续能独立推进的源码/呈现整理，不把普通文件检查也停下来。

OpenDesign 的产物是设计参考。最终实现仍为 CJGUI 仓颉组件、现有样式/布局和窄平台桥；不能把 HTML、WebView、React 或 OpenDesign 运行时嵌入应用来代替实现。原型不能当作最终窗口截图。正常的设计—实现—截图对照由执行者在同一整包完成，不按每个间距或按钮向用户反复请示。

### 15.3 信息架构：先让用户看到自己要处理的对象

**规则编辑器默认页：** 顶部保留文档名称、保存状态与少量全局操作；左侧是规则搜索/列表和新增入口，主区是当前规则详情、校验与 Apply/Cancel。对象名、当前选中项、启用状态必须明确。集合列设置、批量操作等跟随所属集合，不能散落在详情下方。保留原表格/多选与公共动作，不能为截图好看改成静态列表。

**打印预设默认页：** 对象集合、当前预设详情和有用途的预览构成主线。手写/生成两种呈现默认选一种，另一个通过“标准界面 / 自定义界面 / 对照”之类的明确入口到达；比较视图是演示/开发用途，不再默认重复铺开两份相同业务。切换呈现不能创建第二份草稿或私改 owner；原双呈现共同编辑的验证仍保留。

**界面工作区：** “编辑界面”进入文档管理/预览区域；主工作区与摘要工作区使用一个当前区域选择器，各自的会话、路径、dirty、预览与文件保护保持独立。切换呈现上下文不得覆盖另一会话，不能用一个全局 path/status 替代已有 scoped workspace。预览激活时再显示确认/取消；没有预览时不摆出整排灰色按钮。高级动作可以收进已有菜单/Popover，状态决定真实可用性，不凭布局隐藏来伪造禁用。

**诊断：** 结构版本、票据、完整摘要、资源编号等进入“开发者信息”折叠区或 Inspector，公共读回仍保留原事实。正常界面用“已保存”“有未应用修改”“正在载入”等明确状态；错误要说明下一步，保留可展开的技术详情。重叠标题如“辅助摘要布局·辅助摘要·界面文档”缩为一次有用的标题。空态引导创建对象/打开文件，不显示空白大框加一屏不可用按钮。

### 15.4 设计系统：共用样式，不逐控件临时调色

以下为本项目的起始尺度，单位都是逻辑 pt，不能从用户截图的物理像素反推控件尺寸。执行者根据文字测量和真实画面在同一体系内调整，并写回设计稿；不要求机械逐像素复刻原型。

| 项 | 起始规则 |
| --- | --- |
| 间距 | 采用 4/8/12/16/24 的有限尺度；页面内边距通常 16–24，字段间距 8–12，主区之间 16–24。 |
| 字体 | 正文和控件通常 13–14；辅助信息 12–13；区块标题 16–18；页面标题 20–24。同层级统一字号/字重，不把所有标签都加粗。 |
| 控件与行 | 常用输入/按钮约 30–36 高；普通行约 32–40，长内容按既有 measured rows 自然增高。不给短行强加大块高度，不截掉实际输入区域。 |
| 色彩角色 | 定义背景、表面、正文、次要文字、边线、强调色、选中、焦点、危险/警告等少量命名样式；手写与生成引用同一份。普通文字以至少 4.5:1 对比度为目标；禁用仍需能辨认。 |
| 按钮层级 | 每个当前任务区域原则上一个主要动作，其余次要/文字动作；危险动作独立表达。保留清晰点击边界，不能让所有按钮都像正文或全是实心蓝色。 |
| 选择与焦点 | 选中用克制背景/标记，焦点用可辨识焦点环；不只靠色彩传达启用、错误或选中。禁止整块详情大面积高饱和选中色。 |
| 容器 | 必要的一层表面分区即可，不逐层重复边框和标题。已有 ScrollViewport 管辖真实内容，避免为每个小分组再套滚动区。 |
| 主题 | 公共角色集中映射现有主题；本包所承诺的浅/深色模式都要可读。未验主题明确列出，不能用硬编码浅色背景破坏原主题。 |

控件外观必须覆盖默认、聚焦、禁用、只读、错误及选中。输入框要明显可编辑，Select 要有触发器与当前值，按钮要看得出可以按；这些是视觉要求，不授权改写角色、可用性或事件语义来配图。

### 15.5 框架落点与实现顺序

### 15.6 一次正常消费验收，而非设计稿评比

两消费者的同源最终候选都要满足：

- 至少一次公开运行时改布局/命名样式后，生成部分仍符合相同设计系统，owner 草稿保留且人可继续编辑。设计不能只在编译好的固定首页成立。
